数据分析：解释已经发生的事

同一个 8% 的跌幅，有人拆出四个切片，有人只说一句「大环境不好」；差别不在工具，在拆法。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出数据分析的四种基本问法：多少、怎么变、由什么构成、哪里不一样。
  2. 能把一个总量指标按乘法与加法拆开，并让各部分贡献对上总变化。
  3. 能区分「可验证的原因」与「听起来合理的猜测」。

01一句掉量，三个数

周一早上，区域经理发来一句：上周销售额怎么掉了 8%？附的日报只有三个数——上周、前一周、前四周均值。这是演示用的示例数据，不是真实经营结果。

手上有 18 家门店、52 周、42 万条订单明细，字段细到门店、时段、商品、渠道。要回答这个问题，不需要模型，需要的是把 8% 拆开：掉在哪类渠道、哪几家门店、哪个时段，以及口径有没有变。

同样看这张表，为什么有人能给出可验证的原因，有人只能猜？

02先看指标，再看异常

体检报告不会一上来就说「你最近太累」。先看哪项指标超出范围，再看是哪几项一起带动的，最后才谈原因。分析走的是同一条路：先描述，再诊断。

图里四问的顺序有讲究：不知道总量与趋势，就没有基线；不知道结构，就找不到贡献最大的那一块；不做对比，原因只能靠感觉。

03四种问法

数据分析用汇总、对比、拆解与归因，解释已经发生的现象。输出是结论与建议，不是可调用的模型；它也不承诺在新样本上的表现。

问法看什么典型输出
多少总量、均值、分布上周销售额 7.36 万元
怎么变同比、环比、趋势较前四周均值下降 8.0%
由什么构成渠道、品类、地区的占比与贡献外卖贡献了约六成跌幅
哪里不一样分组之间的差异三家门店跌幅超过 15%

前两问是描述，后两问走向诊断。边界也要说清：问题由人提出，假设由人给出，工具不负责搜索未知模式——那是 8.2.3 的事。

04先乘后加，再查口径

总额先按乘法拆：销售额 = 订单数 × 客单价；订单数再拆成流量 × 转化率。乘法拆完，按维度做加法分解，各部分的贡献加起来要能对上总跌幅，否则说明还漏了一个维度。

三条纪律。其一，先定基线：前四周均值、去年同期或对照组，没有基线就没有「下降」。其二，每次只动一个维度，交叉着拆会互相掩盖。其三，先查口径：门店停业、系统升级、统计范围变化，都会造出假跌幅。

如果各渠道跌幅都接近 8%，原因多半在总量层——天气、假期、竞品，而不在某个渠道内部。拆不动，往往说明假设本身就错了。拆完还要能还原：各维度的贡献相加，应当回到那个 8%，否则说明还漏了一个维度。

05把 8% 拆到门店

用示例数据走一遍。上周 7.36 万元，前四周均值 8.00 万元，跌幅正好 8.0%。

第一刀按渠道：到店跌 3%，外卖跌 19%；外卖约占三成，加权后约 -8%，对得上。第二刀按地区：只有 3 家门店跌幅超过 15%，且同属一个配送范围。第三刀按时段：晚高峰跌 22%，其余时段基本持平。最后查口径：其中一家门店有两天系统升级，剔除后跌幅收窄到约 6%。

结论不是「用户不喜欢了」，而是「某区域外卖晚高峰供给中断」。验证动作很具体：拉这三家店的配送时长、取消率与骑手在线数；如果配送时长同步抬升，原因就落地了。

06拆一份虚拟日报

任务：给一份「日活下降 8%」的虚拟日报，按渠道、版本、地区、机型四个维度拆解，写 3 条可能原因和 1 条验证动作。

要求：每条原因写成「某个切片上的变化 + 一个可查的数据」，不能写「用户不喜欢了」；验证动作要能在一天内做完，并写明看哪个指标。

验收：各维度的贡献加起来能解释大部分跌幅，且至少有一条原因被你用数据排除。接着看 机器学习：预测未发生的事，看预测任务的输入有什么不同。

注：本页示例仅用 Python 标准库（8.3.4 关联规则 Demo 可离线复现），运行口径为 Python 3.13.14（Windows 原生 CPU）；8.4 的七种思维属方法论，非学术共识。知识库 M08 18 条已建库（filled，2026-11-19），页面按条目口径撰写。
