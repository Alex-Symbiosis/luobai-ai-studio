关联规则：从购物篮里找「一起出现」

支持度说常不常见，置信度说准不准，提升度才回答「是不是真的有关」。三个数缺一个，规则就可能骗人。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出支持度、置信度、提升度的公式，并用 12 条交易手算一遍。
  2. 能解释 Apriori 逐层筛的思路，说清阈值抬高后规则数量为何骤减。
  3. 能读懂提升度接近 1 的规则为什么不能直接拿去做推荐。

01十二张小票

便利店店长拿来一叠小票：12 笔交易，商品只有四种——啤酒、尿布、牛奶、面包，他想知道哪些该摆在一起，好调一次陈列。

店员说「啤酒和尿布总一起出现」，可这是感觉。要能复核，得回答三个问题：一起出现占多少、买了 A 的人里有多少也买 B、比 B 本来的销量高多少倍。

这三个问题对应三个数：支持度、置信度、提升度。少一个就会误判：只看出现次数，高频商品霸榜；只看条件比例，好卖的商品配什么都高。

12 笔交易，凭什么说一条搭配值得调陈列？

02先筛频繁，再筛可信

关联规则分两段：先筛出现次数够多的组合，叫频繁项集；再从项集里生成规则，按置信度筛。

三个指标各答一句：支持度答「常见不常见」，置信度答「准不准」，提升度答「是不是真的有关」。提升度等于 1，说明两件商品各买各的，只是碰巧同框。

逐层筛靠一条性质：不频繁项集的超集也不频繁，所以 2-项集只从留下来的 1-项集里组合，计算量才压得住。

03项集与规则

一笔交易是一个商品集合，例如 {啤酒, 尿布, 牛奶}。若干笔交易的集合叫事务集，事务总数记作 N。项集是若干商品的组合，含 k 个商品就叫 k-项集。

支持度是项集出现的交易占全部交易的比例。支持度不低于阈值的项集叫频繁项集。规则写成 A → B，A 与 B 不相交，含义是「买了 A 的人也会买 B」。

置信度是条件比例：在含 A 的交易里，同时含 B 的比例。提升度把置信度除以 B 本身的支持度，回答「比单独买 B 高多少倍」。

概念写法读法
支持度sup(A ∪ B) = |A ∪ B| / N同时出现占全部交易的比例
置信度conf(A → B) = sup(A ∪ B) / sup(A)买了 A 的人里也买 B 的比例
提升度lift(A → B) = conf(A → B) / sup(B)比 B 的自然购买率高多少倍

两个阈值一起用：最小支持度管「够不够常见」，最小置信度管「够不够可信」。阈值是筛选成本与规则数的折中，必须写进报告。

04三个数手算

拿这 12 笔交易手算两对搭配，所有数字都可复核（手算示例）。

量啤酒 → 尿布牛奶 → 面包
单品出现次数73
后件出现次数84
同时出现次数63
支持度6 / 12 = 0.5003 / 12 = 0.250
置信度6 / 7 = 0.8573 / 3 = 1.000
提升度0.857 ÷ 0.667 = 1.2861.000 ÷ 0.333 = 3.000

读法要连着看。牛奶 → 面包的置信度是 1.000，但牛奶只出现 3 次，样本极小；提升度 3.000 说明买牛奶的人买面包的概率是普通顾客的 3 倍。

啤酒 → 尿布的置信度 0.857 更高，提升度却只有 1.286：尿布本身就出现在 8 笔交易里，买了啤酒再买尿布，只比随便一个顾客高 28.6%。这就是「同现」与「关联」的差别。

pythonrules.py
def support(itemset, trans):
    return sum(1 for t in trans if itemset <= t) / len(trans)

def confidence(a, b, trans):
    return support(a | b, trans) / support(a, trans)

def lift(a, b, trans):
    return confidence(a, b, trans) / support(b, trans)

操作要点：阈值要扫描，看规则数怎么变；双向规则去冗余，只留业务上说得通的方向；按门店、时段分层，全局规则常掩盖局部差异；支持度对应的交易数最好不少于 30 笔。

05阈值一动，规则就变

把 12 笔交易跑一遍，最小支持度固定 0.25，只动最小置信度。下面是本机实测输出（Python 3.13.14，仅标准库，脚本 d8_3_apriori.py）。

解读：阈值抬高，规则变少但每条更强；lift 大于 1 才说明「一起买」超出单品本身的概率，
      接近 1 的规则只是同现，不能直接拿去做推荐。

输出分三段读。第一段是频繁项集：12 条交易、最小支持度 0.25（至少出现 3 次），筛出 6 个频繁项集，其中 1-项集 4 个、2-项集 2 个。第二段是规则：置信度阈值 0.50 / 0.80 / 1.00 对应规则 4 条 / 2 条 / 1 条。

第三段看提升度：牛奶 → 面包的 lift 是 3.000，啤酒 → 尿布的 lift 是 1.286。提升度 3.000 是明显关联，1.286 只高 28.6%，接近同现。

但样本只有 12 条，支持度 0.25 等于 3 笔交易。三条交易撑起的规则不能直接上线，它的价值是把阈值扫描的过程摆出来。「啤酒与尿布」的故事最容易被跳过的正是这一步：先看数据量，再看指标。

06六笔交易手算

任务：六笔交易：{面包, 牛奶}、{面包, 牛奶}、{面包, 啤酒}、{牛奶, 啤酒}、{面包}、{牛奶}。最小支持度取 0.3，求频繁 1-项集与 2-项集，再算规则「面包 → 牛奶」的三个指标。

量你的计算参考值
sup(面包)？4 / 6 = 0.667
sup(牛奶)？4 / 6 = 0.667
sup(面包, 牛奶)？2 / 6 = 0.333
conf(面包 → 牛奶)？2 / 4 = 0.500
lift(面包 → 牛奶)？0.500 ÷ 0.667 = 0.750

追问：① 提升度 0.750 小于 1，说明什么？② 把最小支持度抬到 0.5，2-项集还剩几个？

验收：三个指标都能手算，且能解释「提升度小于 1，说明两件商品同现的概率低于各自独立时的乘积，在这批数据里互相排斥」。下一步见 神经网络与 Web 挖掘；数据清洗见 探索性分析与数据清洗。
