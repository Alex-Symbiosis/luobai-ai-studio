HMM 中文分词与 F1 评估

F1 报 0.905，听着不错。可业务只问一句：错的那 11 处，错在哪一类？这个数字答不上来，评估就还没做完。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能把分词写成逐字 BMES 标注，再用 Viterbi 解码。
  2. 能按词级完全匹配算 P、R、F1，并说清分母。
  3. 能把错误按未登录词、歧义切分、人名边界归因。

01一次小规模分词实验

要验证「HMM 能不能撑起分词」，最省事的做法是自己造一批语料，跑一遍完整流程，再按词级指标打分。

实验设定：100 句自造句，80 句训练、20 句测试；词表 50 个词、89 个字符；标签用 BMES 四个。测试集里 9 句是模板生成的干净句，11 句是刻意埋了缺陷的句子。

流程不复杂：逐字标注、数频次估参数、Viterbi 解码、按边界还原成词，最后对标准答案算 P、R、F1。

02从字到词，再从词到分

分词被拆成两步：先把词边界转成逐字标签，再把标签还原成词。

标签的含义很直白：S 单字成词，B 词首，M 词中，E 词尾。见到 E 或 S 就断一次，词就出来了。

这个转换把「怎么切」变成了「每个字标什么」。后者是标准的序列标注问题，HMM、CRF 都能接。代价是标签之间的约束变多了：M 前面只能是 B 或 M，E 前面只能是 B 或 M。

为什么不用字级准确率

一个字标错，整词就算错。「实验报告」错切成「实验 / 报告」，字级只错一个位置，词级直接错两个。评估要看词边界，就得按词算。

03词级 P、R、F1

判定单位是「词的起止位置」，也就是 span。预测的一个 span 与标准的一个 span 完全相同，才算一次命中；只重合一部分不算。

指标公式分母含义
准确率 PTP / 预测词数切出来的词里有多少是对的
召回率 RTP / 标准词数标准答案里的词被切对多少
F12PR / (P + R)两者的调和平均

两个分母不能混。预测切得碎，预测词数变大，P 被拉低而 R 不受影响；预测切得粗，标准词数不变，R 掉得比 P 快。F1 把两边拉平，所以汇报时三个数一起给。

参数估计是监督式的：转移概率数「前一个标签→当前标签」的频次，发射概率数「标签→字」的频次，两者都加 0.1 的平滑，避免未登录字把概率打成零。

04几十行代码的骨架

核心就三段：标注、数频次、Viterbi。下面是解码部分的节选，对数域计算，平滑系数 0.1。

pythond9_5_segment.py（节选）
def p_trans(prev, cur):
    return math.log((trans.get((prev, cur), 0) + alpha)
                    / (trans.get((prev, ""), 0) + alpha * len(TAGS)))

def p_emit(tag, ch):
    return math.log((emit.get((tag, ch), 0) + alpha)
                    / (tags_total[tag] + alpha * vocab))

dp = {tag: p_trans("<s>", tag) + p_emit(tag, chars[0]) for tag in TAGS}
back = []
for ch in chars[1:]:
    ndp, bp = {}, {}
    for cur in TAGS:
        best = None
        for prev in TAGS:
            score = dp[prev] + p_trans(prev, cur)
            if best is None or score > best[0]:
                best = (score, prev)
        ndp[cur] = best[0] + p_emit(cur, ch)
        bp[cur] = best[1]
    dp, back = ndp, back + [bp]
last = max(TAGS, key=lambda t: dp[t])

三个细节值得留意。取对数是为了把连乘变连加，避免长句概率下溢。平滑加在分子分母两侧，未登录字的发射概率不会变成零，只是变小。回溯指针单独存一份，解码完要倒着走一遍。

还原成词时，遇到 B 就开一个新词，遇到 M 或 E 就续上，遇到 S 就单字成词。句子结尾若还有残留，补成最后一个词。

05二十句实测

text实测输出 · Python 3.13.14（仅标准库）
语料规模    : 100 句（训练 80 / 测试 20），固定种子 20261119

错误类型分布
  未登录词     6

错例 1
  原句    : 老师 分析 神经网络 的 结果 。
  标准    : 老师 / 分析 / 神经网络 / 的 / 结果 / 。
  预测    : 老师 / 分析 / 神经 / 网络 / 的 / 结果 / 。
错例 2
  原句    : 老师 需要 提交 实验 报告 和 语料 。
  标准    : 老师 / 需要 / 提交 / 实验 / 报告 / 和 / 语料 / 。
  预测    : 老师 / 需要 / 提交 / 实验报告 / 和 / 语料 / 。
结论        : 词表内的词切分稳定，误差集中在未登录词、交集歧义与人名边界。

三个数可以互相校验。197 个标准词、194 个预测词、命中 177 个：177/194 ＝ 0.912，177/197 ＝ 0.898，F1 ＝ 0.905。P 高于 R，说明切得偏粗：只切出 194 个词，比标准少 3 个，漏掉的边界全记在召回上。错例 2 把「实验 / 报告」并成「实验报告」，正是这种情形。

错误 11 处，正好对应 11 个缺陷句各一处：未登录词 6、歧义切分 3、人名边界 2。三类的原因不同。「神经网络」不在词表里，发射概率靠平滑，切成了「神经 / 网络」；「实验报告」两词都常见，但连写时的组合没在训练里出现，被并成一个词；「王五 阅读」被并成「王五阅读」，是姓氏单字加动词的边界没学到。

三类错要分开修。未登录词靠更大的词表或字符级回退；歧义切分靠上下文特征，HMM 的观测独立假设在这里是短板；人名边界要先有人名识别，单靠分词模型很难稳定。这也是为什么实际系统常用 CRF 加词典兜底。

06改一个变量再跑

任务：只改一处，重跑一遍，比较三个指标的变化方向。

改动预期变化理由
平滑系数 0.1 → 1.0P/R 怎么变未见字概率变大，误切增多还是减少
测试集加 5 个新词R 怎么变未登录词比例上升
训练集 80 → 40 句三者怎么变转移与发射的频次变稀
标签改 3 个（B、I、E）词数怎么变约束变少，非法序列变多

追问：① 为什么 P 与 R 的分母不同却都要报？② 「实验报告」这类错，加词典能解决吗？③ 逐字错与整词错，哪个更该出现在汇报里？

验收：每项改动都给出变化方向与一句机制解释，且能复算至少一题的 P、R、F1。这套解码的理论，见 HMM：三要素与两个基本问题；想补上下文特征，见 条件随机场。
