激活函数：给网络加弯折

同为隐藏层，换成 ReLU 之后 loss 从 0.693 开始下降。差别不在公式好不好看，而在导数会不会被压扁。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出 sigmoid、tanh、ReLU 的公式、值域与导数，并指出哪个会饱和。
  2. 能用 0.25 的连乘估算梯度衰减，解释深网为什么偏爱 ReLU。
  3. 能按「隐藏层看梯度、输出层看任务」选激活，并说出死亡 ReLU 的成因。

01卡在 0.693 的八层网

一份二分类数据，八层、每层 32 个单元，激活用 sigmoid，优化器 Adam，学习率 0.01。训了 40 轮，训练损失从 0.693 降到 0.691，几乎没动。

0.693 是 ln 2，也就是二分类在「什么也没学到」时的损失：输出恒为 0.5。模型不是训得慢，是前几层几乎没收到梯度。

换个激活就能好？

把 sigmoid 换成 ReLU，初始化同步换成 He 正态，其余不动，损失在第 5 轮就降到 0.4 以下。原因不在「ReLU 更现代」，而在它的导数不会把梯度一路乘小。

02三种形状，三种脾气

把三个函数画在同一张图上，形状的差别一眼能看出来：sigmoid 是 S 形，两头压平；tanh 也是 S 形，但关于原点对称；ReLU 是一根折线，左半边贴地，右半边直线上升。

直觉结论

「压平的地方」就是梯度传不过去的地方。选激活，本质是选把哪一段留成通路。

03三个公式与三个导数

函数公式值域导数饱和
sigmoidσ(z) = 1 / (1 + e^(−z))(0, 1)σ(1 − σ)，最大 0.25两侧
tanh(e^z − e^(−z)) / (e^z + e^(−z))(−1, 1)1 − tanh²(z)，最大 1两侧
ReLUmax(0, z)[0, +∞)z > 0 为 1，z < 0 为 0仅负半轴
Leaky ReLUmax(0.01z, z)(−∞, +∞)1 或 0.01基本不饱和

三个性质决定了它们的用法。第一，导数上限：sigmoid 最大只有 0.25，tanh 最大 1，ReLU 在正半轴恒为 1。第二，是否零中心：sigmoid 输出恒正，下一层输入有系统性偏移；tanh 与 ReLU（近似）没有这个问题。第三，计算成本：ReLU 只要一次比较，指数运算要贵一个量级。

激活必须几乎处处可微，否则反向传播用不了；ReLU 在 0 点不可导，工程上直接取 0 或 1，不影响训练。

04四行实现，一行求导

三个函数各自都能用 NumPy 写成一行，导数也是一行。写一遍，比背公式牢。

pythonactivations.py
import numpy as np

def sigmoid(z):
    return 1.0 / (1.0 + np.exp(-z))

def tanh(z):
    return np.tanh(z)

def relu(z):
    return np.maximum(0.0, z)

def d_sigmoid(z):                # σ' = σ(1−σ)，最大 0.25
    s = sigmoid(z)
    return s * (1.0 - s)

def d_tanh(z):                   # tanh' = 1 − tanh²，最大 1
    t = tanh(z)
    return 1.0 - t * t

def d_relu(z):                   # 正半轴 1，负半轴 0
    return (z > 0).astype(float)

导数写成「用输出推输出」的形式很有用：反向传播时手上只有 a，没有 z，d_sigmoid 与 d_tanh 都能直接用 a 算，省一次存储。

量级也可以估。sigmoid 取 z = 0 时导数 0.25；八层连乘就是 0.25⁸ ≈ 1.5 × 10⁻⁵。误差传回第一层时只剩十万分之一，参数等于没更新。tanh 在 0 点导数为 1，所以同深度下比 sigmoid 好，但两头一饱和，照样衰减。

05选型与两个坑

选型先分两处：隐藏层看梯度，输出层看任务。

位置默认选择配套理由
隐藏层ReLUHe 初始化正半轴梯度不衰减，计算便宜
隐藏层（需要负值输出）tanhXavier 初始化零中心，但会饱和
二分类输出sigmoid二元交叉熵压到 0–1 当概率
多分类输出softmax多类交叉熵归一化成分布

坑一：梯度消失。不是 sigmoid 独有的问题，而是「导数长期小于 1」的连乘问题。深网里换 ReLU 有效，正是因为它把大部分连乘因子固定在 1。

坑二：死亡 ReLU。某个单元一旦长期落在负半轴，梯度恒为 0，参数再也不动。学习率过大（比如 0.1）、偏置被推得过负，都会让大片单元「死掉」。诊断方法很简单：统计每层输出为 0 的比例，健康时大约一半，接近全零就该怀疑了。缓解手段是 Leaky ReLU 或 PReLU，给负半轴留一个 0.01 左右的小斜率。

「为什么必须是非线性」不在这里展开——那是结构层面的问题，见 去线性化。这一页只管「有哪些、怎么选」。
