MP 神经元：加权求和再阈值

整个深度学习的计算，可以压缩成一行：把输入乘上权重加总，再和阈值比一次。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出 MP 单元的判别式，并说清权重与阈值各自决定什么。
  2. 能解释偏置 b 与阈值 θ 是同一件事的两种写法，符号相反。
  3. 能用一组权重和阈值复现人工评分卡的判决。

01评分卡与阈值

一家小贷公司的风控规则表贴在墙上：收入低于 4000 记 10 分，近半年每逾期一次记 5 分，近三个月每查一次征信记 8 分；总分到 30 就拒贷。

审核员每天照着表手工算。后来系统上线，工程师发现这张表可以原样写成一行公式：三个特征各乘一个系数，加起来和 30 比一次。

这条规则里，哪个数字决定「看什么」，哪个数字决定「多严」？

审核员从不追问「为什么是 30 分」。他们只关心这条线画得合不合业务——而这恰恰说明，表里的每一个数字都是人定的，模型没有参与。

02投票箱与开箱线

把 MP 单元想成一个投票箱：每个输入是一张票，权重是这张票的分量；把所有票的分量加起来，超过开箱线就输出 1，否则输出 0。

直觉结论

权重调的是「谁更算数」，阈值调的是「态度松还是紧」。两者分工，不能互相替代。

03一行公式

对输入 x = (x1, …, xn)、权重 w、阈值 θ：

a = 1，若 Σ wᵢxᵢ ≥ θ；否则 a = 0

符号名称作用
xᵢ输入特征可以是 0/1，也可以是连续值
wᵢ权重该特征的分量，正负都可
θ阈值点火所需的票数
a输出只有 0 和 1，不是概率

工程代码里更常写偏置：b = −θ，判别式变成 w·x + b ≥ 0。两者等价，只是把「减多少」换成了「加多少」。按拓扑归类，这个单元是最早的单层前馈网络，见 演变史。

还有一个性质值得记住：把所有权重和阈值同时乘 2，判决完全不变，因为比较的只是相对大小。真正起作用的不是绝对数值，而是方向与相对位置。后面的标准化，动的就是这个相对尺度。

最容易错的一处

θ 与 b 符号相反。看到「b = 0.1」就说「阈值是 0.1」是错的，阈值是 −0.1。代入一个样本算一遍就能发现。

04换阈值看结果

同一组输入与权重，只动阈值，判决就会翻转。这正是「阈值决定多严」的具体含义。

pythonmp_unit.py
import numpy as np

def mp(x, w, theta):
    return int(np.dot(w, x) >= theta)

x = np.array([1, 0, 2])        # 收入不达标、无逾期、查询两次
w = np.array([10.0, 5.0, 8.0])  # 对应三项的记分

print(mp(x, w, 30))            # 10 + 0 + 16 = 26 < 30
print(mp(x, w, 20))            # 同一组数，放宽到 20

第一行输出 0，第二行输出 1。注意函数返回的是整数 0/1，不是「拒贷概率」。这个区别在后面的交叉熵与多分类页里会反复出现。

05一张评分卡

特征取值权重贡献
收入低于 400011010
近半年逾期次数050
近三月查询次数2816
合计——26

阈值定 30，结论是「通过」；定 20，结论是「拒绝」。同一份数据、同一个模型，只因为一条线画在不同位置，业务结果完全相反。

这也暴露了 MP 单元的真实处境：它的全部表达能力都靠人把权重和阈值填进去。它不会从数据里学，写成代码只是把手工表搬进了系统。

顺带说清一件事：这类系统里最贵的不是计算，而是那张表怎么定。权重调多少、阈值卡在哪，全靠业务经验与历史坏账回测。MP 单元负责执行，不负责发现规则。

06调阈值做或门

任务：三张票的权重分别是 1、1、1。要让它变成「任意一项超限就通过」，阈值该设多少？要变成「三项全超才通过」，又该设多少？

想要的规则阈值 θ用 (1,0,0) 验证
至少一项？1 ≥ θ 应为 1
全部三项？1 ≥ θ 应为 0

追问：如果把某一项权重设成 0，在物理上意味着什么？如果设成负数呢？

验收：两行阈值都填对，并且能解释「权重 0 = 这根线不接」。下一节会把这套做法用到逻辑门上。
