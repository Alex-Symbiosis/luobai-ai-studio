反向传播：把误差逐层传回去

反向传的不是误差本身，而是敏感度：这个权重动一点，损失会变多少。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出 δ 的输出层公式与隐藏层递推式。
  2. 能解释 Wᵀ 的作用是按连接权重分配责任，而不是把误差平均分。
  3. 能说清为什么必须缓存前向的中间结果。

01错成 3 之后

一个三层网络识别手写数字，这张图的正确答案是 8，模型输出最像 3。工程师面对的问题不是「整体调一调」，而是：几万个权重里，哪一个该为这次错误负责，各负多少？

如果一个个权重去试——把它加一点、重跑前向、看损失变没变——几万个参数就是几万次完整前向。训练一轮要跑几天。

能不能一次算完所有参数的「责任」？

反向传播的回答是：可以。一次前向把所有中间值存下来，再一次反向，用链式法则从输出层往回推，几万个梯度一次算完。

02去程与回程

同一条连接，正向传信号，反向传敏感度。前向只关心「输出是多少」，反向只关心「这个节点的输入动一点，损失变多少」。

直觉结论

反向传播是一套「责任分配」算法，不是「学习算法」。它只负责把梯度算准，怎么走由优化器决定。

03δ 是敏感度

记 δ⁽ˡ⁾ = ∂L/∂z⁽ˡ⁾，读作「第 l 层预激活的每个分量，对总损失负多少责任」。

输出层：δ⁽ᴸ⁾ = ∇ₐL ⊙ f′(z⁽ᴸ⁾)

隐藏层递推：δ⁽ˡ⁾ = (W⁽ˡ⁺¹⁾)ᵀ δ⁽ˡ⁺¹⁾ ⊙ f′(z⁽ˡ⁾)

参数梯度：∂L/∂W⁽ˡ⁾ = δ⁽ˡ⁾(a⁽ˡ⁻¹⁾)ᵀ，∂L/∂b⁽ˡ⁾ = δ⁽ˡ⁾

不是平均分

Wᵀδ 不是把上层误差平摊给每个隐藏单元，而是按每条连接的实际权重加权求和：权重大的上游，分到的责任就大。这是「敏感度回传」，不是「误差平分」。

另外别漏掉 f′(z)。某一层的输入再敏感，如果激活函数在那里是平的，梯度也传不过去——深层网络的梯度消失就出在这个连乘上。

从形状上看，Wᵀ 把「输出层维度的敏感度」映射回「隐藏层维度的敏感度」，所以转置不是可选项，是维度对齐的必需动作。写错转置的代码通常还能跑，只是梯度方向错，表现为「训练不降反升」。

04四行核心

矩阵形式下，一个样本的反向只有四行。前向的 h 被留下来复用，这是「缓存」的全部意义。

pythonbp_core.py
import numpy as np

sig = lambda z: 1 / (1 + np.exp(-z))

x  = np.array([[1.0, 1.0]])           # 一个样本
h  = sig(x @ W1 + b1)                 # 前向，缓存 h
o  = sig(h @ W2 + b2)                 # 输出
d_o = o - t                           # 输出层 δ（BCE + sigmoid）
d_h = (d_o @ W2.T) * h * (1 - h)      # 隐藏层 δ = Wᵀδ ⊙ f'(z)
gW2 = h.T @ d_o                       # 参数梯度
gW1 = x.T @ d_h

第二行的 h * (1 - h) 是 sigmoid 的导数，直接由输出值算出来，所以 h 必须缓存。d_o @ W2.T 里的转置不能省：形状不对时通常不在这里报错，而是到下一行矩阵乘才报，容易查错方向。

05两倍与两百万倍

为什么非要 BP？对比两种算法算同一个模型的梯度：

方法需要的开销100 万参数时
逐参数数值差分参数量 × 2 次前向约 200 万次前向
反向传播约 2 次前向约 2 次前向

差距是六个数量级。这不是「快一点」，而是「从不可行变成可行」。BP 之所以值钱，就在这一次反向能拿到全部参数的梯度。

还要分清两件事：BP 算梯度，优化器用梯度。把学习率调小、加动量、换 Adam，改的都是后半段，梯度本身不变。同理，Dropout 这类正则只改变训练时的前向图，链式法则的推导照旧，只是被求导的网络换了一张。

一句话记住分工：算法负责算账，优化器负责花钱，人负责定目标和结构。三件事混着谈，就会出现「调了学习率却怪模型不行」这类判断。

一个过度解读

BP 不保证找到全局最优，也不保证泛化。它只保证「在当前点给出最陡的方向」。损失曲面的形状、初始化、数据，都不归它管。
