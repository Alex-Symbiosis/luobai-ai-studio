吸引子与联想记忆

内存按地址取，Hopfield 按内容取：给一部分，就能拿回整条。前提是起点落在同一个坑的坡上。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能解释吸引子、吸引域与「按内容寻址」三者的关系。
  2. 能用汉明距离量化噪声，并判断一次恢复为什么会失败。
  3. 能说清虚假吸引子与容量上限之间的联系。

01撕掉一角的封面

图书馆盘点，一摞书的封面被磨掉大半，只剩书名开头两个字和一种深蓝色。管理员扫不了条码，仍然能把它们归回正确的架位。

两种检索方式在这里对比得很清楚。扫码是按地址：条码缺一位，系统就查不到。人眼是按内容：颜色、字数、版式凑在一起，够像就行。

「够像」到底是多少？

这个问题在 Hopfield 里可以被量化。它有一个距离，有一个能容忍的范围，也有一条越过去就认错的边界。

02一个谷底一片坡

每个存进去的图案都是地形上的一个谷底。落在这个谷底的「坡面」上的任何状态，往下滑都会到达它；这片坡就叫吸引域。

直觉结论

恢复能不能成功，不看「噪声多不多」，而看起点落在谁的坡上。两个域的边界一旦被踩过去，滑到底就是另一个图案。

03吸引子与汉明距离

概念含义本页的量
吸引子更新后不再变化的状态存进去的图案
吸引域最终收敛到该吸引子的起点集合大致对半分
汉明距离两个 ±1 向量不同的位数0–25
虚假吸引子没存过、却是稳定状态的组合图案多时出现

汉明距离是最顺手的噪声尺：25 个单元里改了 7 位，距离就是 7，占 28%。它比「看起来挺像」精确，也比像素误差更贴合 ±1 状态。

容量与吸引域是一体两面。图案少，每个域宽，容错强；图案多，域被挤窄，稍有噪声就越界。0.15N 这个上限说的不是「存不下」，而是「存下之后不再有像样的容错」。

一个常见的美化

「Hopfield 能纠错」说得太满。它只能纠域内的错；越过边界，它会自信地给出一个错误答案，而且没有任何提示。

04翻几位再恢复

实验的做法很直接：取一个存好的图案，随机翻若干位，再让它异步跑几轮，最后数剩下多少位不同。翻转位数就是自变量。

pythonassoc_probe.py
import numpy as np

def hamming(a, b):
    return int((a != b).sum())

rng = np.random.default_rng(3)
s1 = to_spin(P1)                  # 目标图案
noisy = s1.copy()
flip = rng.choice(25, size=7, replace=False)
noisy[flip] *= -1                 # 翻 7 位

rec, hist = recover(W, noisy, rng)   # 异步恢复，见 6.3.4
print("起点距离:", hamming(noisy, s1))
print("终点距离:", hamming(rec, s1))

起点距离是 7，终点距离是 0，说明这一次落在目标自己的域里。把 size 从 7 改成 10、12、13，会看到某个位置之后终点距离突然不再回到 0——那不是收敛变慢，是起点已经跨到了另一个域。

注意 recover 每次都用同一批权重与同一个随机源，这样不同噪声位数之间的比较才是可比的。种子一换，「临界点」会小幅移动。

05七位噪声还能回来

25 个单元、两个图案、翻转 7 位，结果是完全恢复。7/25 = 28% 的位上都是错的，仍然认对，这对「按内容检索」来说已经够用。

但别把这次成功读成「抗噪很强」。两个图案之间的汉明距离决定了域能有多宽：距离越大，边界越远；距离太小，两个坑几乎连成一片，翻三位就可能滑到隔壁。

工程上真正要盯的是三件事：图案之间的最小距离、存了几个图案、噪声大概多少位。三者一起决定恢复率，单看其中任何一个都会误判。

还有一个反直觉的现象：继续增加迭代轮数不会提高恢复率。状态只会往低处走，起点在哪个域，终点就已经定了；多跑几轮只是把同一件事做完。
