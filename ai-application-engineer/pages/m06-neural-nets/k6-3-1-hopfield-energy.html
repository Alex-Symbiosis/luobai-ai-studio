Hopfield 结构与能量函数

给网络一半的线索，它自己补全。Hopfield 把「记忆」写成了一件事：状态不断往低处走，最后停在一个坑里。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能画出 Hopfield 的全连接结构，说清 25 个单元为什么有 300 条无向连接。
  2. 能写出 Hebb 规则与能量函数，并解释常数缩放为什么不改吸引子。
  3. 能估出 25 个单元的存储容量，并说明为什么不是 25 个。

01油污下的编号牌

仓库的货位牌是 5×5 的点阵编号，钉在货架侧面。用了五六年，右下角被油污盖住了七八个格子，巡检员照样一眼认出是哪个货位。

换系统来做就难了。如果按「地址」查——第 3 行第 4 列到底亮不亮——缺一格就查不到。按「内容」查是另一条路：拿剩下的格子去和记忆里的图案比，谁最像就是谁。

少了七格，凭什么还能认出？

Hopfield 网络回答的正是这件事。它不存「第几号记录」，而是把每个图案摊进一组权重，让图案本身成为状态空间里的一个低点。输入残缺时，状态从坡上往下滑，滑到的谷底就是答案。

02地形与谷底

把 25 个单元的取值全列出来，是 2²⁵ 个格点的空间。给每个格点配一个标量，叫能量。网络运行就是在这张地形上往下走，走到不能再低就停住。

直觉结论

记忆不是存在某个地址里的数据，而是地形上的一个坑。给出残缺输入，等于把球放在坡上松手。

03对称与零对角

符号含义本页取值
N神经元个数25（5×5 点阵）
s状态向量每个分量 ±1
W权重矩阵对称，对角为 0
E能量一个标量

权重由 Hebb 规则一次算出：W = Σ s sᵀ / N。这里的 N 指存入图案的个数（本页 2 个），不是神经元数；写成 25 只差一个常数尺度。外积让「同一图案里同时为 +1 的两个单元」之间连一条正边，不同图案的贡献相加后再平均。

能量函数 E = −½ sᵀWs。前面那个负号是关键：状态与权重越合拍，E 越小，所以谷底对应的正是存进去的图案。

常数缩放不改吸引子。把 W 整体乘 0.1，每个局部场的符号不变，更新结果完全相同，只是能量读数缩小十倍。所以「除以图案数」还是「除以神经元数」只影响数值，不影响行为。

对角必须清零

留着 W_ii 等于让单元给自己投票，局部场被这一项抬高，能量地形与更新规则一起被带偏。清零不是可选项。

04十来行就建完

三件事按顺序做：把 0/1 图案转成 ±1、累加外积、清掉对角。没有梯度，也没有损失函数。

pythonhopfield_build.py
import numpy as np

def to_spin(p):                  # 0/1 图案 → ±1 状态
    return np.where(p.ravel() == 1, 1.0, -1.0)

def hebb(patterns):              # W = Σ s sᵀ / N
    n = patterns[0].size
    W = np.zeros((n, n))
    for p in patterns:
        s = to_spin(p)
        W += np.outer(s, s)
    W /= len(patterns)
    np.fill_diagonal(W, 0)       # 自己不看自己
    return W

def energy(W, s):                # E = −½ sᵀWs
    return -0.5 * s @ W @ s

np.outer(s, s) 是一个 25×25 的矩阵，它天然对称。清零对角之后矩阵仍然对称，这正是能量单调下降的前提——少这一步，收敛性的证明就不成立。

还有一处容易忽略：to_spin 必须把 0 映射成 −1，不能映射成 0。状态只有 ±1 两种，夹一个 0 进去，能量公式里就会出现「既不贡献也不抵消」的项，更新也会卡死。

05存储容量上限

容量有个经验上限：大约 0.15N 个图案。N=25 时是 3.75，也就是可靠存 3 个。存 2 个时两个吸引域还很宽，加到 4 个就开始串扰——恢复出来的可能既不是 A 也不是 B。

为什么不是 25？一个单元只贡献一位信息，而「记得住」要求图案之间互不干扰。图案越多，交叉项越大，谷底被填平，甚至凭空长出原本没存过的坑，也就是虚假吸引子。

另一个常见误解是把容量当成「能接收多少个输入」。它能存的是稳定状态的数量；输入只是把状态推到哪个坡上的起点。
