InceptionNet-V3：多尺度并行

同一张图里，路牌只占二十个像素，公交车占两百个。与其赌一种卷积核大小，不如让四种尺度同时工作。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能画出 Inception 模块的四条分支与拼接方式。
  2. 能算 5×5 拆成两个 3×3、n×n 拆成 1×n+n×1 的参数收益。
  3. 能说明「v3」这个叫法的来历，不把它当论文原题。

01两种尺度看不全

一张街景图里，近处的路牌可能只占 20×20 像素，远处的公交车占 200×200。同一个 3×3 卷积核，在浅层只能看到局部边缘，到深层又只能看到粗略结构，很难同时对两种尺度都敏感。

常见做法是堆更深的网络，让感受野慢慢变大。但这样每一层只提供一种尺度，网络得靠「深度」去间接混合。

能不能在同一层里，就把几种尺度一次拿全？

Inception 的回答是：并排开四条分支，分别用 1×1、3×3、5×5 和池化，输出在通道维拼起来。哪条有用，交给后面的层自己挑。

02四条支路拼成一条

把 Inception 模块想成一个路口：同一批特征图进来，分成四路各走各的——1×1 做跨通道整合，3×3 抓中等范围，5×5 抓更大范围，池化保留最强响应。

直觉结论

VGG 靠「串联不同深度」获得多尺度，Inception 靠「并联不同宽度」获得多尺度。前者结构简单，后者一次拿全，两条路线正好互补。

03四分支 + 分解

模块定义：输入 H×W×C 同时送入四条分支——1×1 卷积、1×1 降维接 3×3、1×1 降维接 5×5、3×3 池化接 1×1——四路输出沿通道维 concat。

设计做法解决的问题
多尺度并行四种核大小同层并存目标大小差异大
1×1 瓶颈大核前先降通道计算量随通道平方膨胀
卷积分解5×5→两个 3×3；n×n→1×n+n×1同感受野下省参数
辅助分类器中部引出分支参与训练深层梯度难回传
标签平滑硬标签变软标签模型过度自信

命名要单独说清：原始论文标题是 Rethinking the Inception Architecture for Computer Vision，标题里没有 v3。「v3」是文献与工程界为区分初代 GoogLeNet 及其后续版本加上的叫法。

不要报单一参数总量

从 BN-Inception 到 v3 再到 v4，各版本的通道配置与模块数都不同，参数总量差异很大。本页只算模块级算术，不给「总共有多少万参数」这种数字。

04一个模块一个函数

四条分支各自算完再拼接，Keras 里就是 Concatenate。注意池化分支要加 1×1 卷积，否则它的通道数与另外三路对不上：

pythoninception_module.py
import tensorflow as tf
from tensorflow.keras import layers

def inception(x, f1=64, f3r=96, f3=128, f5r=32, f5=32, fp=32):
    b1 = layers.Conv2D(f1, 1, activation="relu")(x)

    b2 = layers.Conv2D(f3r, 1, activation="relu")(x)
    b2 = layers.Conv2D(f3, 3, padding="same",
                       activation="relu")(b2)

    b3 = layers.Conv2D(f5r, 1, activation="relu")(x)
    b3 = layers.Conv2D(f5, 5, padding="same",
                       activation="relu")(b3)

    b4 = layers.MaxPooling2D(3, strides=1, padding="same")(x)
    b4 = layers.Conv2D(fp, 1, activation="relu")(b4)

    return layers.Concatenate()([b1, b2, b3, b4])

inp = layers.Input((28, 28, 192))
out = inception(inp)     # 28x28x256

默认参数下输出通道是 64+128+32+32=256。池化用 strides=1 加 padding="same"，是为了让四条分支的空间尺寸保持一致——尺寸不一致，拼接就会直接报错。

05十八万参数怎么来

以输入 28×28×192、输出 256 通道为例，逐分支算一遍：

分支操作参数量输出通道
11×1：192→6412,35264
21×1：192→96；3×3：96→128129,248128
31×1：192→32；5×5：32→3231,80832
4池化；1×1：192→326,17632
合计179,584256

读法有三条。第一，1×1 加 3×3 这条分支占 129,248/179,584≈72%，因为它是最常用的尺度。第二，先降维再卷 5×5 是 25×32×32+32=25,632；若直接对 192 通道卷 5×5 出 32 通道，要 25×192×32+32=153,632，接近五倍。第三，分解本身也在省钱：一层 3×3 是 9C²，拆成 1×3 与 3×1 是 6C²，省三分之一；一层 7×7 是 49C²，拆开是 14C²，省 71%。

这里必须区分两种「省」：1×1 瓶颈省的是计算量，卷积分解省的是同感受野下的参数。前者靠压通道，后者靠把方核拉成条核，两者叠在一起才是 Inception 的完整配方。

还有一处容易忽略：四路输出是拼接而不是相加，所以模块输出的通道数等于四路之和。拼接保留了「这条响应来自哪种尺度」的信息，代价是通道数随模块变宽而膨胀，后面的 1×1 卷积要负责把它压回去。

06拆一层 5×5

任务：C=64，比较三种实现 5×5 感受野的方式。

追问：① 为什么池化分支也要接 1×1？② 拼接与逐元素相加，对通道数的影响差在哪？③ 非对称分解（1×n + n×1）为什么不放在网络最前面？

验收：三个数算出 102,400、73,728、40,960，且能说清各自省的是参数还是计算量。多分支怎么影响核算，见 卷积层；串联路线怎么走，见 VGGNet；下一个网络怎么解决更深的问题，见 ResNet。
