多类别输出与 Softmax

三个打分进去，三个概率出来，和恒为 1。更值得记住的是它的梯度为什么只剩 p − y 这么干净。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出 softmax 与多类交叉熵的式子，并说明「先减最大值」为什么不影响结果。
  2. 能推导 softmax + CE 的梯度为 p − y，指出对数与指数在哪一步抵消。
  3. 能读懂三分类的混淆矩阵，指出哪两类最容易被认错。

01八成标签里改错了一成

三堆二维点，分别在 (−2, 0)、(2, 0)、(0, 3) 附近，每堆 200 个，三个类别。采集时出了点问题：8% 的标签被随机改成了别的类，约 48 条。

网络很小：两个输入、16 个隐藏单元、3 个输出。训 30 轮，验证准确率 0.9333。这个数字看着还行，但它把两类问题混在了一起——到底是模型不会分，还是标签本身错了？

光看准确率，分不清这两件事。

要看清，得看混淆矩阵：错的那几条，是从哪一类错到哪一类。

02打分变概率

输出层先给每个类一个实数打分（logit），softmax 做三件事：取指数把负分抬成正数，除以总和把量级拉回 0–1，最后保证加起来正好是 1。

直觉结论

softmax 不创造信息，它只把「谁的分高」翻译成「谁的概率大」。分差越大，分布越尖锐。

03公式与互斥假设

ŷ_k = exp(z_k) / Σ_j exp(z_j)，分母对所有类求和，所以 Σ ŷ_k = 1。

数值实现上要先减最大值：softmax(z) = softmax(z − max z)。分子分母同乘 exp(−max z)，比值不变，但最大的指数变成 exp(0) = 1，不会再溢出。

训练目标是最小化真实类的负对数似然：L = −log ŷ_c。Keras 里标签用整数时选 sparse_categorical_crossentropy，用 one-hot 时选 categorical_crossentropy，两者算的是同一个数。

场景输出层损失
类别互斥（一张图一个类别）softmax多类交叉熵
标签不互斥（一图多物体）每类一个 sigmoid各标签 BCE 求和

判断口诀：能同时为真吗？能，用 sigmoid；不能，用 softmax。用错的话，模型会被迫在「猫」和「狗」之间分掉概率，明明两个都在图里。

04为什么梯度是 p − y

先把结论放这儿：∂L/∂z_k = ŷ_k − y_k。推一遍，就能看出「对数」与「指数」在哪一步互相抵消。

第一步，对 L = −log ŷ_c 用链式法则：∂L/∂z_k = −(1/ŷ_c)·∂ŷ_c/∂z_k。

第二步，求 softmax 自己的导数。分两种情况：k = c 时 ∂ŷ_c/∂z_c = ŷ_c(1 − ŷ_c)；k ≠ c 时 ∂ŷ_c/∂z_k = −ŷ_c·ŷ_k。合并成一个式子就是 ∂ŷ_c/∂z_k = ŷ_c(δ_ck − ŷ_k)，δ 在 k = c 时为 1。

第三步，代回去：−（1/ŷ_c)·ŷ_c(δ_ck − ŷ_k) = ŷ_k − δ_ck。这就是 p − y：预测概率减去「是不是真实类」。除法的 1/ŷ_c 与乘法里的 ŷ_c 正好约掉，指数在求导时留下的自身又被打包进 ŷ_k。

它的含义非常直白：真实类的概率低了就往上抬，其他类高了就往下压，压抬的量正好等于「差多少」。所以 softmax + CE 训起来稳，不需要额外调梯度尺度。

pythond6_6_softmax.py
import os
os.environ["TF_CPP_MIN_LOG_LEVEL"] = "3"
import numpy as np
import tensorflow as tf

rng = np.random.default_rng(6)
centers = np.array([[-2.0, 0.0], [2.0, 0.0], [0.0, 3.0]])
X = np.vstack([c + rng.normal(0, 0.55, (200, 2)) for c in centers]).astype("float32")
y = np.repeat([0, 1, 2], 200)
flip = rng.choice(len(y), size=int(0.08 * len(y)), replace=False)
y[flip] = rng.integers(0, 3, size=len(flip))
idx = rng.permutation(len(y))
X, y = X[idx], y[idx]

tf.keras.utils.set_random_seed(6)
model = tf.keras.Sequential([
    tf.keras.layers.Input((2,)),
    tf.keras.layers.Dense(16, activation="relu"),
    tf.keras.layers.Dense(3, activation="softmax"),
])
model.compile(optimizer=tf.keras.optimizers.Adam(0.02),
              loss="sparse_categorical_crossentropy", metrics=["accuracy"])
h = model.fit(X, y, epochs=30, batch_size=32, verbose=0,
              validation_split=0.2)

代码里没有手写 softmax 与交叉熵：Keras 把两者合成了一个算子，内部用 log-sum-exp 实现，避免「先算概率再取对数」造成的下溢。这也是为什么框架里几乎从不单独使用 softmax 加 log。

05三行读数与一张矩阵

  [4, 192, 7]
  [6, 5, 187]

首样本的三个概率是 0.008、0.9726、0.0194，和正好 1.0。第二个类占绝对优势，说明这个点落得离类 1 的簇心很近；如果真实标签不是 1，这就是一条被改错的标签或一个离群点。

矩阵的对角是 190、192、187，行和分别是 199、203、198——不是整齐的 200，因为 8% 的标签被改过，训练集与验证集里各类的样本数都会轻微变动。非对角上最大的是第 2 行的 7（真实类 2 被判成类 1），其次是第 1 行的 6（真实类 0 被判成类 2）。

这正是混淆矩阵比准确率有用的地方：0.9333 只告诉你「错了 6.7%」，矩阵告诉你「错在哪」。如果错误集中在相邻两类上，多半是特征不够或类别边界重叠；如果错误均匀散布，反倒更像标签噪声。

别把概率当把握

softmax 输出的 0.97 不等于「97% 的把握」可信。未经校准的网络概率常常过度自信，需要可靠性图或温度缩放才能当置信度用。
