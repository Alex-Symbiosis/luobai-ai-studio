基于梯度下降的优化

模型训不动，先别怪网络结构：先数一数这一个 epoch 到底更新了几次参数。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出一次参数更新必须走完的四个动作，并区分 epoch 与 iteration。
  2. 能按样本数与批大小算出一次 epoch 的更新次数。
  3. 能比较 BGD、SGD 与 mini-batch 在梯度噪声、单步耗时、硬件利用上的差别。

01跑了一夜没动

有人接了一个三分类任务，样本 12,000 条，写了 epochs=40，跑了一夜，损失从 1.09 掉到 1.06，基本没动。他怀疑数据有问题，又怀疑网络太浅。

打开代码一看：batch_size=12000。整份数据一次性喂进去，一个 epoch 只更新一次参数。40 个 epoch 等于 40 步梯度下降——这个步数，连热身都算不上。

一个 epoch 到底更新几次？

答案在「样本数 ÷ 批大小」这个除法里。12,000 ÷ 32 = 375 次；12,000 ÷ 12,000 = 1 次。同样的 40 轮，前者走了 15,000 步，后者走了 40 步。

02四步一循环

训练循环只有四个动作，反复执行：取一批数据、做前向算损失、反向求梯度、按梯度改参数。改完参数，这一批的使命就结束了，下一批接着来。

直觉结论

epoch 是「数据看了几遍」的计数，iteration 是「参数改了几次」的计数。两者只差一个除法，却常被混着说。

03三种批模式

同一个更新式 θ ← θ − η·g，区别只在于 g 用多少样本算出来。梯度下降本体的定义、步长与分类见 步长的概念及优化步长的方法，本页不重复推导，只讲它在神经网络训练里怎么落地。

模式每步用多少样本梯度噪声一个 epoch 更新几次
全批量 BGD全部 N无偏、几乎无噪1 次
小批量 mini-batch32–512，常用 32/64/128近似无偏，噪声随批增大而降N ÷ B
单样本 SGD1噪声最大N 次

「随机」二字指的是抽样带来的噪声，不是「随机乱走」。小批量梯度是真实梯度的无偏估计，方差按 σ²/B 下降：批从 32 提到 256（8 倍），噪声标准差降为 1/√8 ≈ 0.354 倍。

04四步写成代码

框架已经把四步包进 fit，但知道它内部做什么，出问题才知道查哪。下面手写一遍最小循环：

pythontrain_loop.py
import tensorflow as tf

model = tf.keras.Sequential([
    tf.keras.layers.Input((2,)),
    tf.keras.layers.Dense(32, activation="relu"),
    tf.keras.layers.Dense(3, activation="softmax"),
])
loss_fn = tf.keras.losses.SparseCategoricalCrossentropy()
opt = tf.keras.optimizers.SGD(learning_rate=0.1)

ds = tf.data.Dataset.from_tensor_slices((X, y)).batch(32).shuffle(1000)

for epoch in range(10):                 # 外层：数据看几遍
    for xb, yb in ds:                   # 内层：一批一步
        with tf.GradientTape() as tape: # ② 前向，顺便记录
            p = model(xb, training=True)
            loss = loss_fn(yb, p)
        grads = tape.gradient(loss, model.trainable_variables)  # ③ 反向
        opt.apply_gradients(zip(grads, model.trainable_variables))  # ④ 更新

三个细节决定这段代码对不对。第一，GradientTape 只包前向，反向在 tape.gradient 里发生；第二，model.trainable_variables 必须与 grads 一一对应，顺序错了会把梯度贴到别的参数上；第三，shuffle 要在 batch 之前，否则每个 epoch 的分批完全一样，噪声就成了固定偏差。

批大小怎么定？先看显存，再在 32–256 之间试。批太小，梯度噪声大、损失曲线毛刺多；批太大，单步成本上升，且噪声太小反而不利于跳出尖锐极小值。训练轮数不变时，改批大小等于改总步数，这两件事必须一起调。

05同一份数据的两种走法

把上面那个 12,000 条样本的任务拆成两组配置对照，只改批大小：

配置每 epoch 更新40 轮总步数会看到的现象
batch 12,0001 次40 步损失曲线几乎水平，像没训练
batch 32375 次15,000 步损失正常下降，曲线有毛刺

毛刺不是坏事。批内 32 条样本的梯度只是真实方向的一个带噪估计，相邻两步的损失小幅回弹是正常的；判断有没有在学，看的是若干步的滑动平均，而不是某一步。

最常见的误读

把「训练轮数」当成「训练步数」。调参时只改 epochs 不动批大小，很容易得出「加轮数没用」的结论——实际是总步数被批大小卡住了。反过来，批大小减半而轮数不变，总步数翻倍，学习率通常也要跟着调。

06先算三步再调参

任务：数据集 48,000 条，批大小 64，计划训 20 轮。回答三个问题，都要给出算式。

问题要算的量提示
A一个 epoch 更新几次、总步数多少样本数 ÷ 批大小
B批改成 256 后总步数变成多少同样 20 轮，步数是原来的几分之一
C批改成 256 后学习率大致怎么调步数变少，单步步长是否该加大

追问：① 全批量训练在什么规模下还能跑得动？② 如果损失曲线剧烈上下震荡，先怀疑学习率还是先怀疑批大小？③ 为什么单样本 SGD 在 GPU 上反而慢？

验收：三个问题都有算式，且能说清「改批大小等于改总步数」这条连带关系。梯度怎么算出来的，见 反向传播；步子该多大，见 Momentum、RMSProp 与 Adam。
