经验回放与目标网络

三项技巧，治三种病：样本太像、答案在动、奖励量纲不一。少一项，训练都可能崩；多一项，就不在本节范围里了。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出三项技巧各修复了哪一条被破坏的假设。
  2. 能写出发放回放池、周期性同步目标网络的代码。
  3. 能指出奖励裁剪的适用边界。

01十帧几乎一模一样

一个回合里，连续十帧画面几乎没有变化：球在同一个位置，只是慢了一点点。如果按采集顺序做梯度下降，这十次的梯度方向高度相关，参数会被同一条轨迹连续拽着走。

更麻烦的是目标。更新式里的 y = r + γ·max Q(s′,a′;θ) 用的是正在训练的那个网络，每改一次参数，「答案」就跟着变一次。预测在追目标，目标也在跑。

这两件事，加上奖励尺度不一，会一起把训练搞崩吗？

会。样本相关让梯度有偏，目标漂移让回归不稳定，奖励量纲不同让学习率无法通用。DQN 的三项技巧，就是分别对着这三处下手。

02三个补丁三处裂缝

把强化学习数据硬塞进监督学习的框子里，会有三条假设不成立。三项技巧不是「炼丹配方」，而是三个补丁，一个补一条缝。

直觉结论

回放把「连续剧情」打散成「独立样本」，目标网络把「移动靶」短暂钉住，奖励裁剪把不同任务的分数拉平到同一量纲。三者都在用信息换稳定。

03三项技巧各做什么

技巧修复的假设做法代价
经验回放样本独立同分布存池，随机抽小批量内存、旧数据过时
目标网络标签固定θ⁻ 每 C 步从 θ 复制目标滞后，要调 C
奖励裁剪损失尺度一致r ← sign(r)，取值 −1/0/+1丢失奖励幅度

回放池容量约 10⁶ 条转移，每步写入，训练时均匀随机抽 32 条。随机抽样近似打破时间相关性，同一条经验还能反复用，样本效率随之提升。

目标网络是另一套参数 θ⁻，只用来算目标：y = r + γ·max Q(s′,a′;θ⁻)。每 C 步（原文 C=10,000）令 θ⁻←θ。在 C 步的窗口内目标视为常数，问题暂时退化成平稳回归。

奖励裁剪把正奖励记 +1、负奖励记 −1、零保持 0，让不同游戏的回报与 Q 值落在同一量级，一套学习率可以通用。

边界要说清

回放要求算法离策略，所以这套做法不能直接套到 SARSA 上。目标网络不是「冻结网络」——它周期同步，不是永不更新。奖励裁剪丢掉「好多少」，需要精细奖励幅度的任务不适用。

04三段代码补三处

回放池就是三个列表加随机抽样；目标网络是第二套权重加一个同步计数；奖励裁剪只有一个 sign。

pythonreplay_target.py
buf = []                        # 存 (s, a, r, s2, done)

def remember(s, a, r, s2, done):
    r = float(np.sign(r))       # 奖励裁剪：[−1, 0, 1]
    buf.append((s, a, r, s2, float(done)))
    if len(buf) > 20000:        # 环形容量
        buf.pop(0)

def sample(batch=64):
    idx = np.random.randint(0, len(buf), batch)
    return [buf[i] for i in idx]

def sync_target(model, target, step, C=10000):
    if step % C == 0:
        target.set_weights(model.get_weights())

抽样用均匀随机，不加优先级——那是后续算法的事，本节不展开。同步计数放在「与环境交互的步数」上，不是梯度步数；两者在跳帧环境下差 4 倍，写错会让目标网络更新得过密或过疏。

回放池满之后删最旧的一条，容量本身就是超参数：太小仍然相关，太大则池里塞满过时策略的数据，学到的 Q 会落后于当前策略。

05为何要这么大

原文的两个数量级不是随手定的。回放池 10⁶ 条，是为了让随机小批量里能抽到足够多样的历史场景；目标网络 10⁴ 步同步一次，是为了在一个窗口内把目标当常数，同时又不至于落后太多。

配置取值调错的后果
回放池约 10⁶ 条太小：样本仍相关；太大：旧策略数据占比高
小批量32太小：梯度噪声大；太大：显存与单步成本上升
同步周期 C10,000 步太大：学得慢；太小：失去稳定作用
奖励sign(r)精细幅度任务里会丢掉关键信息

2015 年的结果值得记一遍：同一套算法、同一套网络结构、同一套超参数，跑 49 款 Atari 游戏，达到与人类测试员相当的水平——单款之间差异很大。这说明三项技巧不是针对某款游戏调出来的，而是通用的稳定化手段。

但稳定不等于万能。连续动作的控制任务用它就不合适：输出层要枚举动作，取 max 也需要有限个动作。这类任务该转向策略梯度或 Actor-Critic。

06关掉一项会怎样

任务：在 CartPole 上逐项关闭，先写预测，再看曲线。

关闭项你预计的曲线原因
经验回放？梯度被连续轨迹拖走
目标网络？目标每步都变
奖励裁剪？本例奖励恒为 1，裁不裁有区别吗

追问：① 回放池为什么要求算法离策略？② 同步周期 C 调成 100 会怎样？③ 本例奖励恒为 +1，奖励裁剪还有意义吗？

验收：三行预测都有机制依据，尤其能说出「本例奖励恒为 1，裁剪近似无操作」这个特例。目标怎么算，见 DQN；完整跑一遍，见 奖励设计与 CartPole 训练。
