五网络对比与迁移学习

五个网络看下来，主线不是「谁更深」，而是「谁用更少的参数换到同样的精度」。这一页把五个网络排成表，再跑一次迁移学习。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能按年份说出五个网络各解决了什么问题。
  2. 能写出冻结卷积基、只训练分类头的代码。
  3. 能诚实解读实验：迁移的优势是首轮更快、参数更少，不是必然涨点。

01只有一千张图

手上有一个二分类任务：判断数字是不是 5 以上。带标签的样本只有 1,000 张，画质与 MNIST 一致。

从零训练一个 CNN，1,000 张图连一个 epoch 的梯度都喂不饱，验证准确率会随初始化漂。可如果先在一个更大的、相似的任务上训好卷积层，再把它们冻结，只训练一个新的分类头，需要的样本量就小得多。

这就是迁移学习，它为什么有效？

因为卷积段学的是「边缘、笔画、局部形状」这类通用特征，换任务时这些特征大多还能用。真正需要重学的，是「怎么用这些特征下结论」的那一层。

02五条主线一次冻结

先把五个网络排成一张表。看的时候不要只记参数，要看每一次改动解决了前一个网络的什么问题。

LeNet 证明卷积可训练，AlexNet 证明规模可行，VGG 证明深度可以系统研究，Inception 转向宽度与算力效率，ResNet 解决「深到一定程度训不动」。五步走完，主干网络的基本工具箱就齐了。

直觉结论

迁移学习不是新网络，是一种训练策略：把已经学好的通用特征当成固定的特征提取器，只让最后几层适配新任务。

03冻结换头解冻

冻结：把卷积基的 trainable 设为 False，反向传播不更新这些权重，优化器也不再为它们维护状态。换头：去掉原模型的分类层，接一个输出维度等于新任务类别数的新头。

做法可训练部分适用条件
只训练新头分类头目标数据很少，源任务相似
解冻最后一段头部 + 末段卷积数据中等，需要一点适配
全部微调整个网络数据充足，但学习率要小

三档的选择标准就两条：源任务与目标任务有多像、目标数据有多少。越像、越少，越应该冻得狠；越不像、越多，越应该放开。解冻时学习率通常要降一到两个数量级，否则预训练权重会被几步大梯度冲掉。

04冻结前后差在哪

下面这段就是本节实验的主体：先训一个 0–9 十类模型，再把它的卷积段接到二分类头上，分别跑冻结与从头两种设置。

pythond6_9_transfer.py
def conv_base():
    return tf.keras.Sequential([
        tf.keras.layers.Input((28, 28, 1)),
        tf.keras.layers.Conv2D(8, 3, activation="relu"),
        tf.keras.layers.MaxPooling2D(),
        tf.keras.layers.Conv2D(16, 3, activation="relu"),
        tf.keras.layers.MaxPooling2D(),
        tf.keras.layers.Flatten(),
    ], name="conv_base")

base = tf.keras.Sequential([conv_base(), tf.keras.layers.Dense(10,
                             activation="softmax")])
base.compile(optimizer="adam", loss="sparse_categorical_crossentropy",
             metrics=["accuracy"])
base.fit(src_x, src_y, epochs=5, batch_size=128, verbose=0,
         validation_split=0.1)

def head_model(frozen):
    cb = base.layers[0]
    cb.trainable = not frozen          # 冻结即 trainable=False
    m = tf.keras.Sequential([
        cb,
        tf.keras.layers.Dense(16, activation="relu"),
        tf.keras.layers.Dense(1, activation="sigmoid"),
    ])
    m.compile(optimizer=tf.keras.optimizers.Adam(0.002),
              loss="binary_crossentropy", metrics=["accuracy"])
    return m

两个容易踩的点。第一，trainable 必须在 compile 之前设好，编译后再改，优化器已经按旧参数表建好了状态，改动不会完全生效。第二，冻结的层在 summary 里仍显示总参数，要看「可训练参数」那一行才知道真正被更新的有多少。

数据切分也决定结论：源任务用前 20,000 张，目标任务用接下来的 1,000 张，标签由「是否大于等于 5」重新生成。两次训练都用同样的随机种子，唯一变量是卷积基冻不冻。

读数 3

6,433 vs 7,681

差的 1,248 个参数正是卷积基；冻结版只更新头部，训练更省。

结论要说得诚实：本实验里迁移的优势不是涨点。冻结版末轮 0.9250，从头 0.9400，低了 1.5 个百分点。它真正赢在两处——首轮更快（0.7600 对 0.7450），可训练参数更少（6,433 对 7,681，省掉整个卷积基）。

为什么这次没涨点？因为目标数据是 MNIST 的另一段，和源任务几乎同分布，从头训练也有足够信号。若换成完全不同的图像（比如彩色商品图），或目标数据只有一百张，冻结的优势会立刻显出来。源任务与目标任务越像、目标数据越少，冻结训练越划算——这是选型原则，不是保证。

别把迁移当定理

「预训练一定更好」只在特定条件下成立。冻结会限制模型对新任务的适配能力；数据够多、分布够远时，解冻微调甚至从头训练都可能反超。判断依据是验证集，不是名词。

06换三个条件再判断

任务：不改代码，只改条件，先写预测再看验证集。

改动你预计冻结版会怎样依据
目标数据从 1,000 张减到 100 张？可训练参数的差距被放大
源任务改成彩色时装分类？特征还通用吗
解冻最后一层卷积一起训？可训练参数增加多少

追问：① 为什么 trainable 要在 compile 之前设？② 冻结版的 6,433 个参数具体由哪几层组成？③ 若把学习率从 0.002 提到 0.02，冻结版与从头版谁更敏感？

验收：三行预测都有依据，且能说清「迁移省的是样本与时间，不是必然的精度」。五个网络的对比见 LeNet-5 到 ResNet；冻结的层是什么，见 CNN 一般框架。
