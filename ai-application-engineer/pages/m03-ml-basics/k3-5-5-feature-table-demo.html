订单表到特征宽表：先定粒度，再做聚合

特征工程交付的不是一段脚本，而是一张能被人读懂、被模型直接吃的宽表。这张表的每一行必须唯一对应一个预测对象，每一列必须对应一条业务假设。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说清「粒度」在宽表中的含义，并保证主键唯一。
  2. 能用 groupby + 时间窗口完成一次从流水到宽表的聚合。
  3. 能为宽表写出字段级特征字典，标注可用时点。

01原始订单表进不了模型

手上是一张 120 万行的订单流水：一行一次交易，字段有用户、时间、金额、类目、支付方式。

模型要预测「某个用户下个月会不会流失」，可这张表里一个用户有几十行。哪一行代表这个用户？

都不代表。必须先把「交易粒度」汇总成「用户粒度」，模型才有唯一的输入对象。

02把流水账汇总成个人档案

银行不会拿几百条流水去评估一个人的信用，而是先汇总成「月均流水、最大单笔、逾期次数」几项指标，再看这几项。

直觉结论

宽表 = 粒度（一行是谁）+ 窗口（看多久）+ 聚合（怎么算）。三者定了，表就定了。

03粒度、窗口、聚合

要素含义本页取值
粒度一行代表谁一个 user_id
快照以哪一天为预测时点2026-03-31
窗口回看多长时间近 30 天 / 全历史
聚合窗口内怎么算计数、求和、均值、最大值、去重计数
定义

特征宽表是以预测对象为行、以特征为列的建模输入表。它的合格标准有两条：主键唯一、每个特征都能在快照时点取到。

04四步产出宽表

定粒度与快照先写清「一行一个用户、快照日为 X」，这一步定错，后面全错。
截断历史只保留快照日之前的记录，避免未来信息混入。
分窗口聚合同一批 groupby，分别算近 7 天、近 30 天、全历史三套特征。
拼表并校验按 user_id 左连接，断言主键唯一、无全空列、无未来列。

第三步的窗口必须显式写进列名（如 _30d），否则半年后没人记得这个均值看的是多久。

05可运行的聚合脚本

pythonbuild_feature_table.py
import pandas as pd

df = pd.read_csv("orders.csv", parse_dates=["order_time"])
SNAP = pd.Timestamp("2026-03-31")        # 预测时点

hist = df[df.order_time < SNAP]          # ① 先截断，再聚合
w30 = hist[hist.order_time >= SNAP - pd.Timedelta(days=30)]

g = w30.groupby("user_id")
feat = pd.DataFrame({
    "order_cnt_30d": g.order_id.nunique(),
    "amount_sum_30d": g.amount.sum(),
    "avg_amount_30d": g.amount.mean(),
    "max_amount_30d": g.amount.max(),
    "n_categories_30d": g.category.nunique(),
})

last = hist.groupby("user_id").order_time.max()
feat["days_since_last_order"] = (SNAP - last).dt.days

feat = feat.reset_index()
assert feat.user_id.is_unique, "主键必须唯一"
feat.to_csv("user_features.csv", index=False)
print(feat.shape, feat.isna().mean().round(3).to_dict())

行数变了

读数 2

主键唯一

读数 3

空值要解释

近 30 天无下单的用户，计数为 0 或空，需决定填 0 还是保留缺失。

任务：把订单表加工成「一行一用户」的宽表，至少 8 个特征，附一份特征字典。

特征名计算口径粒度窗口可用时点业务假设

验收四条：① 主键唯一；② 每列都能在快照日取到；③ 窗口写在列名里；④ 每列都有业务假设。
