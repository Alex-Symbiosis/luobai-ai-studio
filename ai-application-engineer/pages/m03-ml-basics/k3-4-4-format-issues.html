结构、重复与格式：不报错的那一类脏

缺失和异常至少还会在图上看出来。重复、单位混用、编码不一致、时间格式混乱，往往在合并两张表时才爆发，而且一爆就是「少了一半数据」。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能列出重复、单位、编码、时间、文本五类结构性问题。
  2. 能解释合并键不一致为什么会静默丢行。
  3. 能写出可复现的去重与归一规则。

01同一张表，两种连接

订单表 10 万行、用户表 3 万行，按用户 ID 连接。两种处理：

做法 A

直接 join

跑通了，结果 4.8 万行。没有报错，也没有人核对行数，直到模型效果异常才发现少了一半。

做法 B

先对齐再连接

统一 ID 类型、去空格、查未匹配的 2 万条订单；连接后断言行数并输出未匹配清单，丢失量可控。

两种写法都「成功」了，差别在哪一步？

差别在连接前的对齐与连接后的核对。格式问题不会抛异常，它只会静默改变数据规模。

02插头和插座对不上

两表合并像插头和插座：形状（类型）、尺寸（单位）、针脚定义（编码）任何一处不一致，要么插不进，要么插进去不通电，而且不会报警。

直觉结论

结构性问题的共同特征是「静默失败」：代码跑通、表也生成了，但内容已经不对。

03五类问题与判定方法

类型判定方法处理原则
重复按主键或全部列计数按业务规则保留一条（最新/最完整）
单位与量纲分位数跨度异常、极值差 100 倍统一单位后重算，保留换算记录
编码与拼写类别取值数量异常多建映射表归一（男/M/1 → 男）
时间格式字符串与时间戳混用、时区不一致统一解析为时间类型并标明时区
文本脏值首尾空格、全角字符、占位符清洗后再做类别统计
定义

结构性问题是指数据的组织方式或表示格式不一致，导致合并、分组、排序等操作产生错误结果，但不触发运行错误。

04为什么「静默丢行」最难查

连接键类型不一致整数 1001 与字符串 "1001" 不相等，连接后全部落空。
空白与全角" 1001" 与 "1001" 不相等；肉眼几乎看不出差别。
一对多关系用户表同一 ID 有两条记录，左连接会让订单翻倍，行数变多同样是错误。

防线是三个断言：连接前后行数对比、连接键去重检查、连接后空值率检查。任一异常就停下来查，而不是继续往下跑。

这一页适合现场演示：用两份手工构造的小表做一次错误连接，让学生看到「程序不报错，但结果少了一半」。

05三张表的合并事故

问题现象定位与修复
ID 类型不一致左连接后仅剩 48%统一转为字符串并 strip，重连后恢复 96%
金额单位混用部分订单金额是另一部分的一百倍按来源表分别换算为元，记录换算系数
用户表重复连接后行数变多先按 ID 去重保留最新，再连接

三个问题里只有第一个会让人立刻察觉「数据少了」。后两个若不做分布检查，会一路带进模型。

自检三问：① 合并后行数和我预期的一致吗？② 关键列的空值率有没有突然升高？③ 类别数量有没有异常膨胀？

常见误解

「左连接不会丢数据」不成立。左连接保留左表所有行，但如果右表有重复键，行数会增加；如果之后又做了内连接或过滤，行数会减少。
