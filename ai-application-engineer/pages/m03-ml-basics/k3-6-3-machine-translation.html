机器翻译：序列到序列的生成

把「我很喜欢这本书」逐词替换成「I very like this book」，每个词都查对了，句子却不成立。翻译不是词典拼接，而是理解意群之后的重排与再生成。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说明机器翻译为什么不能逐词替换。
  2. 能描述编码—解码的基本流程与对齐的作用。
  3. 能用 BLEU、chrF 或人工错误分类评价一段译文。

01同一句话，两种译法

把「我昨天在图书馆看了一本书」译成英文，两种做法：

做法 A

逐词替换

I yesterday in library read a book. 每个词都查对了，但英文不会这样排；「开灯」还会被译成 open light。

做法 B

先理解再生成

先把整句压成语义表示，再在目标语言里重新组织语序与搭配，得到 I read a book in the library yesterday.

两种做法都用了词典，为什么 A 的句子不成立？

因为翻译要处理语序、一词多义与固定搭配。逐词替换把「句子」当成了「词袋」，丢失的正是这些关系。

02意群重排，不是词典拼接

中文说「我昨天在图书馆看了一本书」，英文更自然的顺序是「I read a book in the library yesterday」。地点与时间的位置整个调换了。

直觉结论

翻译的输出不是「输入的逐词映射」，而是「在另一种语言里重新组织一遍」。所以它是一个生成任务。

03序列到序列任务

定义

机器翻译是把源语言序列映射为目标语言序列的任务，属于序列到序列（seq2seq）生成。输入与输出长度可以不同，词序可以重排，输出词表也完全不同。

组件作用要解决的问题
编码器把源句压成向量表示保留语义，丢弃表层词序
对齐建立源词与目标词的对应处理语序调换与一对多
解码器逐词生成目标句保证目标语言流畅、语法正确

04生成过程中的三个难点

一词多义「bank」是银行还是河岸，取决于上下文。编码器必须把整句信息带进来，而不是只看当前词。
语序重排修饰语、时间地点的位置在两种语言里可能相反，对齐机制要允许「跳着对应」。
长度变化输出可能比输入长或短，解码要能自己决定何时结束，而不是按输入长度逐位生成。

这三点也解释了为什么翻译模型比分类模型难评：一句原文可以有多个正确译文，评价必须允许「不同但都对」。

BLEU 高不代表没错误：它看的是 n-gram 重合度，漏掉一个否定词可能只掉零点几分，但语义完全反了。

06为三句译文找错误

任务：找三句中英对照，给每句译文标注错误类型（漏译 / 错译 / 语序 / 语法），并写一条改进方向。

自检

「读起来别扭」不算错误类型。要指出具体是哪个词、哪段结构出了问题，否则无法转成可执行的改进项。

验收：三类错误各至少一例；每例都能定位到具体词或结构。
