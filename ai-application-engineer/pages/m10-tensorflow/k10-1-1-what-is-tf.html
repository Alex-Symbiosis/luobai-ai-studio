TensorFlow 的定位与特点

NumPy 能算矩阵，sklearn 能训模型，为什么工程团队还要多背一套 TensorFlow？答案不在「能不能算」，而在「算完以后怎么办」。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能用一句话说清 TensorFlow 的定位：端到端的机器学习框架。
  2. 能举出自动微分、硬件加速、跨端部署三个特点各自解决什么问题。
  3. 能解释 tf.keras 与独立 keras 的关系，不被版本号绕晕。

01手工作坊与流水线

同一个需求：把用户评论分成「好评 / 差评」，上线给运营用。两种做法：

做法 A

NumPy 手写

前向自己写，反向传播自己推，梯度公式抄在笔记本上；模型训完是一个 .npz，上线还要自己写一套加载与预处理代码。

做法 B

TensorFlow

层、损失、优化器直接调用，梯度由框架求；模型存成 .keras 或 SavedModel，服务端、手机端各有现成加载方式。

两套代码的差距，是「少写几行」吗？

不是。差距在于链路的完整性：从数据读取、梯度计算，到导出与跨端加载，TensorFlow 每一段都有现成接口，而手写版每换一个环节都要重新造。

02端到端，指的是覆盖首尾

把机器学习项目想成一条产线：备料、加工、质检、包装、发货。多数工具只覆盖其中一段，TensorFlow 的设计目标是五段都在同一套代码里。

直觉结论

「端到端」不是营销词，而是说：同一套张量类型、同一套设备管理，贯穿从读盘到线上推理的全过程。

03三个特点，各解决一件事

特点解决什么问题落到哪个接口
端到端数据、训练、评估、导出各用一套工具，接口对不上tf.data、tf.keras、model.export
自动微分手推反向传播，公式错一个符号就训不动tf.GradientTape、model.fit
跨平台执行同一模型要在服务器、手机、浏览器上跑CPU / GPU / TPU 后端、SavedModel、TFLite

自动微分是「记录—回放」：前向时把运算记进 GradientTape，回放时按链式法则逐节点求导。跨平台执行则是把同一张计算图交给不同后端，算子实现由后端负责。

常见的混淆

tf.keras 是 TensorFlow 侧的懒加载命名空间，不等于独立的 keras 包：tf.keras is keras 为 False，但 tf.keras.layers.Dense is keras.layers.Dense 为 True——两者指向同一套实现。

04调用即得值，顺便做一次矩阵乘

本模块全部示例的运行口径为 tensorflow-cpu 2.21.0 + Keras 3.15.1 + Python 3.13.14（Windows 原生 CPU，独立虚拟环境），不需要 GPU。先确认环境真的可用：

pythontf_basics.py
import tensorflow as tf
import keras

print("TensorFlow:", tf.__version__)
print("独立 keras:", keras.__version__)
print("tf.keras is keras:", tf.keras is keras)
print("eager:", tf.executing_eagerly())

a = tf.constant([[1.0, 2.0], [3.0, 4.0]])
b = tf.constant([[10.0], [20.0]])
print("a @ b =", (a @ b).numpy().tolist())

三个读法：tf.executing_eagerly() 为 True，说明是 2.x 的即时执行；@ 直接按矩阵乘法求值；.numpy() 把张量转回 NumPy 数组才交给 print，输出格式才可控。

05实测读数与两个坑

text实测输出 · TF 2.21.0 / Python 3.13.14
TensorFlow: 2.21.0
独立 keras: 3.15.1
tf.keras is keras: False
eager: True
a @ b = [[50.0], [110.0]]
读数 1

2.21.0 / 3.15.1

TensorFlow 与 Keras 各自有版本号；TF 2.21 内置的是 Keras 3，不是早期的 2.x Keras。

读数 2

is keras: False

两个名字不是同一个对象，但底层实现是同一份；判断「是不是同一层」要比 layers.Dense。

读数 3

[[50.0], [110.0]]

2×2 乘 2×1 得 2×1：第一行 1×10+2×20=50，第二行 3×10+4×20=110。

首次运行会刷警告

oneDNN 与 GPU 相关提示走的是 stderr，不影响结果，也不代表装错了；本机无 GPU，出现「Could not find cuda drivers」属正常。

06三项差异，各配一个例子

任务：列出 TensorFlow 与 scikit-learn 的三项差异，每项配一个具体能力作证据，而不是写「更强大」。

切入点要观察什么提示
自动微分不用写导数公式，梯度能否直接取到tf.GradientTape
硬件与部署同一模型能否导出到非 Python 环境model.export
数据规模数据大于内存时还能不能训tf.data 流式读取

追问：① sklearn 的 fit 和 TF 的 fit 分别在什么粒度上更新参数？② 为什么「能导出」比「能训练」更接近工程交付？

验收：三项差异都能对应到一个可运行的接口，而不是形容词。

注：本页代码与「实测输出」的运行口径为 tensorflow-cpu 2.21.0 + Keras 3.15.1 + Python 3.13.14（Windows 原生 CPU，独立虚拟环境，未安装 GPU 版），结果来自本机实际运行，可直接复现。
