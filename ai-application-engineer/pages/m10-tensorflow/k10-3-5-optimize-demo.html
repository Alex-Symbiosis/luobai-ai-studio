优化模型：超参数与回调

效果不好时最先动的往往是学习率，但学习率排在排查顺序的第四位。前三位不对，调它只是把一种欠拟合换成另一种。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能按「数据—特征—模型—超参数」的顺序排查，而不是直接调参。
  2. 能解释学习率过大与过小分别表现成什么样。
  3. 能用早停与学习率衰减两个回调控制训练过程。

01三组对照，同一份数据

同一份线性数据、同一个模型，只改学习率设置：

text三组结果（下方代码复现）
SGD lr=0.01: 2.5371
SGD lr=0.05: 0.0
指数衰减 lr=0.05: 0.0

0.01 训练 100 轮仍停在 2.5 上下，0.05 已经收敛。同一份数据、同一个模型，差别只在一个数字。

那是不是学习率越大越好？

不是。再大就会震荡甚至发散；而且这份数据先做了标准化，否则同样的学习率会因尺度过大而直接崩掉。

02先查原料，再调工艺

菜不好吃，先看食材新不新鲜，再看刀工火候。数据、特征就是食材；学习率只是火候。

直觉结论

按「数据 → 特征 → 模型容量 → 超参数 → 回调」的顺序，每一步只改一个变量，才能知道是谁起了作用。

03超参数、回调与两个常用回调

概念含义本页取值
超参数训练前设定、不由梯度更新的量学习率、批大小、层数
回调 Callback在训练过程中被调用的钩子早停、降学习率、存检查点
EarlyStopping验证损失若干轮不降就停patience=10
学习率衰减随步数按公式降低学习率每 50 步 × 0.9

早停必须监控验证集损失：监控训练损失会在过拟合开始后继续「变好」，停不下来。

04三组设置，一次跑完

pythonoptimize_demo.py
import numpy as np
import tensorflow as tf

X = np.array([[i] for i in range(1, 6)], dtype="float32")
y = 3.0 * X + 2.0
X = (X - X.mean()) / X.std()


def train(optimizer, epochs=100):
    tf.keras.utils.set_random_seed(0)
    model = tf.keras.Sequential([tf.keras.layers.Input((1,)), tf.keras.layers.Dense(1)])
    model.compile(optimizer=optimizer, loss="mse")
    h = model.fit(X, y, epochs=epochs, verbose=0)
    return h.history["loss"][-1]


print("SGD lr=0.01:", round(train(tf.keras.optimizers.SGD(0.01)), 4))
print("SGD lr=0.05:", round(train(tf.keras.optimizers.SGD(0.05)), 4))

schedule = tf.keras.optimizers.schedules.ExponentialDecay(
    initial_learning_rate=0.05, decay_steps=50, decay_rate=0.9)
print("指数衰减 lr=0.05:", round(train(tf.keras.optimizers.SGD(schedule)), 4))
print("衰减学习率 step 0/50/100:",
      [round(float(schedule(s)), 4) for s in (0, 50, 100)])

三组实验共用同一个 train()，唯一的变量是传入的优化器；set_random_seed(0) 放在函数内部，保证每组初始化一致。

读数 2

lr=0.05 已把损失压到浮点精度以下，此时再加大学习率不会更快，只会震荡。

读数 3

0.05 → 0.0405

每 50 步乘 0.9：第 0 步 0.05，第 50 步 0.045，第 100 步 0.0405。

标准化是前提

示例先做了 (X - mean) / std。未标准化时特征尺度可能大几个数量级，同一个学习率会直接发散成 nan。

06做一次可复现的对照

任务：完成一个二分类全流程，做 3 组超参数对照，加早停，并写「哪组最好、为什么」。

要做要观察什么说明
切验证集早停监控哪个损失validation_data
三组只改一个量结论能否归因学习率或层数，不要同时改
固定种子重跑结果是否一致set_random_seed
加 EarlyStopping停在第几轮patience 记录

追问：① 为什么早停要监控验证损失而不是训练损失？② 学习率衰减与早停分别在解决什么问题？

验收：重跑两次结论一致；能说出每组实验唯一的变量。
