1.x 与 2.x：计算图、会话与 Eager

考纲写的是「计算图、会话」，你装好的 2.21 里却一行 Session 都找不到。这不是教材错了，而是它描述的是 1.x——两种范式都得认识。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出 1.x「先建图、后开会话」与 2.x「调用即计算」的执行差别。
  2. 能解释 tf.function 为什么在 2.x 里仍然重要。
  3. 能把一段 1.x 写法改写成等价的 2.x 写法，并说明结果为何一致。

01教材和屏幕对不上

照着教材敲：

python教材上的 1.x 写法（在 2.x 下会报错）
import tensorflow as tf

a = tf.placeholder(tf.float32)
b = tf.placeholder(tf.float32)
c = a + b

with tf.Session() as sess:
    print(sess.run(c, feed_dict={a: 3.0, b: 4.0}))

在 TF 2.21 里运行会得到 AttributeError: module 'tensorflow' has no attribute 'placeholder'。同一个目的，2.x 只需要两行：

python等价的 2.x 写法
import tensorflow as tf

a = tf.constant(3.0)
b = tf.constant(4.0)
print((a + b).numpy())

「图」消失了吗？

没有。它从「你必须手动搭的东西」变成了「框架在需要时替你生成的东西」。

02先画图纸，还是边做边改

1.x 像装修：先出完整施工图，再交给施工队按图施工；图一旦建好，改动就要重建。2.x 像搭积木：放一块就能看到结果，错了立刻拆。

直觉结论

Eager 优先解决「调试」：能 print、能断点、能按 Python 逻辑分支。图模式解决「速度」：能整体优化、能脱离 Python 执行。tf.function 就是两者的接口。

03四个词，一条时间线

术语属于含义
计算图（graph）1.x 核心，2.x 可选节点是运算、边是数据的依赖图
会话（Session）1.x执行图的入口，负责分配资源并运行节点
Eager Execution2.x 默认调用即求值，行为接近 NumPy
tf.function2.x把 Python 函数追踪成图，兼顾速度与部署

时间线：TF 1.0（2017）以图与会话为核心；TF 2.0（2019）默认 Eager，把 tf.function 作为「需要图时」的开关；TF 2.16 起默认搭配 Keras 3。所以考纲的原词要保留，但代码必须按 2.x 写。

042.x 下先跑一遍即时执行

本页只演示 2.x 的一半；1.x 的会话写法在 k10-2-3 用 tf.compat.v1 完整对照，那里会真正关闭 Eager，必须单独开进程。

pythontf1_vs_tf2.py
import tensorflow as tf

# 2.x 的默认写法：调用即求值
a = tf.constant(3.0)
b = tf.constant(4.0)
print("2.x eager:", (a + b).numpy())

# 1.x 的写法（需在独立进程中先关闭 eager，完整对照见 k10-2-3）
# c = tf.compat.v1.placeholder(tf.float32, shape=[])
# sess.run(c, feed_dict={c: 7.0})
text实测输出 · TF 2.21.0 / Python 3.13.14
2.x eager: 7.0

tf.function 的用法只多一个装饰器：函数体照常写 Python，首次调用时被追踪成图，之后同形状输入直接复用图。这也带来约束——函数里不能依赖 Python 的副作用（例如往列表里 append 后指望下次还能读到）。

05同一件事的三种写法

目的1.x2.x
放一个数tf.placeholder(tf.float32)tf.constant(3.0)
执行sess.run(c, feed_dict=...)直接 c.numpy()
求梯度tf.gradients + sess.runtf.GradientTape
要图加速默认就是图@tf.function

注意 tf.compat.v1 不是「1.x 代码原样能跑」的保险箱：它提供同名 API 与 Session，但要真正进入图模式，仍需 tf.compat.v1.disable_eager_execution()，而这一步不可逆——所以只能放在单独脚本里。

06把一段 1.x 改写掉

任务：把下面这段改写成 2.x Eager 写法，保持输出一致。

python待改写片段
import tensorflow as tf
tf.compat.v1.disable_eager_execution()   # 必须放在最前，且不可逆

x = tf.compat.v1.placeholder(tf.float32, shape=[2])
w = tf.Variable([2.0, 3.0])
y = x * w

with tf.compat.v1.Session() as sess:
    sess.run(tf.compat.v1.global_variables_initializer())
    print(sess.run(y, feed_dict={x: [1.0, 10.0]}))
改动要观察什么说明
placeholder → constant还需不需要 feed值直接写在张量里
删掉 Session结果怎么取.numpy()
变量初始化2.x 还需不需要显式 init创建时即已初始化

追问：① 为什么 disable_eager_execution() 一旦调用就无法恢复？② 什么场景下 2.x 反而要主动加 @tf.function？

验收：改写后输出为 [2.0, 30.0]，且全脚本不出现 Session。

注：本页代码与「实测输出」的运行口径为 tensorflow-cpu 2.21.0 + Keras 3.15.1 + Python 3.13.14（Windows 原生 CPU，独立虚拟环境，未安装 GPU 版），结果来自本机实际运行，可直接复现。
