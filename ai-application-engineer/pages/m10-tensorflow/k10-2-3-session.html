会话：图执行的入口

图只是图纸。1.x 里，图纸要交给「会话」才会真正开工；理解这一层，才能读懂老代码，也才知道 2.x 到底替你省了什么。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出 Session 在 1.x 中承担的三件事：分配资源、运行节点、返回数值。
  2. 能读懂 sess.run 的 feed 与 fetch 两个参数。
  3. 能说明为什么这段代码必须单独跑一个进程。

01图画好了，谁来执行

1.x 的两段式写法：

第一步

建图

用 placeholder 占位，用 a + b 往图里加一个 AddV2 节点。此时没有任何数值被计算。

第二步

开会话

Session 负责把图放到设备上、分配内存，run 时才真正执行，把结果取回来。

为什么不能像函数一样直接调用？

因为图是「声明」，不是「调用」。声明里没有数据，只有槽位；执行需要另一个角色来决定什么时候跑、跑在哪个设备上。

02图纸交给施工队

建筑师画好图，不会自己动手；施工队按图施工，还要决定先做哪层、用几台吊车。会话就是那个施工队。

直觉结论

建图与执行分离，好处是图可以脱离 Python 单独优化与部署；代价是每次取值都要显式 run。

03Session、run、feed、fetch

概念作用代码位置
Session持有图与设备资源，管理生命周期with tf.compat.v1.Session() as sess:
run(fetches)要取回的节点（fetch）sess.run(c)
feed_dict给 placeholder 喂的值（feed）feed_dict={a: 3.0, b: 4.0}
disable_eager_execution关闭 2.x 默认的即时执行必须在建图前调用，且不可逆

2.x 中 tf.compat.v1.Session 仍然存在，但默认 Eager 打开时，placeholder 无法创建；因此这段代码必须先关闭 Eager，并且只能放在独立脚本里跑。

不可逆

disable_eager_execution() 只影响当前进程，调用后无法恢复。把它混进主程序，会让同进程里所有 2.x 写法失效。

04完整可运行的 1.x 对照

pythonsession_demo.py（需独立进程）
import tensorflow as tf

tf.compat.v1.disable_eager_execution()
print("eager:", tf.executing_eagerly())

a = tf.compat.v1.placeholder(tf.float32, shape=[], name="a")
b = tf.compat.v1.placeholder(tf.float32, shape=[], name="b")
c = a + b

with tf.compat.v1.Session() as sess:
    print("sess.run(c, feed={a:3,b:4}):", sess.run(c, feed_dict={a: 3.0, b: 4.0}))
    print("计算图操作数:", len(tf.compat.v1.get_default_graph().get_operations()))

注意 shape=[] 是 0 维标量，不是「未知形状」；如果写成 shape=[None]，就成了长度可变的向量，feed 一个标量会报形状错误。

06标注三处关键位置

任务：读下面这段 1.x 代码，标出「建图」「开会话」「取结果」三处，并说出执行顺序。

python阅读材料
import tensorflow as tf
tf.compat.v1.disable_eager_execution()

x = tf.compat.v1.placeholder(tf.float32, shape=[2])
w = tf.constant([2.0, 3.0])
y = x * w

sess = tf.compat.v1.Session()
out = sess.run(y, feed_dict={x: [1.0, 10.0]})
print(out)
sess.close()
位置属于哪一步判断依据
placeholder 与 x * w建图只加节点，没有数值
Session()开会话分配资源
sess.run(y, ...)取结果feed 进去、fetch 出来

追问：① 不调用 sess.close() 会怎样，为什么推荐 with？② 这段代码在 2.x 里等价写法是什么？

验收：三处标注正确，输出为 [ 2. 30.]。

注：本页需关闭 Eager 才能创建 placeholder，代码必须在独立进程中运行；运行口径为 tensorflow-cpu 2.21.0 + Python 3.13.14，输出为本机实测。
