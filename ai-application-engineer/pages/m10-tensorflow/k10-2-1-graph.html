计算图：节点与边

框架为什么要把一行 a + b 拆成「节点」和「边」？因为只有先看见依赖，才能决定谁先跑、谁可以并行。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说清计算图中节点与边各代表什么。
  2. 能用 get_concrete_function 取出一张具体的图，并数出操作数。
  3. 能解释图优化与并行执行分别省下了什么。

01为什么不是「算完就完」

同一段前向：relu(x @ w + b)。两种执行方式：

逐条算

Eager

先算矩阵乘，再算加法，再算 relu；每一步都立刻产出数值，也立刻占用内存。看不到全局，优化空间很小。

先成图

Graph

三个运算先记成节点，框架看到「乘 → 加 → 激活」的依赖链，可以合并算子、复用内存、把无依赖的分支并行。

图模式一定更快吗？

不一定。小模型、单次调用时，建图的固定开销反而更贵；图的优势在大批量、重复执行、跨设备部署时才显现。

02工序图与传送带

工厂里没人靠记忆安排工序：流程图贴在墙上，哪道工序等哪道、哪些可以同时做，一目了然。计算图就是这张流程图。

直觉结论

图的本质是「依赖关系」的显式表达。有了它，框架才能替你排程；没有它，只能按你写的顺序一条条来。

03节点、边、依赖

元素表示什么例子
节点（node / op）一次运算MatMul、AddV2、Relu
边（edge）数据流，即张量矩阵乘的结果流向加法
依赖（dependency）谁必须先算完加法依赖乘法的输出
placeholder1.x 的占位节点，运行时喂值tf.compat.v1.placeholder

2.x 里图是「被追踪出来的」：给函数加上 @tf.function，首次调用时框架按实际输入形状记录节点，之后同样形状直接复用。所以同一函数用两种形状调用，可能生成两张图。

04把函数追踪成图并数节点

pythongraph_trace.py
import tensorflow as tf


def dense_relu(x, w, b):
    return tf.nn.relu(tf.matmul(x, w) + b)


concrete = tf.function(dense_relu).get_concrete_function(
    tf.TensorSpec([None, 3], tf.float32),
    tf.TensorSpec([3, 4], tf.float32),
    tf.TensorSpec([4], tf.float32),
)
graph = concrete.graph
print("图操作数:", len(graph.get_operations()))
print("操作类型:", sorted({op.type for op in graph.get_operations()}))
print("eager 直接调用:", dense_relu(tf.ones([1, 3]), tf.ones([3, 4]), tf.zeros([4])).numpy().tolist())

get_concrete_function 要求用 TensorSpec 描述输入，而不是真实数据——这正是「先建图」的含义：形状定下来，值还没进来。

05实测：7 个节点

text实测输出 · TF 2.21.0 / Python 3.13.14
图操作数: 7
操作类型: ['AddV2', 'Identity', 'MatMul', 'Placeholder', 'Relu']
eager 直接调用: [[3.0, 3.0, 3.0, 3.0]]
读数 1

3 个 Placeholder

x、w、b 各一个占位节点；真实值在调用时才喂进去。

读数 2

3 个运算

MatMul、AddV2、Relu 对应三层计算，依赖是一条链。

读数 3

外加 1 个 Identity

输出节点做一次身份映射，保证结果有明确的名字可取。3 + 3 + 1 = 7。

同一函数在 Eager 下调用返回 [[3.0, 3.0, 3.0, 3.0]]：1×3 的全 1 输入乘 3×4 的全 1 权重得 3，加 0 偏置，relu 不改变符号。

06画一个两层网络的图

任务：画出「输入 → 加权和 → 激活 → 加权和 → 输出」的图，标出每个节点的输入与输出，并说明哪些节点可以并行。

检查点要观察什么说明
依赖是否成环能否拓扑排序有环就不是合法的前向图
哪两个节点无依赖能否并行同一层的不同单元之间
把 b 去掉图少几个节点Placeholder 与 AddV2 各少一个

追问：① 为什么 get_concrete_function 要用 TensorSpec 而不是直接传 tf.ones？② 同一函数换一种输入形状，为什么可能重新追踪？

验收：图无环；能指认可并行的节点并说出理由。

注：本页代码与「实测输出」的运行口径为 tensorflow-cpu 2.21.0 + Keras 3.15.1 + Python 3.13.14（Windows 原生 CPU，独立虚拟环境，未安装 GPU 版），结果来自本机实际运行，可直接复现。
