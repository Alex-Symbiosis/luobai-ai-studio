工具包地图：keras、data、TensorBoard

TensorFlow 装完之后，命名空间里有几百个名字。真正需要先记住的只有三条线：建模、备料、观测。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出 tf.keras、tf.data、TensorBoard 各自的职责，并指出它们不重叠。
  2. 能按任务把需求分配到正确的工具包，而不是什么都往 keras 里塞。
  3. 能区分 .keras 与 SavedModel 两种保存格式，并知道 save() 传目录会报错。

01六个任务，先分给谁

拿到一个新项目，手上有六件事：读 CSV、打乱分批、搭三层网络、画训练曲线、算梯度、导出给 Java 服务调用。

新手做法

全部塞进 keras

用 keras.utils 硬读文件，用回调里手写画图，导出时 save() 一个目录，然后卡在 ValueError。

工程做法

按职责分包

读盘与分批给 tf.data，建模与训练给 tf.keras，曲线给 TensorBoard 回调，导出用 export()。

分错的代价是什么？

不是「不能跑」，而是每一处都多写一层胶水，且换数据源、换部署目标时要重写。

02三个工位，一条产线

把工具包想成车间里的工位：tf.data 负责备料，tf.keras 负责加工，TensorBoard 是挂在墙上的仪表盘。工位之间靠「张量」这个标准件传递。

直觉结论

先判断「这件事属于备料、加工还是观测」，再去找对应的包，基本不会选错。

03三个核心包 + 一层算子

包职责典型接口不该用它做
tf.keras建模、编译、训练、评估Sequential、compile、fit大规模流式读盘
tf.data数据管道：读、洗、批、预取Dataset、map、batch定义网络结构
TensorBoard训练过程观测与对比tf.keras.callbacks.TensorBoard替代日志与指标计算
tf.nn / tf.linalg底层算子，手写前向与损失relu、matmul搭常规模型

TensorBoard 不是 import 进来就能用的库，它靠回调在训练中写事件文件，再用 tensorboard --logdir 起一个本地网页查看；本模块不展开，只要求知道它属于「观测」这一层。

04巡览一遍命名空间

先用代码确认这些包都在，且职责边界看得见：

pythontoolkit_tour.py
import tensorflow as tf

names = ["data", "keras", "nn", "linalg", "math", "strings", "image",
         "train", "function", "saved_model", "distribute", "autograph"]
for name in names:
    print(f"tf.{name:<12}", "有" if hasattr(tf, name) else "无")

print("keras.layers 数量:", len(dir(tf.keras.layers)))
print("内置数据集:",
      [n for n in ("mnist", "fashion_mnist", "cifar10", "imdb", "boston_housing")
       if hasattr(tf.keras.datasets, n)])

dir() 数出来的是「名字个数」，不是「可用层数」——里面混着大量内部符号，只适合做存在性检查，不要拿它当 API 清单。

05保存与导出：两种格式，一条规矩

模型训完必须落盘。这里同时验证三件事：.keras 能存能读、save() 传目录会报错、export() 产出 SavedModel 目录：

pythonsave_and_export.py
import contextlib
import io
import os
import tempfile

import keras
import tensorflow as tf

print("tf.keras 版本属性:", getattr(tf.keras, "__version__", "无"))
print("tf.keras.layers.Dense is keras.layers.Dense:",
      tf.keras.layers.Dense is keras.layers.Dense)

model = tf.keras.Sequential([tf.keras.layers.Input((1,)), tf.keras.layers.Dense(1)])
d = tempfile.mkdtemp()
keras_path = os.path.join(d, "model.keras")
model.save(keras_path)
print(".keras 存在:", os.path.exists(keras_path))
print("重新加载层数:", len(tf.keras.models.load_model(keras_path).layers))

try:
    model.save(os.path.join(d, "saved_model_dir"))
except Exception as e:
    print("save() 存目录:", type(e).__name__, "Invalid filepath extension")

export_dir = os.path.join(d, "exported")
with contextlib.redirect_stdout(io.StringIO()):
    model.export(export_dir)
print("export() 产物:", sorted(os.listdir(export_dir)))
text实测输出 · TF 2.21.0 / Python 3.13.14
tf.keras 版本属性: 3.15.1
tf.keras.layers.Dense is keras.layers.Dense: True
.keras 存在: True
重新加载层数: 1
save() 存目录: ValueError Invalid filepath extension
export() 产物: ['assets', 'fingerprint.pb', 'saved_model.pb', 'variables']
两个易错点

① save() 的路径必须以 .keras（或 .h5）结尾，传一个目录名会直接抛 ValueError: Invalid filepath extension，这是本机实测。② export() 默认会向 stdout 打印 Saved artifact 的端点信息，redirect_stdout 只是把它收起来，方便对齐输出；那段信息不是报错。

06把六个任务分下去

任务：给六个任务各标一个归属：读 CSV、打乱分批、搭三层网络、画训练曲线、算梯度、导出给非 Python 服务。

任务归属判断依据
读 CSV / 打乱分批tf.data属于备料，与网络结构无关
搭网络 / 算梯度tf.keras 或 tf.GradientTape属于加工
画曲线 / 导出TensorBoard 回调 / export()属于观测与交付

追问：① 为什么 tf.keras 要设计成「懒加载命名空间」而不是直接 import keras？② 如果团队只允许交付一个 .keras 文件，哪些部署端会受限？

验收：六个任务无归属冲突；能说出选错包时多出来的那层胶水。

注：本页代码与「实测输出」的运行口径为 tensorflow-cpu 2.21.0 + Keras 3.15.1 + Python 3.13.14（Windows 原生 CPU，独立虚拟环境，未安装 GPU 版），结果来自本机实际运行，可直接复现。
