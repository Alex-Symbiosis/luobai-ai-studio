装载数据：tf.data 管道

数据只有几百行，训练却还是很慢——瓶颈常常不在模型，而在「每一步都临时读一次盘」。tf.data 把取数变成一条提前备料的流水线。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能搭出「读源 → map 解析 → batch」的最小 Dataset。
  2. 能读懂 element_spec，知道 (None,) 代表什么。
  3. 能说出 shuffle、batch、prefetch 的正确顺序及原因。

01数据不大，为什么还是慢

两种喂数据的方式：

做法 A

每个 step 现读

训练循环里 open 文件、解析、转数组；CPU 等 IO，GPU（或 CPU 计算单元）空转，利用率上不去。

做法 B

管道预取

用 tf.data 声明「怎么取」，框架在训练当前批次时就把下一批准备好，IO 与计算重叠。

为什么不是「一次全读进内存」？

数据小于内存时可以；一旦大于内存，就必须流式，而流式的性能取决于管道有没有预取。

02传送带提前备料

流水线的价值不在单件速度，而在「不停机」。prefetch 就是让备料发生在加工的同时，而不是加工完再去找料。

直觉结论

Dataset 是「怎么取数」的声明，不是数据本身；它可以是惰性的、无限的，也可以每次遍历都重新打乱。

03四个算子，各管一段

算子作用典型参数
TextLineDataset / from_tensor_slices数据源文件路径 / 两个数组
map逐条转换decode_csv、自定义函数
batch拼成批次batch_size
shuffle打乱顺序buffer_size
prefetch提前准备下一批AUTOTUNE

shuffle 的 buffer_size 是「在多大的缓冲区里随机」：设成 1 等于不打乱，设成整个数据集才接近全随机。数据流是无限的时，只能给一个有限的缓冲区。

04从 CSV 到批次张量

pythonload_data.py
import os
import tempfile
import tensorflow as tf

rows = ["x1,x2,y", "1,2,3", "2,4,6", "3,6,9", "4,8,12", "5,10,15", "6,12,18"]
path = os.path.join(tempfile.mkdtemp(), "toy.csv")
with open(path, "w", encoding="utf-8") as f:
    f.write("\n".join(rows) + "\n")

ds = tf.data.TextLineDataset(path).skip(1)
ds = ds.map(lambda line: tf.io.decode_csv(line, record_defaults=[[0.0], [0.0], [0.0]]))
ds = ds.map(lambda x1, x2, y: ({"x1": x1, "x2": x2}, y)).batch(2)

print("element_spec:", ds.element_spec)
for step, (features, labels) in enumerate(ds):
    print(step, features["x1"].numpy().tolist(), labels.numpy().tolist())

ds2 = tf.data.Dataset.from_tensor_slices(([[1.0], [2.0], [3.0]], [1.0, 2.0, 3.0])).batch(2)
print("from_tensor_slices 批次数:", sum(1 for _ in ds2))

skip(1) 去掉表头；decode_csv 的 record_defaults 必须与列数一致，否则解析出的元组长度不对，第二个 map 会报参数个数不匹配。

读数 1

6 行 → 3 批

批大小 2，6 条数据正好 3 批；最后一批不足时不会自动丢弃。

读数 2

shape=(None,)

批内样本数动态：最后一批可能不足 2 条，所以这一维是 None。

读数 3

2 批

from_tensor_slices 把 3 个样本按 2 分批，得 2 批（第二批 1 条）。

顺序陷阱

先 batch 再 shuffle，打乱的是「批次顺序」而不是样本顺序，同一批内的样本始终挨在一起。训练集要先 shuffle。

06搭一条四步管道

任务：用 tf.data 搭「读 CSV → 打乱 → 分批 → 预取」，打印一个批次的形状。

步骤要观察什么说明
shuffle(6)两次遍历顺序是否不同缓冲区等于样本数时接近全随机
batch(4)最后一批几条6 条数据 → 4 + 2
prefetch(AUTOTUNE)输出是否变化不变，只影响调度

追问：① 为什么 shuffle 必须放在 batch 之前？② 训练集打乱、验证集不打乱，理由分别是什么？

验收：打印出的批次形状为 (4, 2)（特征）与 (4,)（标签）。
