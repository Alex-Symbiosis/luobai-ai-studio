Spark MLlib：同一套思路，另一种规模

单机放不下数据时，Scikit-Learn 的写法会先卡在内存，而不是卡在算法。Spark MLlib 沿用 Estimator / Transformer 的思想，把同一套建模流程搬到分布式集群；变的是一致性约束，不是建模思路。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出 MLlib 中 DataFrame、VectorAssembler、Estimator 的角色。
  2. 能对照 Scikit-Learn 说出两套 API 的对应关系。
  3. 能判断一个任务该用单机还是分布式框架。

01数据放不进一台机器

同一个流失预测任务，两种运行环境：

做法 A

单机 Scikit-Learn

数据 200 万行、特征 300 个，内存勉强装下；训练 20 分钟，调参靠等待。

做法 B

Spark MLlib

数据在 HDFS 上，按分区并行读取；同一套 Estimator 写法，训练时间随集群规模下降。

两套框架的 API 长得不一样，为什么说建模思路是同一套？

因为两者都是「定义阶段 → fit → transform / predict」。差别在数据抽象与执行方式，不在建模逻辑本身。

02同一张图纸，两种车间

图纸规定工序，车间决定用几台机器、怎么搬运。MLlib 换的是车间，不是图纸。

直觉结论

从单机迁到分布式，先做概念映射，再改代码。映射清楚了，迁移就只是换类名与数据源。

03四个核心对象

MLlib 对象作用Scikit-Learn 对应
DataFrame带列名的分布式表pandas DataFrame
VectorAssembler把多列拼成一个特征向量ColumnTransformer / 直接传 X
Estimator有 fit 方法的算法对象Estimator
Pipeline把阶段串成一条流水线Pipeline

一个关键差异：MLlib 的算法通常只接受一个名为 features 的向量列，因此几乎每段代码都要先做 VectorAssembler。这一步在单机框架里常被省略，迁移时最容易漏。

04惰性执行与分布式代价

惰性

先画图，后执行

转换操作只记录计划，遇到 fit、count 等动作才真正计算；报错往往延迟到最后一步。

分区

并行但有开销

数据按分区并行处理；分区过多调度开销大，过少则利用不满。

内存

缓存要显式

反复使用的中间结果需 cache/persist，否则每次动作都从头重算。

这三点决定了 MLlib 的调优重点与单机不同：不是先调模型超参数，而是先看分区、缓存与 shuffle。数据规模没到瓶颈时，分布式框架反而更慢。

选型边界

数据能单机处理、迭代频繁、需要丰富算法时，优先 Scikit-Learn；数据超出单机内存、已在数据湖中、需要与批处理共用集群时，再考虑 MLlib。

05同一任务的两种写法

步骤Scikit-LearnSpark MLlib
读数据pd.read_csvspark.read.csv
拼特征直接选列VectorAssembler
标准化StandardScalerStandardScaler（fit 后 transform）
模型LogisticRegressionLogisticRegression
训练fit(X, y)fit(df)

逐行对照后会发现，真正需要重写的只有数据读取与特征组装；模型与评估的概念完全一致。迁移成本主要来自数据层，而不是算法层。
