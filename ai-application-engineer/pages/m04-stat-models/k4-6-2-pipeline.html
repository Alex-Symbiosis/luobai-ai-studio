Pipeline：把预处理和模型焊在一起

先在全体数据上做标准化，再交叉验证，是数据泄漏最常见的来源。Pipeline 把「预处理 + 模型」封成一个整体，让 fit 只发生在训练折内，从结构上堵住这类错误。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说明 Pipeline 解决了什么工程问题。
  2. 能写出一个包含预处理与模型的 Pipeline。
  3. 能解释为什么交叉验证必须作用在整条流水线上。

01预处理与模型分开写，泄漏了

两种写法，代码都能跑，评估结果却不同：

做法 A

先全体标准化，再切分

标准化用到了验证折的均值与方差；验证信息提前进入训练，分数偏高。

做法 B

把标准化放进流水线

交叉验证时，每一折只在训练部分 fit 标准化器，验证部分只做 transform。

两种写法模型完全一样，为什么 A 的分数不可信？

因为 A 的预处理「看过」验证数据。分数虚高不是模型更强，而是评估被污染。

02流水线：原料进去，成品出来

工厂不会把半成品搬来搬去；原料从一端进，经过各道工序，成品从另一端出。Pipeline 就是这条产线。

直觉结论

Pipeline 不只是「少写几行」，而是把数据流与学习边界固定下来。边界固定，泄漏就很难发生。

03一条链，两种阶段

结构 
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ("scale", StandardScaler()),
    ("clf", LogisticRegression()),
])
pipe.fit(X_train, y_train)
pred = pipe.predict(X_test)
阶段位置要求fit 时做什么predict 时做什么
中间阶段必须是 transformerfit_transformtransform
最后阶段estimator / predictorfitpredict

命名（如 "scale"、"clf"）不是装饰：网格搜索要用「阶段名__参数名」定位超参数，名字写错会直接找不到。

04为什么它能防泄漏

整条线一起 fit交叉验证的每一折，都在训练部分重新 fit 标准化器与模型。
验证部分只 transform验证折不参与 fit，只被训练折学到的规则转换。
超参数用前缀定位`clf__C` 表示最后阶段的正则强度，`scale__with_mean` 表示标准化选项。
整体保存上线时保存整条流水线，避免「模型对了但预处理忘了」。

第三点常被忽略：如果只保存模型、上线时重新写一遍预处理，训练与推理的规则就可能不一致。保存整条 Pipeline，是保证一致性的最简单办法。

05同一份数据，两种写法

写法交叉验证准确率问题
先全体标准化再切分0.842验证折信息泄漏，分数虚高
Pipeline + 交叉验证0.817口径正确，可作为上线预期

两者差 0.025，看起来不大，但方向是系统性偏高。数据量越小、预处理越强（如特征选择），差距越明显。

检查清单

任何「用全体数据算出来的统计量」都不能在切分前使用：均值、方差、分位数、目标编码、特征选择结果，全部要放进流水线。

06搭一条完整流水线

任务：为「数值特征 + 类别特征」的混合数据搭一条流水线。

  1. 数值列：缺失填补 + 标准化。
  2. 类别列：缺失填补 + 独热编码。
  3. 拼接后接一个逻辑回归。
  4. 用 5 折交叉验证报告准确率，并说明预处理发生在哪一步。

验收：能指出「所有 fit 都只发生在训练折内」，并能用「阶段名__参数名」写出一个待调超参数。

注：本页涉及的数值均为教学示意，用于说明机制，非真实实验记录。
