Scikit-Learn 的统一 API

换模型时最怕的是「每个库一套写法」。Scikit-Learn 用 fit / predict / transform 三个动词统一了几乎所有模型，学会一套接口，就能在几十种算法之间切换。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出 estimator 与 transformer 的区别。
  2. 能区分模型参数与超参数，并指出各自设置方式。
  3. 能用统一 API 完成一次训练与预测。

01换一个模型，重写一遍代码

不用框架时，每换一个模型都要重写一套流程：

做法 A

每个模型一套函数

线性回归写 `train_lr`，决策树写 `train_tree`；输入格式、返回结构都不同，切换成本高。

做法 B

统一成 fit / predict

所有模型都先 `fit(X, y)`，再 `predict(X)`；换模型只改一行类名。

统一的接口，除了少写代码，还带来了什么？

带来了可替换性与可组合性：交叉验证、网格搜索、流水线都能对任意模型复用，不必为每个算法单独实现。

02同一个插座，不同的电器

插座标准统一后，换电器不用改墙。fit / predict 就是机器学习库的「插座标准」。

直觉结论

API 统一的价值不在语法，而在生态复用：只要对象遵守同一套接口，就能被同一套评估与调参工具处理。

03三个动词与两类对象

对象 / 方法作用输入输出例子
Estimator.fit从数据学参数(X, y) → self线性回归、决策树
Predictor.predict对新样本输出预测X → ŷ分类、回归模型
Transformer.transform按已学规则转换数据X → X'标准化、编码器
Transformer.fit_transform先学规则再转换X → X'训练集预处理

关键区别：transform 只改数据，predict 给结论。把标准化器当模型去 predict，或把分类器当转换器去 transform，都会直接报错——这其实是接口在帮你检查语义。

04参数与超参数，两条设置路径

类型来源设置方式例子
模型参数fit 从数据学到训练后读取回归系数、树的分裂点
超参数训练前由人设定构造或 set_params树深、正则强度、K 折数
最小示例 
from sklearn.linear_model import LinearRegression
model = LinearRegression()          # 超参数在这里设
model.fit(X_train, y_train)         # 参数在这里学
pred = model.predict(X_test)
print(model.coef_, model.intercept_)

记住这条边界：fit 之前能改的是超参数，fit 之后能读的是模型参数。把两者混在一起讲，就会出现「为什么调了 coef_ 没生效」这类问题。

05换模型只改一行

任务模型类改动量
线性回归LinearRegression()—
岭回归Ridge(alpha=1.0)换类名 + 一个超参数
决策树回归DecisionTreeRegressor(max_depth=5)换类名 + 一个超参数

三者的 fit / predict 调用完全一致，评估代码也完全一致。这就是统一 API 的实际收益：把「换模型」从重写流程变成改一行配置。
