一维与二维梯度下降的实现

梯度下降的代码只有三件事：算梯度、乘步长、更新参数。维度从一变二，变的只是梯度从标量变成向量，更新规则一个字都不用改。把这两段代码写通，后面所有模型都只是换损失函数。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出梯度计算、参数更新、记录三步的代码骨架。
  2. 能说明一维标量梯度与二维向量梯度的对应关系。
  3. 能补全一段梯度下降代码并验证路径收敛。

01公式会推，代码写不出

手推梯度没问题，打开编辑器却卡住：

卡点 A

不知道循环里放什么

公式是一行，代码要写成循环，分不清哪句在算梯度、哪句在更新。

卡点 B

二维就乱

两个参数各有一个偏导，不知道是分别更新还是一起更新。

卡点 C

不知道对没对

跑完只有一个数，无法判断是收敛了还是中途出错。

一维和二维的代码，真的需要写两套吗？

不需要。把参数写成向量、梯度写成向量，更新公式与一维完全相同；差别只在梯度怎么算。

02每轮照着公式抄一遍

把更新公式当成模板：每轮把当前的 θ 代进去算梯度，再按模板算出新 θ。人怎么手算，代码就怎么写。

直觉结论

维度变化只影响梯度的形状（标量 → 向量），不影响更新规则。所以先把一维写对，再把它向量化，是最稳的学习路径。

03三件事与两条路径

步骤一维二维
算梯度g = dL/dθg = (∂L/∂θ₁, ∂L/∂θ₂)
乘步长η · gη · g，对每个分量分别乘
更新θ ← θ − ηgθ ← θ − ηg，两个分量同时更新
关键约束

两个分量必须同时更新：先用旧 θ 算出全部偏导，再统一替换。若更新完 θ₁ 就用新值算 θ₂ 的偏导，走的就不是梯度方向。

04向量化写法

一维与二维共用的骨架 
def gd(grad, theta, eta, steps):
    path = [theta[:]]
    for _ in range(steps):
        g = grad(theta)          # 算梯度
        theta = [t - eta * gi for t, gi in zip(theta, g)]
        path.append(theta[:])    # 记录路径
    return theta, path

一维时 θ 写成 `[x]`，grad 返回 `[2*(x-3)]`；二维时 θ 写成 `[x, y]`，grad 返回两个偏导。调用方式完全一样，这就是向量化的意义。

函数梯度理论最优
(θ − 3)²2(θ − 3)θ = 3
(θ₁ − 1)² + (θ₂ + 2)²(2(θ₁ − 1), 2(θ₂ + 2))(1, −2)

写完先用这两个有解析最优的函数验证：路径最后应落在理论值附近。验证通过，再换成真实损失，才不会把「梯度写错」误判成「模型不行」。

05两条路径的收敛对照

轮次一维 θ二维 (θ₁, θ₂)
00.00(0.00, 0.00)
52.36(0.66, −1.31)
102.89(0.89, −1.77)
202.99(0.99, −1.97)

两条路径都以相同速率靠近各自的最优，说明更新规则一致。若二维只更新一个分量，或两个分量用了不同步长，路径会明显偏斜——这是代码错误最直观的信号。
