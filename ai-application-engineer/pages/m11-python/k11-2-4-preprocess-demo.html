可复用预处理函数与词频报告

清洗规则写三遍，三份就会慢慢分叉：训练用的和上线用的不是同一套，指标再好也无法解释。把规则收进一个函数、把记录收进一个数据类，才有可复用的基础。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能按「配置 / 数据模型 / 纯函数 / I/O / 入口」五层拆分预处理脚本。
  2. 能用 dataclass 定义文档模型，并用 JSONL 读写。
  3. 能写一个纯函数生成词频报告，并用断言固定口径。

01三份清洗规则

同一个项目里，清洗逻辑出现了三次：

训练脚本

版本 A

去标签、转小写、按空格切；为了跑通，额外删掉了长度小于 2 的词。

评估脚本

版本 B

从训练脚本复制，但忘了删短词；评估集与训练集的词表口径不一致。

上线服务

版本 C

为了性能重写了一遍，NFKC 被省掉；线上遇到全角字符时特征直接缺失。

三份代码都能跑，为什么指标仍然不可信？

因为训练、评估、推理看到的输入分布不同；模型学到的关系在线上不成立。

02一把尺子量三次

量三次桌子，必须用同一把尺子；换一把尺，差值不是桌子变了，是尺子变了。

直觉结论

可复用不是「把代码抽成函数」这么简单，而是「让三处调用同一个版本，并能证明它们一致」。

03五层结构与一条边界

层放什么不应该放什么
配置路径、语言、阈值业务逻辑
数据模型Document、Token 等 dataclass文件读写
纯函数清洗、分词、统计全局状态、打印
I/OJSONL/CSV 读写、编码处理清洗规则
入口参数解析、串联流程、日志可复用的核心逻辑

边界的判断标准只有一条：核心函数能否用内存里的数据直接测试。能做到，I/O 就隔离干净了；做不到，说明读写还混在逻辑里。

JSONL 适合一行一条记录、可流式处理；JSON 适合整体读入的小文件。两者都不是数据库，复杂查询要换存储。

04数据模型 + 纯函数

先定义文档模型并用 JSONL 往返，只依赖标准库：

pythondocs_jsonl.py
"""最小可运行示例：dataclass 文档模型 + JSONL 读写（仅标准库）。"""
import json
import tempfile
from dataclasses import asdict, dataclass
from pathlib import Path


@dataclass
class Document:
    doc_id: str
    text: str
    lang: str = "en"

    def to_json(self) -> str:
        return json.dumps(asdict(self), ensure_ascii=False)

    @classmethod
    def from_json(cls, line: str) -> "Document":
        return cls(**json.loads(line))


docs = [Document("d1", "Hello world"), Document("d2", "你好，世界", "zh")]

with tempfile.TemporaryDirectory() as tmp:
    path = Path(tmp) / "docs.jsonl"
    path.write_text("\n".join(d.to_json() for d in docs), encoding="utf-8")

    loaded = [Document.from_json(line) for line in path.read_text(encoding="utf-8").splitlines()]
    print(loaded)
    print("记录数:", len(loaded))
    assert loaded[1].lang == "zh"

再把报告逻辑写成纯函数，输入字符串、输出字典，不碰文件：

pythonreport.py
from collections import Counter


def word_report(text: str, top: int = 2) -> dict:
    words = [w for w in text.lower().split() if w.isalpha()]
    freq = Counter(words)
    return {"tokens": len(words), "types": len(freq), "top": freq.most_common(top)}


print(word_report("The cat sat on the mat. The dog sat on the log."))

word_report 里没有 open、没有 print 之外的副作用；换数据源只需换传入的字符串，测试可以直接断言返回的字典。

05两段实测输出

运行 python docs_jsonl.py：

text实测输出 · Python 3.13.14
[Document(doc_id='d1', text='Hello world', lang='en'), Document(doc_id='d2', text='你好，世界', lang='zh')]
记录数: 2

运行 python report.py：

text实测输出 · Python 3.13.14
{'tokens': 10, 'types': 5, 'top': [('the', 4), ('sat', 2)]}
读数 1

往返不丢字段

asdict 与 cls(**...) 保证写出与读回一致；ensure_ascii=False 让中文保持可读。

读数 2

10 与 5

标点词 mat. 被 isalpha 过滤，所以 token 从 12 降到 10；口径写进函数，不靠口头约定。

读数 3

top 只取前二

top 参数控制报告长度；默认值也是契约的一部分，改默认值要同步改文档。

06把两段拼成一个可交付脚本

任务：新建 pipeline.py，把上面的数据模型、报告函数与一段读取逻辑串起来，满足下面四条。

输入从 docs.jsonl 读取记录，跳过空行；每行必须能构造 Document。
处理对每条记录调用同一个 word_report，不在循环里另写清洗。
输出打印「doc_id → tokens / types」，最后打印全局合计。
可测word_report 单独可导入，导入时不打印、不读文件。

追问：① 为什么 Document.from_json 用 classmethod，而不是普通函数？② 如果一条记录字段缺失，应该在 I/O 层还是纯函数层报错？

验收：同一份 JSONL 跑两次输出一致；删掉一行必填字段时，错误信息能指出行号与缺失字段。

注：本页代码与「实测输出」的运行口径为 Python 3.13.14（Windows），结果来自本机实际运行，可直接复现。
