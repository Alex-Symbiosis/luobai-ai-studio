语料库的开发方法

两个人标同一批句子，一致率 87.5%，看起来不错；扣掉随机一致后只剩 0.81。语料开发的核心，是把「标注口径」变成一个可测量的东西。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能复述语料库开发的完整流程，并指出试标的位置与作用。
  2. 能写出 Cohen's kappa 的公式，并按区间解读结果。
  3. 能用标准库实现 kappa 计算，处理分母为零的边界情况。

01一致率 87.5% 到底好不好

两名标注者独立标了 8 个词的词性，其中 7 个相同：

直觉判断

87.5%，挺好

七对一，看起来可以直接开工；但没人说得清这是「真的会标」还是「碰巧都是高频词」。

扣除随机

kappa = 0.81

把「按标签分布瞎猜也能猜中的部分」扣掉，剩下的才是真实一致性。

为什么原始一致率会高估标注质量？

因为类别分布不平衡时，多数类本身就能带来高一致率；kappa 把这块随机成分扣除了。

02口径先对齐，规模才有意义

标注不是「找几个人开始标」，而是「先证明大家理解的是同一件事」。规范说不清，标得越多返工越大。

直觉结论

一致性系数不是给标注者打分，而是在给规范做体检：分数低，先改规范，不是催标注者更认真。

03流程与 kappa

环节要点产物
规范每个标签有正例、反例、边界案例标注手册
试标小样本双盲标注分歧清单
一致性检验计算 kappa，定位分歧类型一致性报告
仲裁专家裁定分歧样本最终标签
全量与抽检按手册执行，抽检回流发布语料

Cohen's kappa 的定义是 kappa = (Po - Pe) / (1 - Pe)：Po 为观察一致率，Pe 为按各自标签分布独立猜测时的期望一致率。分母 1 - Pe 是「随机之外还有多少可改进空间」。常用经验区间：<0.40 差、0.40–0.60 中等、0.60–0.80 较好、>0.80 很好。

大纲原文的错字

大纲写作「语料库的卡发方法」，「卡发」应为「开发」。页面按正确术语讲解，检索对照时保留原词。

04手写 kappa，含边界处理

只用标准库（collections.Counter），Python 3.13.14 直接运行，无第三方依赖：

pythonkappa_demo.py
"""最小可运行示例：计算两名标注者的 Cohen's kappa（仅标准库）。"""
from collections import Counter


def cohen_kappa(a: list[str], b: list[str]) -> float:
    assert len(a) == len(b) and a, "两列标签长度必须一致且非空"
    n = len(a)
    labels = sorted(set(a) | set(b))
    po = sum(x == y for x, y in zip(a, b)) / n
    pe = sum((a.count(l) / n) * (b.count(l) / n) for l in labels)
    return (po - pe) / (1 - pe) if pe != 1 else 1.0


ann1 = ["N", "V", "N", "ADJ", "V", "N", "ADJ", "V"]
ann2 = ["N", "V", "N", "ADJ", "N", "N", "ADJ", "V"]

po = sum(x == y for x, y in zip(ann1, ann2)) / len(ann1)
k = cohen_kappa(ann1, ann2)

print("标签分布(标注者1):", dict(Counter(ann1)))
print(f"观察一致率 Po = {po:.3f}")
print(f"Cohen's kappa = {k:.3f}")
assert 0.7 < k < 1.0

两处细节：pe != 1 的分支处理「两人标签分布完全相同且各只有一个类别」的退化情况，否则会除以零；sorted(set(a) | set(b)) 保证遍历顺序稳定，不依赖集合的迭代顺序。

06让 kappa 掉下来

任务：只改 ann2，观察三个数字各怎么变。

改动预期变化说明
把两个 N 改成 VPo 下降
让 ann2 全标 NPo 可能不低，kappa 接近 0多数类陷阱
把 8 个样本扩到 80 个系数更稳定

追问：① 为什么「全标同一个类」时 kappa 会趋近 0 而不是很高？② 三个标注者时该用什么系数？

验收：三组改动都能运行；能解释 Po 与 kappa 在什么情况下差距最大。
