token 与 type：词频统计的两个口径

「这份语料有一万词」这句话，至少有两种读法：一万次出现，还是一万个不同词形。报告里不写清口径，后面的词表大小、特征维度、覆盖率全都会对不上。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能区分 token（词例）与 type（词型），并给出各自的计算方式。
  2. 能解释齐夫分布与长尾对特征设计的影响。
  3. 能计算 type/token 比，并说明它为什么不能跨语料直接比较。

01同一个「一万词」

周报里同一句「语料规模约一万词」，三个人理解不同：

读法 A

一万次出现

把全文按词切分后逐个累加，标点不算；这是 token 数。

读法 B

一万个不同词

去重后的词形数量；这是 type 数，也就是通常说的「词汇量」。

读法 C

一万个词条

词典里的条目数，含未在语料中出现的词；这既不是 token，也不是 type。

三个数字都可能是一万，为什么不能混用？

因为它们回答不同问题：出现频次、词形丰富度、词典规模；混用会让特征维度与覆盖率互相矛盾。

02总册数，还是书名数

图书馆说「藏书十万册」，指的是复本总数；说「三万种书」，指的是不同书名。采购时要看种数，借阅量要看册数。

直觉结论

token 看「量」，type 看「种类」；齐夫分布决定了头部词很少、尾部很长，词表因此总在膨胀。

03三个指标与一条曲线

指标算法回答什么
token 数分词后逐项计数，重复也计文本有多长、处理量多大
type 数对 token 去重后计数词表多大、特征维度多高
type/token 比type 数 ÷ token 数词形丰富度，受文本长度强烈影响

齐夫定律描述的是排名与频次的关系：排名第 r 的词，频次大致与 1/r 成正比。它带来的直接后果是长尾——大量 type 只出现一次（称为 hapax），它们既撑大了词表，又几乎不提供统计证据。工程上的应对是设最小频次阈值，把低频词折叠成 <UNK>。

易错点

type/token 比不能跨语料直接比较：文本越长，新词越少，比值天然下降；它只在长度相近时才有可比性。

04排一次序，看清头部与长尾

下面这段用同一份小语料演示三个指标与频率排名，只依赖标准库：

pythontoken_type.py
from collections import Counter

tokens = "the cat sat on the mat the dog sat on the log".split()
freq = Counter(tokens)
ranked = sorted(freq.items(), key=lambda kv: (-kv[1], kv[0]))

print("词例:", len(tokens))
print("词型:", len(freq))
print("排名:", ranked[:3])
print("只出现一次:", sum(1 for v in freq.values() if v == 1))

排序键写成 (-频次, 词形)：先按频次降序，频次相同时按字母序，保证每次运行结果一致。若只写 -kv[1]，并列项的顺序依赖字典插入顺序，换一份数据就可能变。

「只出现一次」的计数就是 hapax 规模。它的比例越高，说明语料越长尾，越需要频次阈值；反过来，短文本里几乎每个词都是 hapax，阈值会把词表砍空。

05实测输出与读数

运行结果为：

text实测输出 · Python 3.13.14
词例: 12
词型: 7
排名: [('the', 4), ('on', 2), ('sat', 2)]
只出现一次: 4
读数 1

12 与 7

12 次出现、7 个词形；the 一个词就占了三分之一，头部集中非常明显。

读数 2

并列按字母序

on 与 sat 都是 2 次，字母序让 on 排在前面；这不是「更重要」，只是排序规则。

读数 3

4 个 hapax

cat、mat、dog、log 各出现一次；7 个词型里有 4 个只出现一次，长尾占了一半以上。

这就是为什么词袋特征常要做 min_df：低频词维度大、证据少，留着只会增加方差。
