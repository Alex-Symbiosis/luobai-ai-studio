原始文本处理：分词、规范化与停用词

网页抓下来的文本，先是一堆标签、实体和全角字符。清洗不是「顺手删一删」，而是一条有顺序的流水线：顺序换了，词表就换了。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能按「解码 → 去标签 → 解实体 → 规范化 → 去噪 → 分词」列出清洗链。
  2. 能解释 NFC 与 NFKC 的差别，并按任务选择。
  3. 能写出一段可复现、带断言的清洗函数。

01同一段网页，两种洗法

同一段抓取结果，两个人洗出了不同的词表：

做法 A

先解实体，再去标签

先把 &lt;p&gt; 解成 <p>，再去标签时把正文里的比较符号也一起删了；词表少了一批本应保留的符号。

做法 B

先去标签，再解实体

先删结构标签，再把 &amp; 还原成 &；正文符号保留，噪声标签清掉，顺序写进函数。

两步都做了，为什么结果不同？

因为清洗是有损且顺序敏感的：前一步改变了后一步看到的输入。

02洗菜的顺序

洗菜时先去泥、再切、最后泡，和先切再洗，得到的干净程度不一样；切面会流失，顺序不能随便换。

直觉结论

清洗链是一份契约：同样的原始输入，经过同一版本函数，必须得到同样的输出。

03六步流水线

步骤操作典型实现
解码字节 → 字符串decode("utf-8", errors="replace")
去标签删除 HTML/XML 标签正则或解析器
解实体&amp; → &html.unescape
规范化统一全角/半角与兼容字符unicodedata.normalize
去噪与空白归一删控制符、折叠空白re.sub(r"\s+", " ", s)
分句分词切成句序列与词序列正则、词典、模型

NFC 与 NFKC 的区别要单独记住：NFC 做规范等价合成，保留字符语义；NFKC 做兼容等价，会把全角字母、①、㈱ 之类折叠成普通形式。前者适合需要保留原字形的场景，后者适合统一检索与匹配。

常见误解

正则去标签不能处理嵌套结构与属性里的 >；结构复杂时用 HTML 解析器，别硬套一条正则。

04一个函数，八个断言

下面这段只依赖标准库，保存为 clean_demo.py：

pythonclean_demo.py
"""最小可运行示例：HTML 去标签 + 实体解码 + NFKC 规范化 + 分词。"""
import html
import re
import unicodedata

RAW = '<p>Caf&eacute; &amp; tea&nbsp;—&nbsp;price: <b>＄３．５０</b></p>'


def strip_tags(text: str) -> str:
    """删除标签，用空格替换，避免相邻词粘连。"""
    return re.sub(r"<[^>]+>", " ", text)


def normalize(text: str) -> str:
    """实体解码 → NFKC → 不换行空格替换 → 空白折叠。"""
    text = html.unescape(text)
    text = unicodedata.normalize("NFKC", text)
    text = text.replace("\u00a0", " ")
    text = re.sub(r"\s+", " ", text)
    return text.strip()


clean = normalize(strip_tags(RAW))
print("清洗结果:", clean)
tokens = re.findall(r"[\w.]+", clean.lower())
print("词序列:", tokens)
assert "café" in clean.lower()
assert "$3.50" in clean

三个细节决定可复现性：strip_tags 用空格替换而不是空串，避免 tea<b>price 粘成一个词；normalize 内部顺序固定；断言直接写在脚本末尾，改坏任何一步都会立刻失败。

中文文本还要多一步分词，且不能按空格切；英文的正则 [\w.]+ 会把 3.50 当成一个词，这是有意的取舍。

05实测输出与两条断言

运行 python clean_demo.py，实测输出：

text实测输出 · Python 3.13.14
清洗结果: Café & tea — price: $3.50
词序列: ['café', 'tea', 'price', '3.50']
读数 1

全角变半角

＄３．５０ 经 NFKC 变成 $3.50；若不做规范化，正则要额外处理全角数字。

读数 2

实体先还原再分词

&eacute; 还原成 é，才能命中 café；若先分词，实体被切成 eacute，断言直接失败。

注意 — 与 & 被保留：清洗的目标是去噪，不是删掉所有符号；哪些符号算噪声，要由任务决定。
