Python 的定位与执行模型

「Python 是解释型语言」这句话只说了一半：它确实不直接生成机器码，但也不是把源码逐字念给 CPU。中间那层字节码，既能解释「改一行立刻见效」，也能解释「为什么它比 C 慢」。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能按「源码 → 字节码 → 虚拟机」复述一次执行的完整路径。
  2. 能说明解释执行与编译执行各自换来了什么、付出了什么。
  3. 能解释 `.pyc`、`__name__` 与模块导入之间的关系。

01两种「解释型」

同一句「Python 是解释型语言」，两个人理解得并不一样：

理解 A

逐行念给 CPU

以为解释器读一行、执行一行，源码直接变成动作；于是解释不清为什么会有 .pyc 文件，也解释不清为什么第一次运行比第二次慢。

理解 B

先编译成字节码，再逐条执行

知道源码先被编译成一种中间指令，再由虚拟机执行；.pyc 是缓存，改一行只会让受影响的模块重新编译。

同一门语言，为什么 A 的解释一遇到「缓存」和「性能」就说不通？

因为 A 漏掉了中间层。补上字节码这一步，执行模型才闭合。

02同声传译，还是先译整本

国际会议有两种译法：同声传译边听边译，发言者一停就能听到；笔译则先把整本书译完，出版后读者一次拿到成品。

直觉结论

字节码相当于「译稿」：比源码更接近机器，但仍需虚拟机翻译；缓存译稿，就省下重复编译的时间。

03三个阶段与三个特点

阶段做什么产物
词法 / 语法分析把源码解析成抽象语法树AST
编译把语法树编译成字节码.pyc
执行CPython 虚拟机逐条执行字节码运行结果
定义

Python 是解释执行、动态类型、以缩进划分代码块的通用高级语言。CPython 是官方参考实现：源码先编译为字节码，再由虚拟机执行。

三个特点各有一层工程后果：解释执行让迭代快，但热点循环要靠 NumPy/C 扩展；动态类型让写法灵活，但需要测试与类型注解兜底；缩进属于语法，混用 Tab 与空格会直接报错，而 PEP 8 只是风格规范，违反了仍能运行。

04跑一遍，再看缓存

下面这段只依赖标准库，文件名 tokenize_demo.py：

pythontokenize_demo.py
"""最小可运行示例：正则分词 + 词频统计 + 二元组（仅标准库）。"""
import re
from collections import Counter

TEXT = "Natural language processing with Python is fun. Python is powerful and fun!"


def tokenize(text: str) -> list[str]:
    """英文小写化后按字母序列切分，丢弃标点。"""
    return re.findall(r"[a-z]+", text.lower())


tokens = tokenize(TEXT)
vocab = Counter(tokens)

print("词数:", len(tokens))
print("词汇量:", len(vocab))
print("Top3:", vocab.most_common(3))
print("二元组:", list(zip(tokens, tokens[1:]))[:3])
assert vocab["python"] == 2

运行只需一条命令：python tokenize_demo.py。第一次运行时，CPython 会把编译结果写入 __pycache__/tokenize_demo.cpython-313.pyc；再次运行直接读缓存，所以小脚本的启动差异不明显，大模块才看得出来。

脚本末尾的 assert 不是装饰：它把「词汇量应该是多少」写成可执行断言，改坏正则时能立刻失败，而不是等到下游分类指标下降才发现。

05实测输出与读数

在 Python 3.13.14 下运行上面的脚本，输出为：

text实测输出 · Python 3.13.14
词数: 12
词汇量: 9
Top3: [('python', 2), ('is', 2), ('fun', 2)]
二元组: [('natural', 'language'), ('language', 'processing'), ('processing', 'with')]
读数 1

12 与 9

12 是 token 数（每次出现都算），9 是 type 数（去重后的词形）。同一个「词表大小」，口径必须先说清。

读数 2

Top3 并列

python / is / fun 各出现两次；Counter.most_common 按计数降序，并列时保持首次出现顺序。

读数 3

二元组只看前 3 对

切片 [:3] 只截取开头，完整二元组有 11 对，正好比 token 数少 1。

这三个数字在第 11.2 节会被反复用到：词频报告、特征维度、语料规模，都建立在这两种口径之上。

06改一处，先预测再运行

任务：把 tokenize 的正则从 [a-z]+ 改为 [a-z]{2,}，先写下你对四个输出的预测，再运行核对。

观察项你的预测核对点
词数单字母词 a 是否被丢掉
词汇量去重后减少了几个
Top3排名是否变化
二元组相邻关系是否被切断

追问：① 删掉 __pycache__ 再运行，输出会变吗？为什么？② 如果把 TEXT 换成中文句子，这个正则会得到什么，说明它缺了哪一步？

验收：能说清「改的是编译前的源码，缓存只影响启动时间，不影响结果」，并指出中文需要专门分词。

注：本页代码与「实测输出」的运行口径为 Python 3.13.14（Windows），结果来自本机实际运行，可直接复现。
