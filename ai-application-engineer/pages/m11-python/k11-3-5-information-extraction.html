信息提取：规则与字段模板

分类回答「这条文本属于哪类」，抽取回答「里面有哪些事实」。前者输出一个标签，后者输出一条条可入库的记录；字段没定清楚，抽出来的串就没法用。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能区分分类、命名实体识别与关系抽取的输出形式。
  2. 能先定字段模板，再用正则匹配并校验。
  3. 能说明规则抽取的适用边界与失效场景。

01从公告到表格

一批公司公告要进数据库，两个小组的做法不同：

做法 A

先写正则，再想字段

看到「收购」就抓前后各十个字，结果抓回半句话、公司简称、甚至标点；字段对不上，只能人工再读一遍。

做法 B

先定字段，再选模式

字段定为「收购方、被收购方、金额、公告日期」，每个字段配模式与校验；抽不到就留空，不硬凑。

两组的正则都能匹配到文本，为什么只有 B 的结果能入库？

因为入库需要的是有类型、可校验的字段，不是一段上下文。

02先画表头，再填内容

做报销单时先有「日期、事由、金额、经手人」四列，再去贴发票；没有表头，贴得再整齐也无法汇总。

直觉结论

抽取的目标不是「找到字符串」，而是「填满一张有类型的表」。

03三个子任务与一条流水线

子任务输出例子
命名实体识别实体边界 + 类型Alice（人名）、Acme Corp（机构）
关系抽取（头实体，关系，尾实体）（Alice，任职于，Acme Corp）
事件抽取事件类型 + 论元收购事件：收购方、标的、金额

流水线是「分词/词性 → 实体 → 组块/句法 → 关系/属性 → 三元组 → 校验入库」。上游边界错，下游关系必然错，所以实体识别要先保证边界，再追求类型细化。

规则与模型是互补关系：日期、编号、固定句式用正则近乎完美；开放表达、指代、跨句则要模型。工业系统通常先规则保底，再用模型补召回。

04实体 + 关系，两段正则

下面这段只依赖标准库，先识别实体，再按「X works at Y」抽三元组：

pythonie_demo.py
"""最小可运行示例：正则实体识别 + 关系模式抽取三元组（仅标准库）。"""
import re

TEXT = "Alice works at Acme Corp in Beijing. Bob works at Acme Corp since 2020."
PERSONS = {"Alice", "Bob"}
ORG = r"Acme Corp"


def find_entities(text: str) -> tuple[list[str], list[str]]:
    words = re.findall(r"[A-Z][a-z]+", text)
    persons = sorted({w for w in words if w in PERSONS})
    orgs = sorted(set(re.findall(ORG, text)))
    return persons, orgs


def find_triples(text: str) -> list[tuple[str, str, str]]:
    pattern = re.compile(rf"(?P<head>{'|'.join(PERSONS)})\s+works at\s+(?P<tail>{ORG})")
    return [(m.group("head"), "works_at", m.group("tail")) for m in pattern.finditer(text)]


persons, orgs = find_entities(TEXT)
triples = find_triples(TEXT)

print("人物:", persons)
print("机构:", orgs)
print("三元组:", triples)
assert ("Alice", "works_at", "Acme Corp") in triples
assert ("Bob", "works_at", "Acme Corp") in triples

两处写法值得注意：rf"...{'|'.join(PERSONS)}..." 把姓名集合拼成「或」模式，新增人名只改集合；命名分组 (?P...) 让取值按名字而不是按序号，模式调整时不容易错位。

这段代码的边界也很清楚：Beijing 虽是地名，却不在模式里，所以不会被抽出；works at 换一种说法（is employed by）就失效。规则抽取的精度来自「只抓确定的」，代价是召回有限。

05实测输出与字段对照

运行结果为：

text实测输出 · Python 3.13.14
人物: ['Alice', 'Bob']
机构: ['Acme Corp']
三元组: [('Alice', 'works_at', 'Acme Corp'), ('Bob', 'works_at', 'Acme Corp')]
字段本页取值校验方式缺失时
head 人物Alice / Bob必须在姓名集合内不输出该条
relationworks_at枚举限定不适用
tail 机构Acme Corp必须在机构模式内不输出该条
时间2020四位年份允许为空

注意 since 2020 没有被抽成字段：模式里没有定义它。这不是遗漏，而是「先定字段」的直接结果——没定义的字段，宁可空着，也不要抓一段来路不明的文本。

06加一个「位于」模式

任务：在现有代码上增加关系 located_in，抽取「X is located in Y」与「X in Y」两种写法，并回答下面三问。

python练习：新增模式
pattern = re.compile(r"(?P<head>[A-Z][a-z]+)\s+(?:is located in|in)\s+(?P<tail>[A-Z][a-z]+)")
print([(m["head"], "located_in", m["tail"]) for m in pattern.finditer(TEXT)])

追问：① 这个模式会把 Alice works at Acme Corp in Beijing 里的哪一段误抽出来？② 如果同一机构有简称与全称，应该在抽取前还是抽取后归一？③ 规则抽取的召回上不去时，下一步补规则还是换模型？

验收：新增模式能跑通，能指出至少一处误抽，并给出「先归一再入库」的具体做法。

注：本页代码与「实测输出」的运行口径为 Python 3.13.14（Windows），结果来自本机实际运行，可直接复现。
