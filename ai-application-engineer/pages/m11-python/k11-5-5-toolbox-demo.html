Toolbox 数据的特点及使用方法

一批上世纪九十年代的田野词表还躺在硬盘里，格式是反斜杠开头的纯文本。它没有 schema，却有一套稳定到今天的字段约定；解析它，比等它消失现实得多。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出 Standard Format 的记录与字段组织方式。
  2. 能把 \ref、\tx、\ge 等标记映射到结构化字段。
  3. 能写出一个容忍空行、缺字段与重复标记的解析器。

01一份只能人读的词表

拿到的文件长这样，记事本能打开，Excel 打不开：

textlexicon.txt
\ref demo-1
\ps N
\tx càt
\ge cat

\ref demo-2
\ps V
\tx rùn
\ge run
特点 A

反斜杠就是字段名

\tx 是原文，\ge 是英文释义，含义靠标记约定，不靠位置。

特点 B

空行分隔记录

空行不是排版，是记录边界；多一个空行就会切出一条空记录。

没有表头、没有 schema，程序怎么知道每行的意思？

靠字段说明表：同一套标记在项目内含义固定，解析器把标记当键、把值当内容。

02格式会过时，结构不会

Toolbox 的前身是 Shoebox，后来有 FLEx，未来还会有别的工具；但「一条记录由若干字段组成」这个结构一直没变。

直觉结论

迁移的核心不是写解析器，而是证明字段没有丢：映射表逐项对照，缺一个字段就是一次静默的数据损失。

03Standard Format 与常见标记

标记含义本页示例
\ref记录标识demo-1
\tx待分析语言文本càt
\ge英文释义（gloss）cat
\ps词性N
\lx词条（lexeme）常与 \tx 并用

Standard Format 的五条特点：纯文本、标记驱动、空行分隔记录、同一标记可重复出现、旧数据常带遗留字体编码。最后一条最麻烦：早期用自定义字体录入，字节对应的不是 Unicode 码位，迁移时需要映射表与人工校对。

重复标记会被字典覆盖

一个词条可能有多个义项、多个 \ge。用 dict 直接存会只剩最后一个；生产解析器应把值存成列表。

04按空行切记录，按首个空格切字段

只用标准库（pathlib、tempfile），Python 3.13.14 直接运行，无第三方依赖：

pythontoolbox_demo.py
"""最小可运行示例：解析 Toolbox Standard Format 记录（仅标准库）。"""
import tempfile
from pathlib import Path

SF = r"""\ref demo-1
\ps N
\tx càt
\ge cat

\ref demo-2
\ps V
\tx rùn
\ge run

\ref demo-3
\ps N
\tx dɔg
\ge dog
"""


def parse_sf(text: str) -> list[dict[str, str]]:
    """按空行切记录，按首个空格切标记与值。"""
    records: list[dict[str, str]] = []
    current: dict[str, str] = {}
    for line in text.splitlines():
        line = line.strip()
        if not line:
            if current:
                records.append(current)
                current = {}
            continue
        marker, _, value = line.partition(" ")
        current[marker] = value.strip()
    if current:
        records.append(current)
    return records


with tempfile.TemporaryDirectory() as tmp:
    path = Path(tmp) / "lexicon.txt"
    path.write_text(SF, encoding="utf-8")
    records = parse_sf(path.read_text(encoding="utf-8"))

for rec in records:
    print(rec["\\ref"], rec["\\tx"], "→", rec["\\ge"])
print("记录数:", len(records))
assert len(records) == 3
assert records[0]["\\ge"] == "cat"
assert records[1]["\\tx"] == "rùn"

三处关键写法：SF = r"..." 用原始字符串，否则 \t 会被当成制表符；line.partition(" ") 只按第一个空格切，值里允许再有空格；循环结束后还要补一次 if current，否则文件末尾没有空行时最后一条记录会丢。

05实测输出与读数

在 Python 3.13.14 下运行：

text实测输出 · Python 3.13.14
demo-1 càt → cat
demo-2 rùn → run
demo-3 dɔg → dog
记录数: 3
读数 1

三条记录都在

末尾没有空行，靠循环外的兜底把最后一条收进来；这是最容易漏的一条。

读数 2

带附加符号的字符完好

càt、rùn、dɔg 原样输出，UTF-8 往返没有损失。

读数 3

映射是单向的

\tx 对应原文、\ge 对应释义；方向反了就是另一套语料，转换前必须核对字段表。

教学简化

示例假定每个记录只有一个 \ps。真实词条可有多个义项，需要把值存为列表并保留顺序；复杂嵌套建议迁移到 XML 或 FLEx。

06从 SF 到结构化数据

任务：把解析结果导出为 JSONL，每行一条记录，并补一个字段覆盖检查。

多值字段把 parse_sf 的值改成 list[str]，同一标记重复出现时追加而不覆盖。
字段覆盖统计每条记录出现过的标记，找出缺少 \ge 的记录。
导出与回读写 lexicon.jsonl，逐行解析后断言条数与原文一致。

追问：① 为什么说「迁移的难点是映射表而不是解析器」？② 什么情况下应该放弃 SF、改存 XML？

验收：多值字段不丢；缺字段的记录能被报出来；导出回读条数一致。

格式对照与后续处理可继续看XML 的使用方法与语料库的结构；文本抽取与实体标注的完整管线见模块七 · 知识图谱，本页不重复实现。

注：本页代码与「实测输出」的运行口径为 Python 3.13.14（Windows），结果来自本机实际运行，可直接复现。
