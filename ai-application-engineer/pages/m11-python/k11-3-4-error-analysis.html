准确率、混淆矩阵与误差分析

准确率 90% 听起来不错，但如果九成样本都是负类，全判负也能拿到 90%。分类评估的第一步，是把那一个数拆回四个格子。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能画出二分类混淆矩阵，并读出 TP、FN、FP、TN。
  2. 能计算精确率、召回率与 F1，并说明各自适用场景。
  3. 能按错误类型归类错例，提出下一步改动。

0190% 的两种含义

两个模型都报告准确率 90%：

模型 A

全判负

测试集 100 条，正类只有 10 条；模型把所有样本判为负类，准确率正好 90%，但一个正例都没抓到。

模型 B

真正区分

正类 10 条抓到 8 条，负类 90 条误报 2 条；准确率仍是 90% 左右，但召回与精确都能单独看。

同一个数字，为什么一个可用、一个不可用？

因为准确率把四格压成了一格；类别不平衡时，多数类会掩盖少数类的失败。

02体检的漏诊与误诊

筛查疾病时，两种错误代价不同：漏诊（有病判没病）可能延误治疗，误诊（没病判有病）多做一次复查。只看「判对多少人」看不出这两种错误的比例。

直觉结论

指标不是越高越好，而是要与错误代价匹配；先确定「哪种错更不能接受」，再选指标。

03四格、三率、一个调和平均

指标公式回答什么
准确率(TP+TN) / 全部整体判对多少
精确率 PTP / (TP+FP)判为正的里面，有多少真的是正
召回率 RTP / (TP+FN)真正的正例，抓回来多少
F12PR / (P+R)P 与 R 的调和平均

P 与 R 通常此消彼长：把判定阈值调低，召回升、精确降；调高则相反。F1 用调和平均而不是算术平均，是因为它对较小的一项更敏感——一项接近 0 时，F1 也会被拉低。

多分类时，每个类别都能算一组 P/R/F1，再按宏平均或微平均汇总；报告指标必须注明平均方式，否则数字不可比。

04不调库，手算一遍

下面这段用标准库把四个格子和三个指标算出来，保存为 metrics.py：

pythonmetrics.py
y_true = ["spam", "spam", "spam", "ham", "ham", "ham", "ham", "ham", "spam", "ham"]
y_pred = ["spam", "spam", "ham", "spam", "ham", "ham", "ham", "ham", "spam", "ham"]

tp = sum(t == "spam" and p == "spam" for t, p in zip(y_true, y_pred))
fn = sum(t == "spam" and p != "spam" for t, p in zip(y_true, y_pred))
fp = sum(t != "spam" and p == "spam" for t, p in zip(y_true, y_pred))
tn = sum(t != "spam" and p != "spam" for t, p in zip(y_true, y_pred))

print("TP/FN/FP/TN:", tp, fn, fp, tn)
print("准确率:", (tp + tn) / len(y_true))
print("精确率:", tp / (tp + fp))
print("召回率:", tp / (tp + fn))
print("F1:", 2 * tp / (2 * tp + fp + fn))

四个 sum 就是混淆矩阵的展开写法：每个样本只落进一个格子。真实项目里用 scikit-learn 的 confusion_matrix 与 classification_report 即可，见模块四 · 模型评估；手写一次是为了看清每个指标的分子分母。

05实测输出与错例归因

运行结果为：

text实测输出 · Python 3.13.14
TP/FN/FP/TN: 3 1 1 5
准确率: 0.8
精确率: 0.75
召回率: 0.75
F1: 0.75
错例类型可能原因下一步
第 3 条：真实 spam，判 ham漏报 FN短信较短，缺少关键词补短文本特征或 n-gram
第 4 条：真实 ham，判 spam误报 FP含「中奖」但语境是通知加否定与上下文规则

准确率 0.8 与 F1 0.75 的差距来自那一个漏报：正类样本少，漏掉一条就明显拉低召回。误差分析的价值不在于再算一个总分，而在于把错例按原因归类，判断下一轮该改特征、改标签，还是改阈值。
