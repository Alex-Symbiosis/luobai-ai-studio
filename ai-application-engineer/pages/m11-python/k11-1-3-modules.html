函数、类与模块：把脚本变成工程

一个 500 行的脚本，改一处崩三处，通常不是水平问题，而是边界问题：步骤、状态、职责全缠在同一个文件里。拆开它们，靠的不是设计模式，而是三种最朴素的封装。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说清函数封装步骤、类封装状态、模块封装职责各自解决什么问题。
  2. 能按「先分步骤、再分状态、最后分职责」的顺序重构脚本。
  3. 能写出带主入口保护、可被导入而不产生副作用的最小模块。

01改一行，崩三处

同一个文本统计脚本，两种组织方式：

做法 A

一路写到底

读文件、清洗、分词、计数、打印全在顶层；改清洗规则要翻 200 行，测试只能整段跑，别人 import 这个文件还会顺带打印一堆东西。

做法 B

先分步骤，再分状态

清洗、分词、计数各是一个函数；需要跨步骤保留的配置与计数结果放进一个类；对外只暴露一个模块级函数。改规则只动一个函数，测试可以逐段做。

同样的功能，为什么 B 改起来更安全？

因为 B 把「变化点」收进了明确的边界：函数管输入输出，类管状态，模块管对外职责。

02工具箱分格

木工箱不会把所有钉子倒在一起：一格放螺丝、一格放钻头、一格放量具。找的时候按格找，补货也按格补。

直觉结论

封装不是把代码变短，而是让「改这里不会影响那里」成为可验证的事实。

03四层结构，一条依赖方向

单位封装什么判断标准
函数一段步骤：输入 → 输出能否用一句话说清它做什么
类一组状态与操作多个函数是否共享同一批数据
模块一个 .py 文件能否被导入而不产生副作用
包含 __init__.py 的目录对外接口是否收敛在 __init__

依赖方向要单向：模块可以导入函数与类，函数不应回头导入模块；底层工具不依赖上层业务。方向一旦成环，任何一处修改都会牵动全局，重构就失去了意义。

主入口保护

if __name__ == "__main__": 区分「被直接运行」与「被导入」。没有它，别人一 import 就会执行你的测试代码与打印语句。

04一个可导入的最小模块

下面这段把「词与标注」建模成两个类，并提供纯函数与主入口；存为 tagger.py：

pythontagger.py
"""最小可运行示例：类型注解 + dataclass + 主入口保护（Python 3.10+）。"""
from __future__ import annotations

from dataclasses import dataclass, field


@dataclass
class Token:
    text: str
    tag: str = "UNK"


@dataclass
class Sentence:
    tokens: list[Token] = field(default_factory=list)

    def render(self) -> str:
        return " ".join(f"{t.text}/{t.tag}" for t in self.tokens)


def tag_naive(text: str) -> Sentence:
    """按空格切分，长度大于 6 的词标 LONG，其余标 SHORT。"""
    sent = Sentence()
    for word in text.split():
        sent.tokens.append(Token(word, "LONG" if len(word) > 6 else "SHORT"))
    return sent


def main() -> None:
    demo = tag_naive("Python natural language processing")
    print(demo.render())
    assert demo.tokens[0].text == "Python"


if __name__ == "__main__":
    main()

拆开看三层职责：Token 与 Sentence 只保存状态与渲染；tag_naive 只做「文本 → Sentence」的转换；main 只负责演示。导入 tagger 时不会打印任何东西，因为打印被主入口保护挡住了。

运行方式与普通脚本一致：python tagger.py。在别的文件里则写 from tagger import tag_naive，只取函数，不触发演示。

05实测输出与拆分记录

运行 python tagger.py，Python 3.13.14 下的输出为：

text实测输出 · Python 3.13.14
Python/SHORT natural/LONG language/LONG processing/LONG
读数 1

SHORT 只出现一次

Python 长度 6，不满足「大于 6」，所以标 SHORT；边界写错一位，标签就会全变。

读数 2

渲染即接口

render() 把内部结构转成字符串；外部只依赖这个方法，不必知道 tokens 怎么存。

读数 3

断言在跑

assert 验证第一个词没被切错；它随脚本一起运行，是成本最低的回归测试。

把这段脚本拆成模块时，推荐顺序是：先抽函数（不改逻辑），再把共享状态收进类（不改行为），最后按职责分文件（不改接口）。每一步都能单独运行、单独回滚。

06把 100 行脚本拆成 3 + 1 + 2

任务：找一段自己写过的、超过 100 行的脚本，按下面结构重构，并记录每一步的验证方式。

产出数量验收
纯函数3 个每个函数只做一件事，输入输出都有类型注解
类1 个至少两个函数共享它的状态，否则不需要类
模块2 个导入任一个都不打印、不读文件、不发请求

追问：① 如果一个「类」只有一个方法、没有共享状态，它应该是什么？② 两个模块互相 import 会发生什么，怎么拆掉这个环？

验收：重构前后对同一输入输出一致；python -c "import 模块名" 无任何输出。
