基于特征的文法规则

纯 CFG 能推出「the cat run」——结构完全合法，只是英语不这么说。缺的不是结构规则，而是「主语和谓语在人称、数上必须一致」这类约束。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出一个特征结构，并说明键与值的含义。
  2. 能按「不重叠则合并、同值则通过、异值则失败」执行合一。
  3. 能解释特征文法与纯 CFG 的分工。

01结构对，句子却不对

同一套 CFG，两句话的推导都成立：

合法

the cat runs

NP 是单数第三人称，VP 也是单数第三人称；结构与特征同时对上。

不合法

the cat run

结构仍是 NP + VP，纯 CFG 照推不误；但主语单数、谓语却是复数形式。

文法规则一条没少，为什么错句也能推导出来？

因为纯 CFG 只看语法类，不看语法类携带的属性；一致性约束没有地方可写。

02钥匙与锁的齿形

钥匙能插进锁孔，不等于能转动；齿形对不上，结构再合适也打不开。特征是齿形，结构是孔的形状。

直觉结论

特征文法 = 结构规则 + 属性约束；合一失败，就剪掉这条组合。

03特征结构与合一

概念含义例子
特征结构属性—值对的集合{num: sg, pers: 3}
合一合并两个结构，冲突则失败{num: sg} ⊕ {num: pl} → 失败
主谓一致主语与谓语在人称、数上匹配cat runs / cats run
子类框架动词对论元数量与类型的要求put 需要三个论元

合一有三条规则：属性不重叠，直接并入；属性相同且值相同，保留；属性相同但值不同，整体失败。嵌套结构递归执行同样的规则。它是单调的——只增加信息，不改写已有值，所以失败可以立即剪枝，不必等到整句分析完。

与纯 CFG 的分工

CFG 负责「哪些成分能组合」，特征负责「组合后属性能否相容」；两者叠加，才既描述结构又排除错句。

04二十行合一函数

下面这段用字典模拟特征结构，只依赖标准库：

pythonunify_demo.py
"""最小可运行示例：特征结构合一，检查主谓一致（仅标准库）。"""
from typing import Optional


def unify(a: dict, b: dict) -> Optional[dict]:
    """递归合一二个特征结构；冲突返回 None。"""
    result = dict(a)
    for key, value in b.items():
        if key in result:
            if isinstance(result[key], dict) and isinstance(value, dict):
                merged = unify(result[key], value)
                if merged is None:
                    return None
                result[key] = merged
            elif result[key] != value:
                return None
        else:
            result[key] = value
    return result


SUBJ = {
    "cat": {"num": "sg", "pers": "3"},
    "cats": {"num": "pl", "pers": "3"},
    "I": {"num": "sg", "pers": "1"},
}
VERB = {
    "runs": {"num": "sg", "pers": "3"},
    "run": {"num": "pl", "pers": "3"},
    "am": {"num": "sg", "pers": "1"},
}


def agree(subject: str, verb: str) -> bool:
    return unify(SUBJ[subject], VERB[verb]) is not None


pairs = [("cat", "runs"), ("cats", "run"), ("cat", "run"), ("I", "am")]
for s, v in pairs:
    print(f"{s} {v}: {'OK' if agree(s, v) else 'FAIL'}")
assert agree("cat", "runs") and agree("cats", "run") and agree("I", "am")
assert not agree("cat", "run")

unify 先复制左侧，再逐键并入右侧：遇到嵌套字典就递归，遇到同键异值就立刻返回 None。复制这一步不能省，否则合并会修改传入的原始特征结构，后续判断全被污染。

05实测输出与判定表

运行结果为：

I am: OK
主语谓语numpers结果
catrunssg = sg3 = 3OK

catrunsg ≠ pl3 = 3FAIL

失败只由 num 一票决定，pers 相同也救不回来；这就是合一的「一票否决」。真实文法会继续往上叠加格、时态、子类框架，但判定逻辑不变。

06补三组特征，看谁失败

任务：在 SUBJ 与 VERB 里补充 they / run、he / run、we / are，先预测结果再运行。

句对numpers预测
they run
he run
we are

追问：① 为什么 unify 要先 dict(a) 复制？② 如果要表达「动词需要宾语」，特征该加在哪一层？

验收：三组判定与特征表一致，并能指出「结构合法但特征失败」的具体一格。
