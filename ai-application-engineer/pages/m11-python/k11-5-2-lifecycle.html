语料库的生命周期

语料库不是发布那天就完事的文件包。链接会失效、格式会过时、许可会到期；没有生命周期管理，三年后的实验就复现不出来。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出语料库生命周期的七个阶段及各自的交付物。
  2. 能解释校验和解决的是「信任」问题，而不是「保密」问题。
  3. 能用标准库生成 manifest 并检测文件变更。

01论文里的数据取不到了

复现一篇三年前的论文，需要它用的语料。按论文写的链接打开：

现状 A

链接 404

作者个人主页已改版，数据没有镜像；论文只写了「公开可用」，没说版本号与哈希。

现状 B

拿到的和当初不一样

数据还在，但作者做过一次纠错，文件被覆盖；没有变更日志，也说不清差在哪。

这两种情况，缺的是同一件东西吗？

不是。前者缺长期托管与退役说明，后者缺版本与完整性校验；两者都属于生命周期管理。

02发布不是终点

软件有版本号、发布说明与缺陷跟踪；语料库是同样的长期资产，只是很多人只做了「上传」这一步。

直觉结论

生命周期管理的目标只有一句话：让三年后的自己（或别人）能确认「拿到的就是当初那一份」。

03七个阶段与四件交付物

阶段主要活动交付物
规划明确任务、规模、许可、隐私数据说明书
采集抓取、授权获取、转写原始数据 + 来源记录
清洗去噪、去重、规范化清洗后语料 + 脚本
标注规范、双盲标注、仲裁标注层 + 一致性报告
发布版本号、清单、许可、文档发布包
维护修错、扩充、迁移格式新版本 + 变更日志
退役停止分发、删除敏感数据退役说明

四件交付物贯穿全程：版本号（主.次.修订）、变更日志（每版新增/修改/删除）、清单（文件 + 哈希 + 大小）、许可（每个样本可追溯）。校验和用哈希保证完整性，它防的是篡改与静默损坏，不是防泄露——那是加密要解决的问题。

04生成清单并检测变更

只用标准库（hashlib、json、pathlib），无需第三方依赖，Python 3.13.14 直接运行：

pythonmanifest_demo.py
"""最小可运行示例：生成 manifest 并校验文件完整性（仅标准库）。"""
import hashlib
import json
import tempfile
from pathlib import Path


def sha256(path: Path) -> str:
    digest = hashlib.sha256()
    with path.open("rb") as fh:
        for chunk in iter(lambda: fh.read(65536), b""):
            digest.update(chunk)
    return digest.hexdigest()


with tempfile.TemporaryDirectory() as tmp:
    root = Path(tmp)
    (root / "a.txt").write_text("hello corpus", encoding="utf-8")
    (root / "b.txt").write_text("second sample", encoding="utf-8")

    manifest = {p.name: sha256(p) for p in sorted(root.glob("*.txt"))}
    (root / "manifest.json").write_text(json.dumps(manifest, indent=2), encoding="utf-8")

    ok = all(sha256(root / name) == digest for name, digest in manifest.items())
    print("初次校验:", ok)

    (root / "a.txt").write_text("hello corpus!", encoding="utf-8")
    changed = [name for name, digest in manifest.items() if sha256(root / name) != digest]
    print("变更文件:", changed)
    assert ok and changed == ["a.txt"]

iter(lambda: fh.read(65536), b"") 是分块读取的惯用法：大文件不必一次读进内存。sorted(root.glob("*.txt")) 保证清单顺序稳定，否则同样的内容会生成不同的 JSON，失去可比性。

05实测输出与读数

在 Python 3.13.14 下运行：

text实测输出 · Python 3.13.14
初次校验: True
变更文件: ['a.txt']
读数 1

初次校验 True

刚生成的清单与文件一致，这是基线；校验的意义在于之后每次比对都有参照。

读数 2

只报出 a.txt

多了一个感叹号，哈希全变；b.txt 未动就不在变更列表里，说明校验能定位到文件级。

读数 3

改一个字符也算变

哈希对输入极其敏感，这正是它能发现静默损坏的原因。

校验和不等于签名

清单只能证明「文件与清单一致」；清单本身若被替换，校验就失效。防抵赖场景需要数字签名或可信时间戳。

06把清单变成发布流程

任务：在示例基础上补三件事，形成一个最小发布脚本。

加元信息清单里除哈希外，再记录每个文件的字节数与 UTF-8 行数。
加版本号用 version.txt 写 1.0.0，并把它自身也纳入清单。
加变更日志每次检测到变更，向 CHANGELOG.md 追加一行日期、文件名与旧新哈希前 8 位。

追问：① 为什么清单要连同版本号一起发布？② 什么情况下应该「退役」而不是「维护」？

验收：脚本重复运行结果稳定；能说清哈希、加密、签名三者的区别。

注：本页代码与「实测输出」的运行口径为 Python 3.13.14（Windows），结果来自本机实际运行，可直接复现。
