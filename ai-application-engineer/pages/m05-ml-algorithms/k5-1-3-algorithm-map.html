算法地图：先按任务定位

一张按难度排序的算法清单，看着整齐，用起来没用。因为选型不是「从简单的开始试」，而是「先确定自己在哪一类任务上，再看附近有谁」。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出算法地图的三条轴以及各自的用途。
  2. 能按任务类型把代表算法放到地图上。
  3. 能用「相邻但不同」的方式比较同一区域的算法。

01清单贴在墙上，没人按它选型

团队墙上贴着一张「常用算法清单」，按学习难度从低到高排：线性回归、逻辑回归、KNN、决策树、SVM、随机森林……

半年后回看，这张清单只被用来应付面试，真正选型时一次也没用上：新需求来了，还是从清单第一个开始试；遇到客户分群这种没有标签的任务，清单上的分类算法一个也用不了。

一份按难度排好的清单，为什么在真实需求面前帮不上忙？

因为它只有一根轴。难度能决定「先学哪个」，却回答不了「这个任务该往哪个方向找」。选型需要的是坐标，不是排名。

02先量任务，再量算法

装修时不会先挑瓷砖再看户型：先确认是厨房还是卫生间，再决定防水、防滑这些硬条件，最后才比较花色。

直觉结论

地图的价值在于「先定位、再比较」。位置错了，后面比的分数再精细也没有意义。

03三条轴，各管一件事

轴取值决定什么
任务类型回归 / 分类 / 聚类 / 降维输出形式、损失与评价指标
数据形态小到中 / 中到高；稠密 / 稀疏算法能否吃得下、要不要先降维
可解释性高 / 中 / 低能否进入强监管、需审批的场景

图上把「数据形态」落到「典型数据规模」这个刻度上，是为了让位置可比；真正的判断仍要看稀疏性与特征类型。可解释性一轴最容易被忽略，却常常是最先淘汰候选的硬条件。

同一算法可以出现在多个任务上：CART 既做分类也做回归，LDA 既能分类也能降维。地图上的一个点，往往代表「某算法的一个用法」，而不是算法的全部。

04定位、收窄、比较

用地图选型是三步，不是一步：

定位先按任务类型确定纵轴位置。无标签的任务直接落在聚类或降维，不必再看分类算法。
收窄用数据规模与可解释性切掉不合条件的点。强监管场景里，低可解释性的模型先出局。
比较只在剩下的邻域里比分数、比训练成本、比上线难度。此时比较才有可比性。

「邻域」是这张图最有用的部分：相邻的两个点往往只差一个假设。逻辑回归与线性 SVM 都是线性分类器，差别在损失与是否输出概率；决策树与回归树结构相同，差别在叶子输出；LDA 与 PCA 都在做投影，差别在要不要用标签。看清这一层差异，比记住十个算法名字更管用。

05违约预测：同一任务的三个候选

任务：预测客户是否违约。三个候选都落在地图的分类区，但位置不同：

候选可解释性非线性样本需求典型用途
逻辑回归高弱，需要造特征中等评分卡、合规场景
决策树高中，轴对齐切分中等规则交付、人工复核
随机森林低强较大容忍黑箱的排序场景

如果业务要求每条拒绝理由都能向客户解释，第三个候选在第一轮就被排除；如果只要求在同等成本下尽可能多抓坏人，前两个候选又可能不够。地图不能替你拍板，但能保证你是在一个合理的候选集里拍板。

06画地图，标算法，写三组对比

任务：在一张二维图上放 12 个算法，并写出三组「相邻但不同」的对比。

  1. 纵轴取任务类型，横轴取可解释性；数据规模用点的标注说明。
  2. 每个点旁写一句「为什么放在这里」，不许只写名字。
  3. 选三对相邻算法，各写「差在哪个假设、换来的代价是什么」。
验收

位置必须有依据，且能解释「同区域的算法为什么还不能互相替代」。只把名字摆满图，不算完成。

注：本页涉及的数值均为教学示意，用于说明机制，非真实实验记录。
