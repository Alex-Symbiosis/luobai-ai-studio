知识图谱：用三元组把知识变成图

知识的最小单位不是文档，也不是表行，而是一条「实体—关系—实体」。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出实体、关系、三元组与 URI，并说清四者的关系。
  2. 能把一句业务文本拆成若干条三元组，再连成一张小图。
  3. 能判断一个问题适不适合用图查，而不是只凭「图很火」。

01三跳的追问

周一的投研会上，分析师连着问了三句：星海科技的实际控制人是谁？它和云图数据是什么关系？云图数据的大股东还投了哪些同行？

数据都在系统里：工商登记表、股权表、企业主表，一张不少。可第一问要关联两张表，第二问再关联一次，第三问得先查出「云图数据的大股东」，再回股权表反查。写查询的人一边加 JOIN 一边改条件，问到第四层就没人愿意接了。

换成图来看，这三问只是同一张图上不同起点、不同步数的走法。星海科技连着陈明，也连着云图数据；云图数据连着数聚信息；数聚信息又连着另外两家云计算公司。三句话，其实是一条链。

同样的事实，为什么换成表就要重写查询，换成图只是多走一步？

02句子拆开就是图

把一句话拆成「谁—做什么—对谁」，剩下的部分就是节点和边。拆完再连起来，文本和图就对上了。

直觉结论

判断一段知识适不适合上图，只看一句：问题的答案是不是「一条路径」。

03主谓宾与标识

三元组写作（主语, 谓语, 宾语），对应一句陈述的主谓宾。主语和宾语通常是实体，谓语是关系；实体用 URI 唯一标识，而不是用名字。

主语谓语宾语读法
ex:company/xinghai收购ex:company/yuntu星海科技收购云图数据
ex:company/yuntu主营ex:industry/cloud云图数据做云计算
ex:person/chenming创始人ex:company/xinghai陈明创办了星海科技

为什么必须用 URI：全国叫「星海科技」的公司不止一家，名字只是标签，会重名、会改名、会有全称与简称。URI 一旦定下就不随文本变化，同名不同实体、同实体不同写法，都靠它区分和合并。

易错点

把「星海科技以 2.1 亿元收购云图数据 35% 股权」压成一条三元组，金额和比例就没地方放了。二元关系只能表达「有/没有」：带数值的事件要么挂在边上的属性，要么抽成一个「收购事件」节点，再把金额、比例、日期连上去。

04多跳为什么难

关系型数据库不是存不下这些事实，问题是每多一跳就要多一次关联，而且跳数在写查询时就得定死。

三张表、每张十万行的库，问「三跳以内谁和星海科技相连」，SQL 要写三次 JOIN，第四次关联还得先落一张临时表；问到第五跳，语句已经没人敢改。图上的做法是：从起点出发，按关系类型一层层展开，走几层由参数决定，查询语句不变。

pythontwo_hops.py
triples = [
    ("星海科技", "收购", "云图数据"),
    ("云图数据", "主营", "云计算"),
    ("陈明", "创始人", "星海科技"),
]

adj = {}
for s, p, o in triples:
    adj.setdefault(s, []).append((p, o))
    adj.setdefault(o, []).append((p, s))     # 先按无向走

def two_hops(start):
    paths = []
    for p1, mid in adj.get(start, []):
        for p2, end in adj.get(mid, []):
            if end != start:
                paths.append((start, p1, mid, p2, end))
    return paths

print(two_hops("星海科技"))

这段代码只做一件事：把「跳」写成循环，而不是写死在查询里。想走三层，就多套一层循环；想限定关系，就在循环里加一个判断。

代价也要说清：图的优势在「关系本身要参与计算」。如果只是按行业分组计数，表一次 GROUP BY 就完了，硬上图反而更慢。

05六条三元组

回到会上那三问。把企业主表、股权表、人名对齐后，只需要六条三元组：星海科技—收购—云图数据，星海科技—总部—杭州，星海科技—CEO—陈明，云图数据—主营—云计算，云图数据—股东—数聚信息，数聚信息—股东—冯雪。

第一问一跳命中陈明，第二问一跳命中「收购」，第三问从云图数据出发两跳，拿到数聚信息。六个实体、六条边，三个问题全部落地。

换成表结构，同样的答案要写三段 SQL，每段都得改一次 JOIN 条件，而且第三段的跳数一旦从两跳变三跳，查询就要重写。图的价值不在「存得更多」，而在问题变深时，查询不必重写。

06拆一句公告

任务：把「星海科技以 2.1 亿元收购云图数据 35% 股权，后者主营云计算」拆成三元组，至少 4 条。

要求：标出哪一部分放不进二元关系，并给出两种补救方案：一种把数值挂在边上，一种把事件抽成节点。验收标准是——金额、比例、日期三项都有明确落点，且能回答「谁收购谁、占多少」。

追问：如果云图数据后来改名「云图智能」，哪一层要改？正确答案是只改名称标签，URI 不动；这正是不用名字做标识的原因。接着看 数据层与模式层，把词表定下来。
