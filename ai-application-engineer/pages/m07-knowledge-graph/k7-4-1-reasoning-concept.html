推理：从已知事实推出未知事实

图里只有 parent，用户问的却是祖孙：推理就是把规则没说出口的那半边写出来。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说清事实与规则的分工，并各举一个例子。
  2. 能用一个 parent→ancestor 的例子说明推理在做什么。
  3. 能说明推理结果为什么要写回图谱并标注来源。

01答案不在图里

校园图谱上线两周，76 个实体、150 条关系，点开每位教师能看到「讲授」和「属于」。有人问：张伟带过的学生里，谁后来选了王芳的课？系统答不出来。

不是数据脏，也不是查询写错：图里没有「师徒」这条边，而这个问题要的正是图上不存在的连接。

家族图谱更小也更干净：只存 parent 与 spouse 两类边。问「张伟的孙辈有谁」，图里同样没有 ancestor 边——可答案按常识是确定的。

图里没写的关系，凭什么能答？

凭的是传递性：张伟是张强的父亲，张强是张小雨的父亲，那么张伟就是张小雨的祖父。这个「那么」不需要新数据，只需要把两条已有事实按规则接起来。

02两类东西

图里有两类东西，性质完全不同。

事实是已经断言的三元组，比如 (张强, parent, 张小雨)。它对不对另说，但它写在库里，有出处。

规则是模式，比如「若 x 是 y 的父或母，且 y 是 z 的父或母，则 x 是 z 的祖先」。规则里没有具体人名，只描述什么样的组合能推出什么。

一句话：推理就是拿规则去扫事实，把 parent 的传递性展开成 ancestor。图里没有 ancestor 边，不等于「不是祖孙」；规则能推出来，它就是祖孙。反过来说，规则没写，推理也不会凭空长出一条边。

直觉结论

事实回答「已经知道什么」，规则回答「知道这些之后还能知道什么」。推理的输出既不是新观测，也不是猜测，而是前提里本来就隐含、只是没写出来的那部分。

03三个部件

定义：给定事实集 F 与规则集 R，从 F 出发反复应用 R，直到再应用不产生新事实，得到的集合 F* 称为 F 在 R 下的闭包。F* 满足两条：包含原来的 F；在 R 下封闭。

部件装什么作用
事实库三元组集合已经断言的边
规则库若…则…的模式允许怎样组合推出什么
推理机匹配与执行一轮轮产出新事实

两种落地方式。物化：推理结果直接写成新边存进库，查询时和普通边一样快，代价是占空间、源数据一变就要重算。查询时推理：不存结果，查询时按规则现算，省空间，但每次查询都要付匹配成本。家族图谱这种小图适合物化，更新频繁的大图常常混用。

还要分清推理和检索：检索是从已有事实里挑出符合条件的，推理是生成原先不存在的事实。

04绑定与写回

一次规则应用只有五个动作。

① 取出候选事实。② 变量绑定：把规则里的 x、y、z 对齐到具体实体。③ 逐条检查前提是否都在事实库里。④ 生成结论。⑤ 去重后写回。

以 R1 为例：扫到 (张伟, parent, 张强) 和 (张强, parent, 张小雨)，x 绑张伟、y 绑张强、z 绑张小雨。前提全部满足，产出 (张伟, ancestor, 张小雨)。

绑定是核心动作：同一个变量在一次匹配里只能取一个值。y 在前一条里是宾语、后一条里是主语，两边必须是同一个人，规则才成立——这一步叫连接，也是推理里唯一需要「对齐」的地方。

写回不能只写一条边。至少要带三样：规则编号、用了哪几条前提、生成时间。没有这三样，三个月后就分不清这条边是抽取来的、人工录的，还是推出来的；出错时也没法顺着规则回滚。

最常见的误读

把推理当「发现新知识」。推理不产生新观测，结论的信息量不超过前提之和。它真正省下的是人工写查询和人工补边的成本。

05一条边省一次连接

取一个最小的家谱：甲是乙的父亲，乙是丙的父亲，丙是丁的父亲，共 3 条 parent 事实。

问题不推理怎么写推理后怎么写
甲的后代有谁两跳模板 UNION 三跳模板，链一变长就改代码一条 ancestor 边查完
丙和丁是什么关系分别查 parent 与 ancestor 再拼直接查 ancestor

按 R1 两两相接，3 条 parent 事实能多出 2 条 ancestor（甲→丙、乙→丁）。链再长，闭包按平方级增长：12 个人排成一条直链，11 条 parent 边，能推出 66 条 ancestor 边。

收益能数出来，代价也能数出来：事实从 11 条涨到 77 条，每条都要存来源；一次人事调整，闭包要局部重算；万一有一条 parent 录错，错误会顺着链传进这 66 条里的一大半。

06先手推再上机

任务：给 5 个人、两代以内的家谱写 5 条事实（parent 与 spouse 都可），手工推出闭包，填一张表：新增了几条、每条来自哪条规则。

追问：① 库里怎么区分「抽取来的边」和「推出来的边」？② 只推一跳够不够，为什么？③ 「没推出 ancestor」能不能当成「不是祖孙」？

验收：能说清事实与规则各管什么；能写出 1 条规则并手工完成一次变量绑定；知道结论要落库、要带来源。规则怎么写才不漏，见 演绎推理：规则引擎与传递闭包。

注：本页示例只用 Python 标准库，运行口径为 Python 3.13.14（Windows 原生 CPU），输出为本机实测，可直接复现。本页对应知识库条目均已建库（filled，2026-11-19），正文按条目口径与大纲要求撰写。
