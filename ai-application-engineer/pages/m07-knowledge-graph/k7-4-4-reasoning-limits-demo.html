推理的边界：不一致、开放世界与规则维护

闭包跑通了不等于对了：一条反向边，能让一个人成为自己的祖先。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能识别不一致、开放世界、规则维护三类边界，并给出处置。
  2. 能读懂闭包输出，判断自环是错误信号而不是正常结论。
  3. 能说明规则变更为什么必须带版本与回滚点。

01自己的祖先

家族页上线第三天，有人点开张小雨的档案，「祖先」一栏里出现了她自己。

前端没问题，图形渲染也没问题。库里有一条 parent(张小雨, 张强)，与另一条 parent(张强, 张小雨) 互为反向——两条边来自两个不同的数据源，抽取时都通过了格式校验。规则一跑，环就闭合了。

这个案例的全部读数：10 个实体，9 条初始事实（8 条基础 + 1 条冲突来源），3 条规则，迭代 2 轮，新增 7 条，闭包 16 条。错误只有 1 条，错误结论却有 3 条。

推理本身没有算错，错的是它默认了「前提都对、规则都对」。这两个假设在真实图谱里都不成立。

02三类边界

问题不是「推理算错了」，是三类边界叠在一起。

第一类，不一致：两条边互相矛盾，而事实库没有机制发现它。第二类，开放世界：库里没有「张小雨的另一位父亲」，不等于她只有一位；把「没写」当「没有」，就会把缺失当成确定。第三类，规则维护：R1 没禁止自反，规则本身也没写「x 与 z 不能是同一个人」。

三类边界对应三种动作：不一致要检测，开放世界要改口径，规则维护要上流程。三者都不属于「把规则写对」这一层，写对规则只解决第四类问题。

03边界如何界定

不一致：同一实体上出现互斥断言。父子互指、出生年 1980 与 1995 并存、总部同时在北京和上海。逻辑上，两条都为真时模型无解，必须有一条被撤回或标注存疑。

开放世界（OWA）：没写不等于假。图谱没写某人的出生地，不能推出「他没有出生地」，只能说「未知」。这与数据库的封闭世界口径相反：SQL 查不到就是不存在。

口径缺值的含义适合风险
开放世界未知知识图谱、多源融合查询返回空，容易被误读为「不存在」
封闭世界不存在业务库、清单核对漏录的数据被当成事实

规则维护：规则也是代码。要有版本号、要评审、要小流量对比、要回滚点。规则一改，闭包就要重算；重算前先留一份旧闭包，出问题才有得退。

04写成可跑的脚本

把三类边界落成一个可跑的脚本：8 条基础事实加 1 条冲突来源，3 条规则，前向链求闭包，最后做一次冲突检测。

pythond7_4_reason.py
# -*- coding: utf-8 -*-
"""Demo 7.4 推理与边界：8 条家庭事实 + 1 条冲突来源，规则前向链求闭包，
观察推理如何放大错误。"""
import sys

sys.stdout.reconfigure(encoding="utf-8")

# 8 条基础事实 + 1 条来源 B 的错误事实（张小雨 是 张强 的 parent）
BASE = [
    ("parent", "张伟", "张强"),
    ("parent", "李娜", "张强"),
    ("parent", "张强", "张小雨"),
    ("parent", "王芳", "张小雨"),
    ("spouse", "张伟", "李娜"),
    ("parent", "刘洋", "刘小川"),
    ("spouse", "刘洋", "陈静"),
    ("parent", "赵敏", "孙浩"),
]
CONFLICT = ("parent", "张小雨", "张强")

facts = set(BASE) | {CONFLICT}
initial_count = len(facts)

# R1 parent(x,y) ∧ parent(y,z) -> ancestor(x,z)
# R2 ancestor(x,y) ∧ ancestor(y,z) -> ancestor(x,z)
# R3 spouse(x,y) -> spouse(y,x)
rounds = 0
while True:
    new = set()
    parents = [(a, b) for r, a, b in facts if r == "parent"]
    ancestors = [(a, b) for r, a, b in facts if r == "ancestor"]
    for (x, y) in parents:
        for (y2, z) in parents:
            if y == y2:
                new.add(("ancestor", x, z))          # R1
    for (x, y) in ancestors:
        for (y2, z) in ancestors:
            if y == y2:
                new.add(("ancestor", x, z))          # R2
    for r, x, y in list(facts):
        if r == "spouse":
            new.add(("spouse", y, x))                # R3
    new -= facts
    rounds += 1
    if not new:
        break
    facts |= new

added = sorted(facts - (set(BASE) | {CONFLICT}))

print("实体数      :", len({x for _, a, b in facts for x in (a, b)}))
print("初始事实数  : %d（8 条基础事实 + 1 条冲突来源事实）" % initial_count)
print("规则数      : 3（R1 parent 两步→ancestor；R2 ancestor 传递；R3 spouse 对称）")
print("迭代轮数    : %d（最后一轮无新增后停止）" % rounds)
print("新增事实数  :", len(added))
print("闭包总数    :", len(facts))
print("新增事实清单（最多 12 条）")
for r, a, b in added[:12]:
    print("  %-8s(%s, %s)" % (r, a, b))

# 冲突检测：parent 互为反向
conflicts = []
pmap = {}
for r, a, b in facts:
    if r == "parent":
        pmap.setdefault(a, set()).add(b)
for a, bs in pmap.items():
    for b in bs:
        if a in pmap.get(b, set()) and a < b:
            conflicts.append((a, b))
print("冲突检测    :", end=" ")
if conflicts:
    a, b = conflicts[0]
    print("parent(%s, %s) 与 parent(%s, %s) 互为反向" % (a, b, b, a))
else:
    print("未发现")
print("冲突后果    : 推出 ancestor(%s, %s) 与 ancestor(%s, %s) 等自环"
      % (conflicts[0][0], conflicts[0][0], conflicts[0][1], conflicts[0][1]))
print("冲突放大    : 1 条错误边产生 3 条错误祖先结论（占新增祖先事实 3/5）")
print("处理标记    : 需人工裁决（保留冲突边，不自动删除）")
print("结论        : 推理会放大错误，闭包越大越需要来源追溯与人工裁决。")

两处设计值得看。第一，循环里先收集 new、最后统一 facts |= new，避免边扫边写导致同一轮重复匹配。第二，冲突检测单独走一遍，检查 parent 是否互为反向。它在脚本里排在写回之后，但在真实系统里必须挪到写回之前：先拦下，再决定要不要入库。

9 到 16。9 条初始事实，两轮迭代新增 7 条，闭包 16 条。新增的 7 条由 5 条 ancestor 和 2 条 spouse 对称边组成，数量对得上：没有凭空多，也没有漏。

自环是错误信号。ancestor(张小雨, 张小雨) 和 ancestor(张强, 张强) 不是「自己是自己的祖先」这种正常结论，而是环状错误边被规则放大后的产物。家谱是树，正常闭包里不该出现自环；一旦出现，先去查数据，不要去改规则。

3/5 的放大率。5 条新增祖先结论里，3 条由那一条错误边产生：两条自环，加上 ancestor(王芳, 张强)——王芳是张小雨的母亲，被错误地连到了张强身上。1 条错误边，污染了 60% 的新增结论。链再长一点，比例会更高。

不自动删。处理标记写的是「需人工裁决」，保留冲突边。两条边来自不同源，删哪条要看哪条有凭证；自动删等于把判断权交给了一条没写过来源的规则。

06三条边界各一问

现象属于处置
A 是 B 的父亲，B 也是 A 的父亲不一致挂冲突标记，回溯两个来源
查询某人的出生地返回空开放世界答「未知」，不要答「没有」
新规则上线后闭包少了一半规则维护对比新旧闭包，按版本回滚

追问：① 冲突检测为什么要跑在写回之前？② 开放世界下查询返回 0 条，怎么向业务方解释？③ 规则回滚要回滚规则、闭包，还是两者都回滚？

验收：能判断三种边界各属于哪一类；能解释自环为什么是错误信号；能说出回滚要回到哪个版本、回滚后谁重算。演绎怎么推，见 演绎推理：规则引擎与传递闭包；归纳怎么补边，见 归纳推理与图谱补全。
