演绎推理：规则引擎与传递闭包

演绎给的是必然：前提成立，结论跑不掉；前向链就是把这条「跑不掉」算到底。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出演绎推理与前向链、后向链各自的适用条件。
  2. 能写出 R1/R2/R3 三条最小规则，并说明每条解决什么问题。
  3. 能解释为什么迭代必须到不动点，并估算一轮的匹配成本。

01五跳写不出来

一家制造企业的供应链图谱，只有「供货」这一类边。风控要看某个零件往上穿五层，最终哪些原厂在供。查询模板只有两跳，写到第三跳就要改代码，穿到第五层几乎没人愿意维护。

组织架构同理：图里只存「直属上级」，问「某人到总经理隔几层」，要么写递归查询，要么先算好存起来。

这类问题的共同点很明确：规则只有一条、方向单一、但要重复用很多次；而且只要事实没错，答案就是确定的，不存在「大概」。演绎推理正是处理这种重复的工具。

02接上再接

看链条的两端。左边两条 parent 是已知事实，右边 ancestor 是结论。中间那一步不是猜，是把两条事实里的同一个中间人（B）对齐，再按「亲子关系可传递」这条规则接起来。

接上之后，新边又变成下一轮的前提：已有 ancestor 与新事实再按同样方式接，一直接到「再也接不出新边」为止。这个终点叫不动点。

所以演绎推理的执行方式非常朴素：扫一遍、接一批、写回去、再扫一遍。复杂的地方不在推理本身，在于规则集写全了没有、以及扫一遍的代价有多大。

03必然与传递

演绎推理：若前提为真，结论必然为真。它保真，不增产——不会推出前提里没有的信息，但会把隐含的部分全部摊开。

传递闭包：关系 R 的传递闭包 R+ 是「至少走一跳能到达」的全体有序对；R* 再加上「零跳」，即包含自己。ancestor 就是 parent 的传递闭包，不含自反时取 R+。

方式起点适合风险
前向链已知事实事实少、规则少、要长期查询推出大量用不上的边
后向链待证结论事实多、只问少数几个问题递归深，容易重复求解

两种方向推出来的闭包一样，差别在成本。事实一百万条、只问一个问题，后向链只碰相关的那一小片；事实几百条、要反复查，前向链一次算完更省。规模是选方向的唯一依据，不是先进与否。

04三条规则到不动点

最小规则集，够跑通家族关系：

R1　parent(x,y) ∧ parent(y,z) → ancestor(x,z)，两跳接一条祖先边。

R2　ancestor(x,y) ∧ ancestor(y,z) → ancestor(x,z)，把已推的祖先边继续串。

R3　spouse(x,y) → spouse(y,x)，配偶对称。

R1 只解决两跳，三跳以上靠 R2 把推出来的 ancestor 当新前提继续用。R3 不增加信息，只是把方向补齐，方便双向查询。

pythonforward_chain.py
rules = [rule_r1, rule_r2, rule_r3]
facts = set(base_facts)

while True:
    new = set()
    for rule in rules:
        new |= rule.match(facts)     # 只读，本轮不边扫边写
    new -= facts                     # 去重：已有事实不算新增
    if not new:                      # 完整扫一轮零新增 → 不动点
        break
    facts |= new                     # 统一写回，下一轮才可见

循环有两道保险，缺一条就出事。new -= facts 去重：不加这一句，R3 每轮都会把已经存在的对称边再「产出」一次，集合永远不为空，程序停不下来。if not new: break 判停：停的条件是一轮完整扫描后零新增，不是某一条规则没产出。

成本可以估：n 条事实一轮要两两配对，约 n² 次比较；直链长 L 需要 L 轮。一万条事实，一轮就是一亿次匹配。这就是大图必须建索引、分批算，或者交给专门推理引擎的原因。

05规则少一条

取一条四代直链：甲是乙的父亲、乙是丙的父亲、丙是丁的父亲。4 条 parent 事实，跑上面三条规则。

轮次新增说明
第 1 轮ancestor(甲,丙)、ancestor(乙,丁)R1 两两相接，共 2 条
第 2 轮无两条 ancestor 首尾对不上，停

闭包里没有 ancestor(甲,丁)。不是算错了，是规则集只有一个两跳入口：R1 只能从 parent 接出两跳，R2 只能串已经存在的 ancestor，而丙→丁始终停在 parent 层，永远进不了 R2 的前提。

补一条引入规则 R0　parent(x,y) → ancestor(x,y)，parent 边才算进了 ancestor 层，R2 才能一路串下去，甲→丁这时才出现。规则集多一条少一条，闭包差一整层。

最常见的误读

把「跑完不新增」当成「推完了」。不动点只说明当前规则集用尽了，不说明结论完整。上线前要用已知答案的样例反查规则集，而不是只看程序有没有报错。

06先算层再数边

任务：直链 A→B→C→D→E 共 4 条 parent，加上 R0 后重跑，写出每一轮新增了什么，数出最终 ancestor 有几条。

参考口径：含直接父子在内，5 个节点两两之间有祖先关系的共 10 对，闭包里应有 10 条 ancestor；少一条就说明规则还缺入口。

追问：① R3 为什么必须去重？② 链长翻倍，轮数和每轮成本各怎么变？③ 什么情况下后向链更划算？

验收：能写出三条规则并说明各自作用；能判断闭包缺边是规则问题还是数据问题；能估算一轮的匹配次数。结论怎么落库才不乱，见 推理的边界；归纳怎么补边，见 归纳推理与图谱补全。
