校园知识图谱综合实战与复盘

七十六个实体、一百五十条关系、五条查询。跑通只是开始，验收要看三张卷子。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能把需求、schema、抽取、入库、查询串成一个最小闭环。
  2. 能用「能查、查准、可维护」三道验收读出 Demo 结果。
  3. 能针对失败项写出下一轮的补强动作。

01验收会

交付验收会上坐了三方：教务处关心先修链对不对，学院关心实验室成员全不全，学生端关心能不能查到教师。三方各提一个问题，正好落在同一张图上。

演示不能只放一张截图。要能现场改一个参数、再查一次，还要能说清每条结果的依据来自哪份表。做不到这三点，验收就过不去。

02五步闭环

整条链路是五步：需求定范围，schema 定类型，抽取取事实，入库做校验，查询回答案。查询的结果再回头修需求，闭环才成立。

闭环里最容易被忽略的是最后那条回边。查询答不上来的问题，往往不是查询写错，而是 schema 里缺了一条边。

复盘走五个维度，每维一问：是否真需要图、数据是否可追溯、抽取能否过线、合并是否可回溯、查询是否有人在用。

03三道验收

能查：5 条验收查询全部能执行且有结果。空结果要能归因，是数据缺失还是查询写错。

查准：从图里随机抽 10 条关系，逐条对照原始表。10 条全对才算过；错 1 条就要查是不是融合阶段合并错了。

可维护：6 项 schema 约束全部通过，且每条约束都有对应的检查函数。约束靠人眼看，不算通过。

三道验收的顺序不能换。先能查，再查准，最后看可维护。前一道不过，后一道的数字没有意义。

04Demo 怎么搭

Demo 只用标准库。实体按类型存成字典，关系存成四元组，第四个位置放依据。查询就是遍历加集合运算，约束检查写成独立函数。

pythond7_6_campus.py（节选）
# 实体：类型 -> {id: 属性}
E = {"学院": {}, "教师": {}, "课程": {}, "实验室": {}, "学生": {}}
# 关系：(主语, 关系, 宾语, 依据)
R = []

def teach(teacher):
    return [c for (t, r, c, _) in R if r == "讲授" and t == teacher]

def lab_members(lab):
    return [s for (s, r, l, _) in R if r == "成员" and l == lab]

def lab_teachers(lab):
    out = []
    for (c, r, l, _) in R:
        if r == "使用" and l == lab:
            out += teach(c)
    return sorted(set(out))

lab_teachers 走的是三段：学生进实验室用成员边，实验室关联课程用使用边，课程再沿讲授边找到教师。三段拼起来正好是「学生所在实验室的教师」，也解释了为什么 schema 里使用边要从课程指向实验室。

约束检查单独成函数，入库前统一跑一遍：课程必须有一条属于边、课程号唯一、工号唯一、先修无环、实验室有房间号、学生最多属一个实验室。

验收 1 能查  : 5/5 条查询有结果
验收 2 查准  : 抽查 10 条关系，正确 10 条
验收 3 可维护: 检查 6 项 schema 约束，通过 6 项，失败 0 项
结论        : 图谱交付要同时过“能查、查准、可维护”三道验收。

先看规模。76 个实体里学生占 30、课程 20、教师 15，与设计时的 5/15/20/6/30 一致。150 条关系正好等于六类关系之和：20+25+45+15+30+15 = 150。边数对得上，说明没有丢数据。

再看查询。查询 2 与查询 4 的「结果条数」分别是 5 和 4，终端只列了前 3 条，这是显示截断，不是数据缺失。查询 3 只返回 1 条路径，因为两跳可达的先修链只有这一条，能唯一解释清楚比多返回几条更难造假。

最后看验收。能查 5/5，说明 5 条查询都能映射到模式；查准 10/10，是随机抽 10 条关系回原始表核对；可维护 6/6，是 6 项约束逐条跑检查函数，失败 0 项。

10/10 不等于全对

抽查 10 条只是抽样。全量 150 条要到 100%，得靠入库时的约束拦截，不能靠抽查运气。抽查的作用是验证抽取规则，不是代替校验。

06三道卷子复盘

任务：按三道验收给这次实战打分，每项写结论与下一步动作。

验收看什么不过时怎么补
能查5 条查询是否都有结果，空结果能否归因补边、补数据，或把问题移出范围
查准抽查 10 条关系与源表是否一致查融合别名，回退该批抽取
可维护6 项约束是否全过，变更能否回滚补检查函数，补别名表版本

追问：① 如果查询 5 返回空，最可能缺哪条边？② 抽查错 1 条，应该整批回滚还是只改那一条？③ 复盘五维里，哪一维最容易被跳过？

验收：三项都有结论、都有下一步动作，且能指出对应的图与边。需求怎么筛，见 需求分析；接口怎么收口，见 查询与服务化。

注：本页示例只用 Python 标准库，运行口径为 Python 3.13.14（Windows 原生 CPU），输出为本机实测，可直接复现。本页对应知识库条目均已建库（filled，2026-11-19），正文按条目口径与大纲要求撰写。
