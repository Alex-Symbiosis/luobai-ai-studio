异构与冲突：融合到底在解决什么

两家公司的主数据并表，字段对不上只耽误一天，真正麻烦的是同一家公司在两边有三个名字。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能区分模式异构、实体异构、值异构，并各举一个例子。
  2. 能按「先模式、再实体、最后值」的顺序给出消解动作。
  3. 能说明归一化只增加可比字段，不改原值。

01合并那天

并购完成后，两家公司的主数据要并成一张客户表。A 系统的字段是 cust_name、city，B 系统是 company_name、registered_city。字段一对不上，ETL 先停了一天。

字段改完还有三关：同一家公司在两边叫「星海科技」「星海科技股份有限公司」「StarSea Tech」；注册资本一边写 5000（万元），一边写 50,000,000（元）；签约日期一边是 2024/01/05，一边是 05/01/2024。

融合到底在解决什么？

不是把表拼在一起，而是让同一条事实在两边指向同一个东西，并且值能比较。

02三类不一致

把上面的麻烦归三类：模式异构是「结构不同」，实体异构是「同一个东西名字不同」，值异构是「同一个值的写法不同」。三类混在一起修，越修越乱；先分类，再各用各的动作。

图里每行是一个具体冲突，右侧写对应的消解动作。注意动作落在不同层：模式问题改映射，实体问题改标识，值问题改规范。改错层，问题会换个地方冒出来。

直觉结论

融合的工作量不在「合并」，在「判定」：判定这两个字段是不是一回事、这两条记录是不是一家公司、这两个数是不是一个值。

03三类的定义

模式异构：描述同一概念的结构不同。字段名不同、粒度不同（地址一个字段与省市区三段）、关系方向相反、类名不同（Customer 与 Client）。

实体异构：指向同一现实对象的标识不同，或不同对象共用同一名称。前者是全称、简称、英文名、曾用名；后者是「星海科技（杭州）」与「星海科技（北京）」这类同名不同实体。

值异构：同一个值在不同来源的表示不同。单位（万元与元）、币种（CNY 与 USD）、日期格式（年/月/日与日/月/年）、编码（行业代码新旧版）、精度（两位与四位小数）。

还有一类常被单列：事实冲突。同一属性两个来源给出不同值，例如注册资本 5000 万与 8000 万。它不是格式问题，靠归一化解决不了，必须定来源优先级或找人裁决。

04分层的动作

三类异构对应三组动作，顺序不能颠倒：先统一模式，再对齐实体，最后归一键值。理由很实际——模式没统一，实体比较连字段都取不到；实体没对齐，值归一会把两家公司的数字平均到一起。

模式层：建字段映射表，cust_name 映射到 name，registered_city 映射到 city；方向统一成「母公司指向子公司」；地址粒度拆成省、市、区三列。映射要落成配置文件并带版本，不能散在 SQL 里。

值层：单位换算、按日期汇率折算、日期统一成 ISO 8601。这两步都能写成纯函数，输入原始值，输出可比值和溯源信息。

pythonnormalize.py
import re
from datetime import datetime

def norm_amount(v, unit="元"):
    """统一到元：万元乘 10000。"""
    return float(v) * (10000 if unit == "万元" else 1)

def norm_date(s, fmt):
    """按来源声明的格式解析，输出 ISO 8601。"""
    s = re.sub(r"[./]", "-", s.strip())
    try:
        return datetime.strptime(s, fmt).date().isoformat()
    except ValueError:
        return None

print(norm_amount(5000, "万元"))          # 50000000.0
print(norm_date("2021/3/1", "%Y-%m-%d"))  # 2021-03-01

日期这段必须点明：05/01/2024 到底是 1 月 5 日还是 5 月 1 日，单看字符串无法判断，格式必须由来源声明，猜错会把整批日期平移几个月。单位换算同理：5000 万元等于 50,000,000 元，先换算再比较，否则两列数值差 4 个数量级。

易错点

用正则「试」日期格式。两种格式都能解析成功时，程序不会报错，只会静默选错；日期必须随来源登记格式，解析失败就进待核队列，不能自动兜底。

05一张处置表

把 200 家公司的冲突逐条登记，处置结果只有三类：合并、保留、待核。

冲突类型动作结果
cust_name 与 company_name模式建字段映射并成同一列
星海科技与星海科技股份有限公司实体别名表合并为 1 个实体
星海科技（杭州）与（北京）实体保留双实体不合并，加城市区分
5000 万元与 50,000,000 元值单位归一相等，保留原值溯源
2024/01/05 与 05/01/2024值按来源声明格式回查合同再定
注册资本 5000 万与 8000 万事实冲突按来源优先级标记待核

「待核」不是失败，是正确输出。强行合并会把两家不同公司并成一家，后面所有查询都错，而且很难回滚。处置表要留原值、动作、执行人和时间，否则半年后没人能解释一个数字是怎么来的。

06四条怎么判

任务：下面四条记录，各判一类异构并写一个动作：① tel 与 phone；② 杭州云图数据有限公司与云图数据；③ 金额 1.2（百万美元）与 8,600,000（元）；④ 成立日期 2021-03-01 与 2021 年 3 月。

追问：① 同名不同城的公司，靠什么字段才能区分？② 币种换算用哪天的汇率，为什么必须写进元数据？③ 事实冲突时，「更新的来源更可信」这条规则有什么风险？

验收：四条都判对类型，动作落到对应层；能说清「归一化不改原值，只增加可比字段」。对齐怎么打分见 实体对齐；类与约束见 本体。
