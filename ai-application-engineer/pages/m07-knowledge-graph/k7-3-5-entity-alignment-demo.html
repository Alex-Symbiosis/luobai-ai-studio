实体对齐：相似度规则与召回评估

200 家对 200 家，人工要比 4 万次；先打分排序，再让人只看边界上的几十对。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能写出名称二元组 Jaccard 与三项加权分的计算过程。
  2. 能读懂阈值表，说清「精确率升、召回率降」在数据上的表现。
  3. 能解释为什么任何自动合并都必须留人工复核入口。

01两百对两百

拿到两份公司名单，各 200 家：A 是自建库，B 是外部采购。B 里有 160 家与 A 真实对应，另外 40 家是干扰项——名字像、城市或行业不对。

人工逐条比对要 40,000 次。可行做法是先打分，把 200×200 压成几千个候选，再由人看边界上的几十对。

打分规则怎么定，阈值定在哪？

规则决定候选排序，阈值决定放多少人进来复核；两者都直接改变准确率和召回率。

02一路筛到人

对齐是一条流水线：先分块，再算名称、属性、结构三项相似度，加权成一个分，过阈值才进入人工复核。

分块不是为省时间，是防爆炸：200×200 共 40,000 对，按城市和行业分块后只剩几千。分块键太窄会漏配，通常要多套键互补。

曲线说明阈值不是越高越安全：精确率升、召回率降、F1 先升后降。峰值只是参考，取点看漏配与误配哪个代价更高。

直觉结论

阈值是「放行线」，不是「正确率旋钮」。调高只减少误配，错配会以漏配的形式出现。

03四个分数

候选生成：按分块键（城市、行业、名称首字）把记录分组，只组内两两比较，避免全量笛卡尔积。

名称相似度：把名称切成字符二元组，算 Jaccard 系数。星海科技切成星海、海科、科技 3 个二元组；星海科技有限公司切成星海、海科、科技、技有、有限、限公、公司 7 个。交集 3、并集 7，相似度 3/7 约 0.429。

属性相似度：城市、行业等关键属性逐项比对，相同记 1、不同记 0 再平均；本例两项，结果只能是 0、0.5 或 1。

结构相似度：共同邻居占两边邻居并集的比例。属性少、图稀疏时这一项不稳，只能给低权重。

加权分：score = 0.6×名称 + 0.25×城市 + 0.15×行业。权重来自业务判断：名称最常用也最不可靠，城市次之。加权分只用于排序，不做最终裁决。

04打分函数

下面用标准库实现三段：分块、二元组、打分。

pythonalign.py
from itertools import combinations

def bigrams(s):
    s = "".join(s.split())
    return {s[i:i + 2] for i in range(len(s) - 1)}

def jaccard(a, b):
    A, B = bigrams(a), bigrams(b)
    return len(A & B) / len(A | B) if A | B else 0.0

def score(a, b):
    name = jaccard(a["name"], b["name"])
    city = 1.0 if a["city"] == b["city"] else 0.0
    industry = 1.0 if a["industry"] == b["industry"] else 0.0
    return 0.6 * name + 0.25 * city + 0.15 * industry

def candidates(records, key):
    groups = {}
    for rec in records:
        groups.setdefault(key(rec), []).append(rec)
    for group in groups.values():
        yield from combinations(group, 2)

三个实现细节。第一，二元组要去掉空白，否则「星海 科技」会多出跨空格的噪声二元组。第二，单字名称没有二元组，len(A | B) 为 0，必须显式返回 0，不能让它除零。第三，分块只用于生成候选，最终打分仍在全字段上做；分块键选错，整批真实对应会被挡在门外，而且不会报错。

权重与阈值要写进配置并记版本，否则同一对记录换个权重就换结论，回溯找不到原因。

阈值表有两个断层。0.55 到 0.65 几乎不动：TP 恒为 128、FP 29 降到 28、召回 0.800；到 0.70 召回掉到 0.300、FN 从 32 跳到 112，因为名称变体的分数挤在 0.65 到 0.70，阈值一过整批落选；0.85 后 TP 归零。

最佳点 0.65：F1 0.810、准确率 0.821。但召回 0.800 意味着 32 家没找回，包括「Company004 Tech」应为「星海医疗」、相似度仅 0.400 的那条——任何高于 0.4 的阈值都救不回来。

另两类错配说明分数高不等于对：星海科技配到北京同名公司，0.750；恒芯半导体名称、城市全同而行业不同，也到 0.850，行业权重只有 0.15，压不住。

所以流程必须留人工口：相似度只管排序，同名、同城、行业冲突要回到登记信息、信用代码或人工核实。阈值越高越保守，名称变体却会整批漏配——表里就是 0.70 那一行。

易错点

把单一阈值当成上线标准。0.65 的召回只有 0.800，32 家真实对应永远进不了复核名单；漏配不会报错，只会让图谱少一批边，且很难在事后发现。

06算一对名字

任务：算「星海科技」与「星海科技有限公司」的名称相似度，写出两个二元组集合、交集与并集，判断在 0.65 阈值下能否进入复核，城市与行业相同。

追问：① 若把权重改成 0.8 名称、0.1 城市、0.1 行业，0.65 那一行的 TP 会升还是降？② 分块键只按城市，会漏掉哪类真实对应？③ 0.70 到 0.75 两行 TP 从 48 掉到 32，你怀疑是什么原因？

验收：相似度算到 0.429，加权分 0.6×0.429+0.25+0.15 约 0.657，刚过线；能说清「过线只代表进复核，不代表判定为同一实体」。异构分类见 异构与冲突；精确率与召回率的统一口径见 抽取评估。
