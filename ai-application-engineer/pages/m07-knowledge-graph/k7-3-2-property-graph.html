属性图：节点带属性，边带类型

同一批公司数据，一组用三元组库，一组用图数据库；两周后后者先交付，差别不在数据，在写法。

认知路线 真实问题→ 直觉类比→ 形式化定义→ 结构与机制→ 案例→ 练习

学习目标

  1. 能说出属性图的四个要素：节点、标签、关系类型、属性。
  2. 能把一条三元组事实改写成建设与查询两段 Cypher。
  3. 能按「以后会不会从它出发查」判断一个值该做属性还是做节点。

01两套库的争执

同一批公司数据，A 组用三元组库，B 组用图数据库。两周后 B 组先交付，理由是「查总部」只要一行。A 组不服：他们那条查询也不过三行。两边吵的是写法，不是数据。

B 组的建模很直接：公司是一个节点，节点上挂 name、city、founded 三个属性；收购是另一回事，画成一条带类型的边，边上记年份和股权比例。

同一批事实，为什么两种库的「手感」差这么多？

因为一个把属性摊平成三元组，一个把属性收进节点。存的东西能一一对应，敲键盘的次数不能。

02节点与边

属性图只有两种东西：节点和边。节点有标签（Company），边有类型（ACQUIRED），方向和属性都写在边上。看一张图，先看节点上的标签，再看边的箭头朝哪。

图里左边是三元组视角：每条陈述单独一行，谓语也是一个资源。右边是属性图视角：公司合成一个圈，圈里塞了属性，圈与圈之间只留关系。事实没少，只是收纳方式不同。

直觉结论

三元组像「一人一行」的流水账，属性图像「一人一张卡片」。查单人信息看卡片快，查全库模式看流水账清楚。

03标签与属性键

定义：属性图由节点、关系、属性三部分组成。节点可带一个或多个标签，关系必须有且只有一个类型、必须带方向，节点与关系都可以挂键值对属性。

RDF 位置属性图对应说明
主语（IRI）节点可挂多个标签，相当于多重类型
谓语（IRI）关系类型或属性键连实体时是关系，存值时是属性
宾语（IRI）节点可继续向外连边
宾语（字面量）属性值字符串、数字、日期或列表

关键差别在属性值：属性图允许把 city: "杭州" 直接放在公司节点上，而 RDF 里这必须是一条独立三元组。属性值不能再连边，这是「属性」与「关系」的分界线，也是建模时最容易含糊的一步。

04一行路径查询

建数据两行，查数据两行。语言是 Cypher，读法接近画图：圆括号是节点，方括号是关系，箭头是方向。

cyphercompany.cypher
// 建点：属性直接挂在节点上
CREATE (s:Company {name: "星海科技", city: "杭州", founded: 2021})
CREATE (y:Company {name: "云图数据"})
CREATE (s)-[:ACQUIRED {year: 2024, stake: 0.6}]->(y)

// 查：总部所在城市
MATCH (c:Company {name: "星海科技"})
RETURN c.city

// 查：谁收购了云图数据，占多少股
MATCH (a:Company)-[r:ACQUIRED]->(b:Company {name: "云图数据"})
RETURN a.name, r.stake

三点对照。第一，city 是属性，查询直接取字段，不经过城市节点；RDF 里对应的是先找 ex:headquarteredIn，再取城市名称。第二，方向和类型写在箭头上，一行就把「谁收谁」说清。第三，属性值没有 IRI，想查「杭州有哪些公司」只能按属性过滤，无法从城市出发遍历它的省份、人口、政策。

所以建模时把「以后会不会从它出发查」当成判断标准：城市只是展示字段，就做属性；城市要连省份、要统计、要接政策库，就必须升成节点。

05等价不同手感

把同一条事实并排写：RDF 需要 3 条三元组（类型、总部、成立年份），属性图是 1 个节点加 3 个属性。查询侧，SPARQL 用图模式匹配，Cypher 用路径语法，两者都能表达多跳，也都能加过滤条件。

结论是「表达等价，查询手感不同」，不是谁更先进。需要与外部交换、跨库合并、做规则推理时，RDF 的全局 IRI 和标准词汇更省事；以遍历为主、团队熟悉 SQL 式语法、数据规模在单库可控时，属性图的写法更短。

选型看约束，不看口号。一个常见组合是：对外发布用 RDF/SPARQL，内部服务用属性图，中间做一次格式转换；代价是两套模型要同步，改一处得改两处。

易错点

把「总部位于」建成属性后，又想查「同城公司」。属性无法建立关系索引，只能全表扫描再分组；补一条关系边可以解决，但两类数据会重复存储，必须提前定好以哪边为准。

06收购怎么建

任务：把「星海科技 2024 年以 60% 股权收购云图数据」建成属性图，写出节点、标签、边类型与属性，并说明哪些信息做成节点、哪些做成属性。

追问：① 如果一家公司被多轮收购，60% 这个数字放边上还够用吗？② 把收购建成「事件节点」有什么代价？③ 用 Cypher 查「谁收购了云图数据」该怎么写？

验收：能说清「属性不能再连边」这条边界，并给出把属性升级为节点的触发条件。RDF 的写法见 RDF；类与约束见 本体。
