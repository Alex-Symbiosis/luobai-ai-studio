手动涂抹局部修改：遮罩到底管住了什么

你把一张不错的客厅图发给客户，对方只回一句：沙发换成黑色皮沙发，其他别动。你整张重跑，地毯、挂画、窗外的光全变了。这一课先讲清遮罩原理，再一起把线追到 SaveImage。

01 / 现实问题与一句话目标

你大概也遇到过：一张图整体都不错，你只想把沙发换成黑色皮沙发。整张重跑，地毯、挂画、窗外的光全跟着变——你失去的是“其他部分不许动”的控制权。

这一课的目标：看懂遮罩怎样把“允许改”限制在一个区域，并学会用“从 SaveImage 倒推”的方法，识别一条看起来在改局部、其实没落盘的支路。

02 / PRINCIPLES

先弄懂遮罩：一张黑白图，决定哪里可以改

局部修改不是“用橡皮擦掉再画”，而是告诉采样器：这块地方可以重新长，其他地方请保持。这个“告诉”的载体，就是遮罩。

MASK

遮罩是什么

一张和原图等大的黑白图。白 = 允许重绘，黑 = 原样保留，灰 = 按灰度比例混合。它不是图层，不参与画面，只是一张“许可表”。

INPAINT

局部重绘怎么发生

把遮罩区域对应的潜空间（按 1/8 缩小的草稿画布，L3-01 讲过）内容重置成噪声，再让采样器只在那块区域去噪；遮罩外保持原 latent。所以“改哪里”由遮罩决定，“改成什么”由提示词决定。

EDGE

为什么边缘会假

遮罩边界是硬切时，重绘区和原图之间会出现一条缝。羽化（feather）让边缘渐变，外扩（grow）让重绘范围略大于目标，接缝才好藏。

还需要装好这些：FLUX1/flux_dev_fp8_scaled_diffusion_model.safetensors、t5/t5xxl_fp8_e4m3fn.safetensors + clip_l.safetensors、ae.safetensors、Impact Pack 的 MaskToSEGS 与 DetailerForEach、rgthree 的 Image Comparer、Flux2 的 flux-2-klein-base-9b-fp8 + qwen_3_8b_fp8mixed + full_encoder_small_decoder。缺一个，节点就会变红。
三格图要看的是“范围”，不是“画风”。中间那格的白块就是遮罩：它不告诉模型“改成什么”，只告诉模型“哪里可以动”。改沙发还是改抱枕，取决于你把白块画在哪、以及提示词写了什么。
三个容易混的词：遮罩（mask）是许可范围；SEGS 是把遮罩拆成一个个矩形区域后的一组“框”，方便逐个区域重绘；Detailer 是拿着这些框，逐个裁出来、放大、重绘、再贴回去的节点。05 号里这三样都出现了。第一次接触遮罩，先看微课 L3-05b · 遮罩是什么：它把黑白许可表、alpha、羽化/外扩和两套格子单独讲了一遍。
03 / BLUEPRINT

全景：两条支路，只有一条通到保存

05 号同时画了两套方案：上面一套是“遮罩 + 局部重绘”，下面一套是“整图 + 一句话交给 Flux2”。先顺着箭头看，再回答一个问题：哪条线最后接到了 SaveImage？先记住两个词——死端：一个节点的输出没接任何下游，ComfyUI 求值时就不会执行它，不报错，只是安静地不工作；子图：把一堆节点折叠成一个方块，双击才进得去，这份文件里 3 个子图全叫 New Subgraph。

遮罩支路（死端） 实际落盘 遮罩 / 分割 图像输入 文字输入
窄屏速读：上支路 = 涂抹图 → MaskToSEGS → DetailerForEach → 无下游（不执行）。下支路 = 同一张图 + 翻译文字 → Flux2 子图 #476 → SaveImage #383。落盘的是下支路。

这就是 05 号最值得记住的地方

它不是“参数没调好”，而是接线断在最后一步：局部重绘算得再对，只要输出没接到保存节点，就等于没做。判断方法永远只有一个——从 SaveImage 往回走。

04 / NODE BY NODE

逐节点：遮罩怎么进来，又断在哪

按“输入 → 重绘支路 → 落盘支路 → 对照”四段看。每张卡都标了真实输入输出，方便你回到 ComfyUI 里对号。

#257DetailerForEach逐个区域重绘

它做什么：拿着 #259 给的每个框，把框内区域裁出来、缩到 512、用 Flux1 重绘 25 步（denoise 0.8），再按 5 像素羽化贴回原图。这是“局部修改”真正干活的地方。三个参数先落地：denoise 0.8 表示大部分重画、留两成旧信息；CFG 1 表示几乎不额外拉提示词；seed（种子）决定从哪团噪声起步。uni_pc 是采样算法，sgm_uniform 是步长分配，换它们只改细节，不改构图。

边界 1

遮罩没盖住 = 一定不改

黑区在理想情况下原样保留。如果黑区也变了，先怀疑支路根本没走遮罩（05 号就是），而不是怀疑遮罩画得不对。

边界 2

遮罩内改成什么，遮罩不管

你把沙发涂白，提示词写“换成书架”，模型就会在沙发的位置长出一个书架。遮罩只给许可，不给内容。

边界 3

遮罩不懂物体边界

它是二维区域，不认识“沙发”和“地板”的交界。涂过界，地板会跟着变；涂不够，旧沙发的边会留在新沙发里。

边界 4：分辨率与细节有上限。Detailer 把每个框缩到 guide_size 512 再重绘，框里的细节上限就受这 512 约束。想让沙发纹理更细，先加 guide_size，再谈步数；只加步数不会凭空长出细节。注意：得先把 #257 接到保存节点，这个参数才会影响你看到的图。
06 / PITFALLS

踩坑：这条链路最会骗人的七个地方

前两条会让你“以为改了、其实没改”；中间三条会让你“改了、但改错地方”；最后两条是工程习惯。

遮罩支路是死端，图不是它出的致命

#257 DetailerForEach · IMAGE 输出为空

症状：你认真涂了遮罩、调了 denoise，出图和“只写一句话重画整张”一模一样。因为 #257 没有下游，ComfyUI 根本不会执行它。

改法：把 #257 的 IMAGE 接到一个新的 SaveImage，跑一次对比，你就知道“真局部”和“整图重绘”差多少。想接到 #260 的 image_b 也可以，但要先断开 #476 → #260 的那根线——那个槽已被占用。

clipspace 临时路径，换机就断高频

#431 · clipspace/clipspace-painted-masked-1782214563526.png [input]

症状：昨天还能跑，今天打开满屏红框，提示找不到图片。这是浏览器涂抹后写进 input 目录的临时文件，重启、清理、换机器都会没。

改法：涂完先把图另存到固定的 input/ 文件名，再用 LoadImage 指向它；或者每次重涂一遍。不要把临时路径当资产。

三个子图全叫 New Subgraph中

#476 → #475 → #474

症状：进了一层又一层，每层面包屑都写着同一个名字，改完参数不知道改的是哪一层。

改法：双击进子图前先记节点编号（#476 → #475 → #474），或者进去后立刻重命名。同名子图是排查时最大的噪音。

#254 面板写着汽车，实际在改沙发中

#254 CLIPTextEncodeFlux ← #382

症状：两个文本框都是 A car was driving on the road，你以为提示词没生效。其实 clip_l 与 t5xxl 两个输入口都接了 #382，面板值被连线整段覆盖。

改法：只改 #382 的中文原文；要验证面板是否生效，就断开 #382 → #254 的两条线再跑。

Flux2 的 1024 是默认值，不是实际尺寸中

#458 Flux2Scheduler · #462 EmptyFlux2LatentImage

症状：面板写着 1024 × 1024，出图却不是方的。因为 width/height 接了 #463 GetImageSize，而且 #472 先把图缩到了 1 MP。

改法：要改输出尺寸，看 #472 的 1 MP 与 #463 的来源图；不要改 #458 / #462 的框。

denoise 与 feather 是一对跷跷板低

#257 · denoise 0.8 · feather 5

症状：denoise 太低，遮罩里几乎不变；太高，框边缘开始“融化”，周围墙地也跟着改。feather 太小有硬边，太大又把重绘区糊回原图。

改法：先按上面的改法把 #257 接到保存节点（否则改它没有可见效果）。固定 feather 5，只调 denoise（0.5 / 0.65 / 0.8 各一张）；找到合适强度后，再用 0 / 5 / 15 试 feather。

保存前缀还是 ComfyUI低

#383 SaveImage · filename_prefix

症状：涂抹实验跑了十几版，全在同一串编号里，分不清哪张是 denoise 0.5、哪张是 0.8。

改法：用 paint_dn080_ft05_s374707 这种前缀，把 denoise、feather、种子写进文件名。

07 / PRACTICE

练习：先证明它没改，再让它真的改

这一课的练习顺序很重要：先复现“遮罩没生效”，再亲手把线接上。你会对“从 SaveImage 倒推”这件事记得很牢。

EXERCISE 01

复现死端

不改任何参数，先只看节点图：#257 的 IMAGE 口有没有下游？再跑一次，对比出图与 #476。

应该看到：#257 的面板参数全对，出图却和“整图重绘”一样——因为它没被执行。
EXERCISE 02

把局部重连接上

新增一个 SaveImage，把 #257 的 IMAGE 接进去；保持遮罩只盖沙发。

应该看到：只有沙发区域变了，地毯、挂画、窗外光影保持不变。
EXERCISE 03

只改一句话

把 #382 的原文从“改为黑色皮沙发”改成“改为深灰色布艺沙发”，其他不动。

应该看到：遮罩内材质和颜色变了，形状仍受原沙发约束。
EXERCISE 04

denoise 三连

先完成 EXERCISE 02（#257 已接到保存节点），再固定种子，把 denoise 设为 0.5 / 0.65 / 0.8，各出一张。

应该看到：0.5 保留最多旧结构，0.8 最敢改；超过 0.9 容易把周围也带走。
EXERCISE 05

feather 找接缝

保持 #257 已接到保存节点，把 feather 改成 0 和 20 各跑一张，放大看沙发与地板的交界。

应该看到：0 有硬边，20 边缘发糊；5 左右通常最自然。
EXERCISE 06

换一张固定图

把涂抹结果另存到 input/paint_sofa.png，用 LoadImage 替换 #431，重启 ComfyUI 再打开。

应该看到：路径不再变红，工作流可以换机复现。

交作业前自检

  • 我能用一句话解释遮罩、SEGS、Detailer 三者的分工。
  • 我知道 05 号真正落盘的是 #476，不是 #257，并能从 SaveImage 倒推证明。
  • 我亲手把 #257 接到保存节点，看到了“真局部”的差别。
  • 我能说出遮罩没盖住、遮罩内提示词、denoise、feather 各管什么。
  • 我知道 clipspace 路径为什么不能当资产。
  • 我改尺寸时看的是 #472 与 #463，不是 #458 的 1024。
  • 我的保存前缀能看出 denoise、feather 和种子。
