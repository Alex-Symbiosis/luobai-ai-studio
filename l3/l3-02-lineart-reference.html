线稿 + 参考图：两条控制线怎么分工

你画好了线稿，也找到了喜欢的参考图，一出图却两头不靠：视角被参考图带偏，水彩又变成写实。多数人怪模型，其实问题出在接线：两条控制线搭了却没接到输出，真正出图的只有 Flux2 那 4 步。

01 / 现实问题与一句话目标

你大概也遇到过：手上有线稿、有风格参考，一出图就“跑”——要么视角被参考图带偏，要么水彩变成写实。多数人以为是模型不行，其实是两条控制线的权重与接线方式没配对。

这一课的目标：读懂 02 号工作流的结构支路与风格支路，知道 0.6 / 0.6 / 0.7 这三个数字各自在管什么，并能解释一次真实的跑偏。

02 / PREREQUISITES

先认三张底牌：形、气、读图

这一课在 L3-01 的“纯提示词生成”旁边搭了一套“双线并行”的 SDXL 支路；但先说结论：它没接到输出，真正出图的仍是 Flux2。下面三张卡先把三个词落地：它们是什么、不是什么。缺一张，第四节会看得很吃力。

L1-04 / L1-05（接线见 L2-02）

ControlNet：管形

ControlNet（控制网）是给采样器额外塞一张“结构图 / 控制图”，让它按线稿或深度图摆位置。ControlNet 的 strength 越高，构图越难被提示词改动。反例：它不是图生图——线稿不会被贴上去，它只在每一步轻轻拉一把。

L1-04 / L1-05（接线见 L2-02）

IPAdapter：管气

IPAdapter（图像提示适配器）把参考图的色调、材质、笔触当成“图像提示”搬进模型。见 IPAdapter。反例：它不是滤镜，也不理解“这是水彩”，只是把特征搬过来。

L2-02c（接线见 L2-02）

Florence2：读图

本课的正向提示词不是手写的，而是 Florence2 从参考图反推的英文描述。Florence2 是“看图写话”的视觉模型，见 Florence2。反例：它不是在猜你的意图，只是把图里有的东西念出来，而且只念参考图，不念线稿。

还需要装好这些：SDXL 建筑大模型、LoRA SDXL 建筑/建筑外观XL终极版.safetensors（LoRA 是补丁：不动主模型，只叠一层建筑审美偏移）、diffusers_xl_depth_full 与 mistoLine_rank256、IPAdapter plus + CLIP-ViT-H、Florence2-large、Deep Translator、Impact Pack、rgthree、pysssss、AIO Aux Preprocessor。缺一个，第四节对应节点就会报红。
03 / BLUEPRINT

全景：两条支路，一个出口

这里其实有两套搭建、一个出口。活链是：两张图 #123 / #122 + #96 中文指令 → #103 CLIP 编码 → #162 Flux2（4 步）→ #80。另一套 SDXL 双控制支路（Depth / Lineart → #119 → #118）元件齐全，但 #118 没有接任何保存或预览，从输出端反查时不会被求值——它是不执行的旁支。所以别把 #119 当合并点：本课拆它，是为了让你看懂这套设计，以及它为什么没生效。

结构：线稿 / 深度 / ControlNet 风格：参考图 / IPAdapter / 提示词 Flux2 出图 保存
窄屏速读：活链只有一条：两张图 #123 / #122 + #96 中文指令 → #103 CLIP → #162（4 步）→ #80。Depth + Lineart 两条 ControlNet（各 0.6）和 IPAdapter 0.7 都搭在 SDXL 支路上，但 #118 没接保存或预览，整条支路不执行——把它当设计旁支看。

06 / TRAPS

五个最容易看错的地方

这份工作流最大的问题不是参数，而是“你以为它听你的，其实它听别人的”。下面五条里，前三条最容易被误判——其中两条根本不在出图链上。

高
#111 · ImageResize+

面板写着 512，旁支里实际是 1800

#111 的 widgets 里确实是 512×512，但 width 和 height 都接着 #112 的 1800。ComfyUI 的规则是连线优先于面板值，所以真正送进 VAE 的是 1800 长边。你在面板上改 512，改了个寂寞。

修法：要么断开 #112 的两根线，要么直接把 #112 改成你要的尺寸。判断方法：看输入槽上有没有小圆点，有就是被连线接管了。注意：这条 SDXL 支路不接输出，所以这个尺寸只影响旁支自身。

高
#107 → #117

正向提示词是 Florence 写的，不是你写的

#117 的面板是空的，text 输入接着 #107。Florence2 会把参考图读成一段“现代两层白色豪宅、门前两辆车”的英文，送进 #117。但这条 SDXL 支路不接输出，运行时根本不执行；真正出图的是 #162，它读的是 #96 的中文。

后果：你以为 #117 的英文在指挥画面，其实它连执行机会都没有；改 #117 面板对最终图毫无影响。

修法：只想改实际出图，就改 #96 的措辞；想让 SDXL 支路真的参与，先把 #118 接到 SaveImage 或 Preview，再断开 #107→#117、在 #117 里自己写，才能对比。

高
#162 Flux2 · #96

4 步重绘会把参考图的构图也搬来

这三张真实图能说明问题：乡村水系那组，输入是跨水拱廊/圆塔的线稿与水彩桥景，终图却变成近俯视的河湾、钢桁架桥、两座石堡、三艘船。水彩笔触没继承，写实哑光倒很明显。

从接线看，真正能改构图的是 #162：它把 #123 线稿和 #122 参考图一起当条件，4 步重绘、1 MP；参考图的构图和线稿的坡道在这一步重新谈判。IPAdapter 0.7 属于不执行的旁支，不是原因。

修法（按代价从低到高）：先固定 #162 内部的 seed，只改 #96 的指令，逐句确认哪一句把画面带偏；再动 IPAdapter 0.7 / end 1.0 这些旁支参数（注意它们默认不参与出图）。

#115 把英文 caption 从 auto 翻成 English，再给 #108 显示一遍，内容和 #107 一模一样，没有任何下游；这是调试残留。另外 #162 点进去，子图名字大概率还是 New Subgraph，三层都同名，找起来很痛苦。

07 / PRACTICE

练习与自检

这一课最重要的是建立“谁在说话”的直觉。每个练习都只改一条支路，别一次动三个参数。

EX 01 · 8 分钟

打开 #162，数清它的输入

进 #162 子图，确认它吃的是 model #102、image #123、image_1 #122、clip #103、text #96；再回顶层看 #119 有没有一根线接到它。

看什么：#162 的输入里没有 #119。没有，就说明出图不靠那条 SDXL 支路。
EX 02 · 10 分钟
