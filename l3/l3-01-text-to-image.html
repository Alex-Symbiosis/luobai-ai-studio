文生图：四步最小链路

周三晚上，你只想先出一张能看的客厅图，再去抠细节。网页版给你四个选项：尺寸不对，改一处又崩全图。这一课把出图拆成最短的一条链——8 个节点、11 根线、0 个子图。跑通它，后面所有出图课都往这条骨架上加东西。

01 / 现实问题与一句话目标

你大概也遇到过这种求助：“我只想要一张能用的室内效果图，但工具要么尺寸不对，要么改一处崩全图。”问题不在模型不够强，而在你无法定位是哪一步出了错。

这一课的目标很窄：用一段英文描述 + 一个 SDXL 模型 + 20 步采样，跑通“编码 → 采样 → 解码 → 保存”四步，并说清每个节点到底在传什么。

02 / PREREQUISITES

先认三张底牌

这一课用到 L0-01 的六步主链与 L1-02 的采样参数，后面 L3-02 会加入结构控制。这条链路只有 8 个节点，但每个节点都压着一个大概念。下面三张卡先把最常拦人的几个词落地：它们是什么、不是什么。缺一张，第四节就会卡住。

L2-01

模型三件套

一个 Checkpoint（检查点）里打包了 MODEL（去噪网络）、CLIP（文本编码器）、VAE（解码器）。它不是“一个画风包”，换它等于三样一起换。本课三根主线全部从 #1 出发。

L2-02

条件与提示词

文字不会直接进模型，要先被 CLIP 压成 CONDITIONING（条件）——一组采样器每一步都要用的数字。反例：它不是提示词原文，你看不见也改不了，要改只能回上游改文本。

L2-03

潜空间与采样

LATENT 是把像素按 1/8 缩小的草稿画布；KSampler 从纯噪声开始，按草稿一步步擦出图。反例：采样不是“渲染”，没有 3D 场景，也不是一次成型。steps 与 CFG 都在这里。

还需要装好这些：SDXL室内大模型.safetensors 与 LoRA SDXL 室内/大平层SDXL.safetensors。这份工作流没有额外的 ControlNet、没有子图、没有自定义节点，是最适合“第一次独立跑通”的一份。
03 / BLUEPRINT

全景：一条从噪声到 PNG 的路

你手上这张待生成的图，现在还只是一张 1600 × 904 的空白噪声画布。先别从左往右扫节点，先找它的出口：右下角 #11 SaveImage。从出口往回走：这张图的上一步是 #9 VAEDecode 把潜空间翻译回像素；再往前，是 #4 KSampler 跑的那 20 步；#4 手里握着三样东西——#5 正向条件、#7 负向条件、#8 空画布，而它用的模型来自 #2 LoRA，再往上一站才是 #1 Checkpoint。节点（Node）就是画布上一个方块，写着一件具体的事；连线是上游把数据交给下游的那一下。整条路只有 8 个节点、11 根线，倒着走一遍，你就知道这张图经过谁。

MODEL / 模型 CONDITIONING / 条件 LATENT / 潜空间 IMAGE / 图像 保存
窄屏速读：#1 模型 → #2 LoRA → #5 / #7 两段提示词 + #8 空画布 → #4 采样 20 步 → #9 解码 → #11 保存 3 张。
04 / NODE BY NODE

逐个节点：每站收什么、交什么

现在跟着这张图走一遍。它先在 #1 装上模型三件套，再由 #2 叠一层室内 LoRA；接着 #5 把 128 词英文描述压成正向条件，#7 用空字符串给一份负向条件，#8 递来一张 1600 × 904、batch 3 的空画布；#4 拿着这四路跑 20 步，把噪声擦成潜空间里的客厅；最后 #9 翻译回像素，#11 存成三张 PNG。每张卡只回答三个问题——这一站收什么、做什么、把什么交给下一站。

A

装载：把模型和风格补丁接上

#1 → #2
#1CheckpointLoaderSimple总开关

它是什么：Checkpoint（检查点）不是“一个模型文件”，而是把 UNet 去噪网络、CLIP 文本编码器、VAE 解码器打包在一起。反例：它不是只换画风；换它，三样一起换。所以它有三个出口，后面每一个分支都从这里出发。

ckpt_nameSDXL室内大模型.safetensors
输出 1MODEL
输出 2CLIP
输出 3VAE
MODEL → #2CLIP → #2VAE → #9
#2LoraLoader补丁

它做什么：LoRA（Low-Rank Adaptation）是补丁：不动大模型，只叠一层“室内 / 大平层”的风格偏移。反例：它不是小模型，也不是插件；删掉它，主模型照常工作。它同时改 MODEL 和 CLIP，所以两根线都要接。

lora_nameSDXL 室内/大平层SDXL.safetensors
strength_model0.41
strength_clip1.0

怎么读 0.41：这是“轻推”。0.3–0.5 通常只改材质与配色；超过 0.8，LoRA 自带的构图习惯会开始压过你的提示词，容易每张都长得像。

B

写条件：一段话变成两份向量

#5 / #7
#5CLIPTextEncode正向

它做什么：把文字压成 CONDITIONING（条件）——一组数字，不是把这段话存起来。采样器每一步都拿它校准“画面该往哪走”。反例：条件不是提示词原文，改条件等于改上游文本。

clip← #2
text 长度128 词 / 829 字符
内容开头sleek and contemporary living room…

这段话描述得相当具体：白色组合沙发、圆形黑茶几、落地窗与白纱帘、棕色休闲椅、纹理墙。它的问题也很具体——太长，第六节会算给你看。

#7CLIPTextEncode负向

它做什么：告诉采样器“哪些方向要躲开”。这里的值是空字符串，不等于“没有负向”，而是“没有特别要躲的东西”。

clip← #2
text""（空）

空负向是 SDXL 的常见做法：配合 2.5–3.5 的 CFG，画面不会太“硬”。如果你把常见的 blurry, low quality 塞进去，CFG 又开得高，颜色会明显变闷。

C

采样：从纯噪声里擦出画面

#8 → #4
#8EmptyLatentImage空画布

它是什么：一张全噪声的潜空间（Latent）画布。潜空间是把像素按 1/8 缩小后的草稿画布，所以 1600×904 在内部是 200×113 的格子。反例：它不是压缩包，解压无损；它来回翻译有损耗。它只决定尺寸和批量，不决定内容。

width1600
height904
batch_size3
LATENT → #4
#4KSampler按草稿擦噪声

它做什么：把“噪声画布 + 正向 + 负向 + 模型”放在一起，跑 20 步去噪。每一步都在猜“如果这里是客厅，像素该长什么样”，再用 CFG 把结果往提示词方向拉。

两个词先落地：seed（种子）是决定从哪一团噪声开始的随机数，反例：它不是画质开关，同 seed 只保证起点相同。CFG（Classifier-Free Guidance）是“听话程度”，2.95 偏温和，调到 7 会明显更硬、更艳；反例：它不是创意度，调高不会更有想象力。

denoise 1.0 的意思：从 100% 噪声开始，完全重画。它不是“强度拉满”，而是“没有起始图，别偷懒”。

D

解码与保存：把潜空间翻译回 PNG

#9 → #11
#9VAEDecode有损翻译机

它做什么：VAE（变分自编码器）是有损翻译机：把 200×113 的潜空间翻译回 1600×904 的像素图。反例：它不是放大，也不是滤镜；翻译损耗会让图发灰、发糊。

samples← #4
vae← #1

如果这一步糊、灰、偏色，通常不是采样器的问题，而是 VAE 与底模不配套。本课的 VAE 来自同一个 Checkpoint，所以不会踩这个坑。

#11SaveImage落盘

它做什么：把图写进 ComfyUI/output/。注意 filename_prefix 只是前缀，不是完整文件名；真正落盘时会自动补 _00001_ 这样的序号。

实际文件名ComfyUI_00001_.png

PNG 里会带工作流元数据，但文件名不会告诉你 seed、模型、LoRA 强度。三天后你回头看 ComfyUI_00012_.png，只能靠猜。第六节会给出一个可追溯的命名格式。

06 / TRAPS

四个会绊倒你的地方

这份文生图本身很干净，但“干净”不等于“没坑”。下面四条是跑它必遇到的；最后一条来自同目录的 01 号线稿课，提前给你打预防针。

高
#5 · CLIPTextEncode

128 词的提示词，后半段根本没进模型

SDXL 的 CLIP 文本编码器单段上限是 77 token。token 是编码器把文字切出来的最小片段，一个英文单词常被切成 1 到 3 个。这段 128 词、829 字符的描述，按常见英文分词估算，大约写到“吊灯”那一句就满了；后面的棕色休闲椅、纹理墙、整体氛围，模型可能一句都没读到。

证据：把 #5 的 text 复制到任意分词器里数一遍，或直接删掉后半段重跑——如果画面几乎不变，说明它本来就没生效。

修法：把最重要的 5 个词提到最前（living room, white sectional sofa, floor-to-ceiling window, modern, photorealistic），长句拆成短句；或先把长句压成简短的英文短句，再编码。

中
#8 · EmptyLatentImage

1600×904 不是 64 的倍数

904 ÷ 8 = 113，能被 8 整除，所以不会报错；但 904 ÷ 64 = 14.125，不是 SDXL 最舒服的 64 倍数。再加上 1600×904 约 1.45 MP，高于它最熟悉的 1024×1024（约 1.05 MP），偶尔会出现双茶几、重复吊灯、沙发接缝错位。

修法：先试 1600 × 896（25×64 与 14×64）或 1536 × 896，同 seed 对比重复构图是否消失。

中
#8 · batch_size = 3

“一次三张”是三倍显存，不是三倍魔法

batch 3 会让三张图同时留在显存里跑。8 GB 显卡在 1600×904 下很可能直接 OOM；更隐蔽的情况是系统自动降级，速度突然变得很慢。

修法：调参阶段固定 batch 1，定稿再开 3。要批量比较，用同一 seed + fixed，跑三次比一次开 3 更容易定位问题。

低
#11 · filename_prefix

前缀叫 ComfyUI，等于没命名

所有输出都叫 ComfyUI_000xx_.png，文件夹里一天就能堆出几百张无法区分的图。同目录的 01 号线稿课更典型：保存前缀写着 Flux2-Klein-4b-base，实际加载的模型却是 flux-2-klein-base-9b-fp8.safetensors——文件名在撒谎。

修法：用可追溯前缀，例如 t2i_sdxl-indoor_lora041_s1236890805499，一眼能看出工作流、模型、LoRA 强度和 seed。

低
同目录 01 号 · 线稿+文字

同门体检：三个你迟早会踩的坑

01 号文件不是纯文生图，它多了一张线稿入口。把它的画布翻一遍，会看到三件事，正好提前认识：

  • 换机即断：#222 的图片名是 image (26).png，ComfyUI 只在原机器的 input 目录里找得到。换电脑、重装、清理缓存，节点立刻报红。修法：把素材改成 lineart_livingroom_01.png 这类可读名字，并随工作流一起打包。
  • 子图全叫 New Subgraph：点开任何一层都叫这个名字，根本分不清谁是谁。修法：右键重命名成“Flux2 精修”“SDXL 装载”这类功能名。
  • 看起来在出图，其实没接线：01 号的 SDXL 支路 #177 采样 → #184 解码，输出没有接到任何保存节点；真正落盘的是 #196 Flux2 子图。判断方法只有一个：从 SaveImage 倒着走，能走到的才算数。
07 / PRACTICE

练习与自检

每个练习只改一个变量。做完再回看第五节，你会对“这行数字在管什么”有体感。

EX 01 · 5 分钟

先跑通，再谈效果

加载 JSON，确认 8 个节点没有报红，直接排队。记录出图耗时与显存峰值。

看什么：能否出 3 张、文件名是不是 ComfyUI_00001_ 开头。
EX 02 · 10 分钟

固定 seed，只动步数

把 #4 的 control_after_generate 改成 fixed，steps 依次跑 20 / 12 / 8。

看什么：第几步开始糊，先崩的是家具边缘还是墙面纹理。
EX 03 · 10 分钟

只动 CFG

seed 不变，cfg 依次跑 1.5 / 2.95 / 7。提示词一个字不改。

看什么：画面变硬、颜色变艳的拐点在哪；7 时是否出现塑料感。
EX 04 · 10 分钟

batch 与显存

batch 先改 1，再改 6，记录两次的显存峰值和单张耗时。

看什么：显存是否线性增长，以及你的卡在哪一档开始 OOM。
EX 05 · 10 分钟

换一个合法尺寸

把 1600×904 改成 1600×896，其他不动，同 seed 对比。

看什么：重复构图是否减少，画面比例是否仍然像横厅。
EX 06 · 15 分钟

把提示词压到 60 词

保留白沙发、圆茶几、落地窗、白纱帘、棕色单椅五个元素，删掉形容词堆叠，重写 #5。

看什么：元素是否更齐。这一步通常比加步数更有效。

自检清单（勾选状态会存在本机）

  • 我能从 #11 倒着走到 #1，说出每一站传的是什么。
  • 我知道 Checkpoint 的三个出口分别去了哪里。
  • 我能解释 denoise = 1.0 不是“强度拉满”，而是“没有起始图”。
  • 我知道 1600×904 对应的潜空间是 200×113。
  • 我能说清 128 词提示词为什么会被截断，以及先写哪五个词。
  • 我知道 filename_prefix 不是完整文件名，并给自己定了一个可追溯前缀。
  • 我改过至少一个参数，并能用“潜空间 / 条件 / 显存”解释结果。
