L3 · 微课 · B 线原理补课

遮罩是什么：你涂的那块白，到底在说什么

你在 B1 里第一次拿笔涂沙发。涂完却开始犹豫：白的一定会改吗？灰的算不算？把图换个软件打开，怎么全黑了？这一课只讲遮罩和 alpha（透明度通道），不重跑工作流。

01 / 现实问题与一句话目标

你涂了一块白，点运行。结果有两种：要么整张图都变了，要么重绘区和原图之间多出一条缝。还有更隐蔽的：换一台电脑，路径变红，你才发现那张“涂过的图”根本不在项目里。

这一课的目标：把遮罩（mask）看透——它是一张许可表，不是图层；白和黑只回答“能不能改”，不回答“改成什么”。

02 / PRINCIPLES

先把话说死：遮罩是一张许可表

真正决定“哪里能改”的，不是你涂得准不准，而是那张白图里每个像素的值。白是允许，黑是保留，灰是部分允许。

VALUE

一个像素，一个值

白 = 1，黑 = 0，灰是 0 到 1 之间的数。重绘节点读这个值，决定这一块允不允许重新长。

NOT A LAYER

它不参与画面

遮罩没有颜色、没有材质，也不会出现在最终图里。它是一张和原图等大的“能不能动”的表。

GEOMETRY

它不懂物体

白块画到沙发上，不代表模型认识沙发。你画过界，它就把墙也当可改区；你少画一条腿，那条腿就不动。

遮罩（mask）：一张和原图等大的许可表，白 = 可以改，黑 = 不许动，灰 = 按比例混合。反例：它不是橡皮擦，也不是图层；擦掉画面和“允许重画”是两件事。

这个类比已登记在手册的术语表里（A07：遮罩 = 许可表）。理由：遮罩不携带画面内容，只回答“这块能不能改”，和已有的草稿画布、补丁、翻译机都不是一回事。后面全站统一用“许可表”。

窄屏速读：原图 → 黑白许可表（白=1 可改，黑=0 保留）→ 只重画白区。遮罩不告诉模型“改成什么”。
白不是“更重要”，是“允许改”；黑不是“删掉”，是“别动”。遮罩不携带画风，也不携带内容。它只回答“这块能不能动”；改成什么，由提示词和参数决定（B1 已讲）。
先核对约定：ComfyUI 这套工作流是“白 = 改，黑 = 留”。有些绘图软件正好相反，白色表示保护。接别人工作流时，先用 MaskToImage（把遮罩转成黑白图的节点，B1 用过）看一眼，不要凭颜色猜。
03 / THREE FORMS

同一张许可表，三种外壳

二值、灰度、alpha（透明度通道）经常被混着叫“遮罩”。它们确实能装同一件事，但装法不同，丢的东西也不同。先把“装什么”和“装在哪”分开。

形态每个像素存什么边界常见来源
二值遮罩
binary mask		只有 0 或 1（存成图时是黑与白）硬边，像剪刀剪的手涂、阈值（按分界值切黑白）、自动圈选输出（B2 讲）
灰度遮罩
grayscale mask		0 到 1 的连续值软边，像喷枪喷的羽化、抗锯齿（边缘过渡像素）、模型给的 0 到 1 分数图
alpha 通道
alpha channel		透明度，存图时 0 到 255；进节点后是 0 到 1通常也是连续PNG（支持透明的图片格式）的透明层、涂抹图

二值遮罩（binary mask）：每个像素只有两个答案，改或不改。反例：它不是“越白越强”的调节阀；它没有中间档。

灰度遮罩（grayscale mask）：0 和 1 之间还有中间值，0.4 表示这一块只允许四成改动。反例：它不是三种颜色；灰不是第三种颜色，是 0 和 1 之间的数。

alpha 通道（alpha channel）：图片自带的一层透明度，0 是全透明，255 是不透明；读进节点后换算成 0 到 1。ComfyUI 读 alpha 时会翻转：涂过的地方透明，读进来变成白色。反例：它不是独立的遮罩文件，也不是“第四种颜色”。

一句话分清：二值和灰度说的是“里面装了什么”；alpha 说的是“这层透明信息存在哪”。一张图可以既有 alpha，又有二值内容，关键看节点读的是哪个通道。
为什么换个格式就没了：JPEG（不支持透明的图片格式）不存 alpha；截图会把透明压成白底或黑底；看图软件显示棋盘格，只说明有透明，不说明节点会读它。要带遮罩，存 PNG（支持 alpha 的图片格式），并确认节点的遮罩通道选的是 alpha。
这一课先不展开的三件事：SEGS（把白区拆成矩形框的一组数据）和 Detailer（按框逐个重绘的节点），B1 专门讲；GroundingDINO 和 SAM（B2 的两个模型：一个按名词找框，一个在框里抠边），B2 专门讲；像素遮罩和潜空间遮罩的区别，下一节就讲。
04 / EDGE

边缘：软边、羽化、外扩，各管一段

硬边遮罩像用剪刀剪的。重绘区和原图之间会出现一条直缝。两种办法处理：让过渡变软（feather），或让范围变大（grow）。它们不是一回事。

窄屏速读：硬边会留缝；feather 把边界变渐变；grow 把白区向外推一圈。虚线框是目标物体的真实边缘。
feather 改过渡，grow 改范围。示意图不按像素比例。05 号只有 feather 5（DetailerForEach 贴回时用）；grow_mask_by 6 属于 06 号的 #33。本课只解释它们做什么，不改这些值。

羽化（feather）：把边界从 0/1 的硬切改成一段渐变，让重绘区和原图慢慢接上。反例：不是给整张图加模糊，只动边界附近。

外扩（grow / dilate）：把白区向外推 N 个像素，给采样器多一点周边信息。反例：不是把图片放大；图没变，许可范围变了。

腐蚀（erode）：反向外扩，把白区收回 N 个像素。反例：不是擦除画面，只是缩小许可范围。

你看到的症状先用哪个它改什么过头会怎样
重绘区和原图之间一条直缝feather边界过渡带重绘区被糊回原图，像没改干净
目标边缘缺一圈周边信息，接不上grow白区范围墙、地板也被当成可改区
涂过界，连不该动的一起白了erode / 负向 grow白区范围目标边缘反而改不到
两个真实值分别在哪：05 号的 DetailerForEach（按框逐个重绘的节点，B1 讲过）贴回时用 feather 5；它没有 grow_mask_by。外扩 6 像素出现在 06 号的 #33 VAEEncodeForInpaint：在把图压进 1/8 草稿（L3-01 讲过）之前，先把遮罩外扩 6 像素；不过 06 号的 #25 没有下游，外扩 6 像素要在接上输出之后才看得出来。这些数字只用来对照，不在本课重讲。
05 / COORDINATES

像素遮罩与潜空间遮罩：两套格子

遮罩不是悬空的。它必须和它所限制的东西在同一套坐标里。像素遮罩一格对一个像素；潜空间遮罩一格对 1/8 草稿上的一个格子。

PIXEL

像素遮罩

和原图等大，每个值对应原图的一个像素。你在画布上看到的白区，就是它。

LATENT

潜空间遮罩

和 1/8 草稿等大，每个值对应草稿上的一个格子。一格盖住原图 8 × 8 个像素。

SCALE

换算一次就明白

512 × 512 的遮罩，到潜空间只剩 64 × 64 个格子；L3-01 的 1600 × 904，进采样时是 200 × 113。

窄屏速读：像素层可以把边界切在第 5 个像素；压到 1/8 草稿后，边缘只能落在 8 的倍数上，第 5 像素被并进第 1 个格子，边界跳到第 8 像素。
同一块白区，换坐标系就会“跳格”。示意图不按真实比例。潜空间一格盖住 8 × 8 像素，所以像素级的细边到了草稿层，只能落在 8 的倍数上。

像素遮罩（pixel mask）：和原图等大、一格对一像素的许可表。反例：不是“分辨率越高越好”，它必须和 image 的尺寸对齐。

潜空间遮罩（latent mask）：和潜空间（latent，按 1/8 缩小的草稿画布，L3-01 讲过）等大的许可表。反例：不是像素遮罩缩小一点就能直接用；缩小会改掉边界。

VAE（变分自编码器）：在像素和草稿之间来回翻译的有损翻译机，L1-01 专门讲。它压图时不会替你保留像素级边缘。

为什么不能混用：一个 512 的像素遮罩直接塞进 64 的潜空间槽，节点要么把它拉伸，要么按格子重新采样。无论哪种，原来贴着手臂的边都会跳 8 像素。判断方法：看节点有没有 image（图像）输入。有 image 的，通常会先编码，顺手把遮罩压到同一尺寸。只收 mask（遮罩）和 latent（草稿）的，它要的就是潜空间尺寸。
8 倍不是宇宙常数：这是这批工作流里 VAE 的压缩比。换模型先看它的 VAE，再决定遮罩该给哪一版。给错了，预览里就能看到错位或边缘发毛，不用等出图。
06 / PITFALLS

clipspace 与五个常见误用

先把最硬的一条说清：clipspace 不是项目文件夹，是工作台旁边的临时粘贴板。它能让浏览器里的涂抹立刻被服务端读到，也能让你换台电脑就断。

clipspace 是什么：ComfyUI 这个工作台在浏览器里涂完，会把带 alpha 的 PNG 写进 input/clipspace/。文件名带时间戳。工作流 JSON（保存工作流的那份文本文件）里存的只是一条路径字符串，不是图片本身。05 号那条 clipspace/clipspace-painted-masked-1782214563526.png [input] 就是一条取件指令。它让 ComfyUI 的服务端（跑模型的那一边）去“这个工作台的托盘”取图。换一台机器，托盘不在；清理 input，文件没了；临时目录被清，也会断。

clipspace（临时粘贴板）：ComfyUI 的网页界面涂抹后，在服务端 input 目录里留下的临时 PNG，靠一条带时间戳的路径交接。反例：不是素材库，不是云同步，也不能当项目资产。

这个说法是本课新增的。理由：它既不是节点，也不是模型，用“临时粘贴板”才能和“项目文件夹”区分开；全站只拿它指 clipspace，不拿它比喻别的临时文件。

白黑看反高频

换软件 / 换工作流时

症状：你涂了沙发，结果墙变了，沙发没动。原因：有些工具用白色表示保护，和 ComfyUI 正好相反。

改法：先接一个 MaskToImage 看黑白预览，确认哪边是白，再动手。

把灰度当二值中频

同一张遮罩进两个节点

症状：遮罩明明没改，换一个节点边缘就变了。原因：一个按 0.5 这个分界值切硬边，一个按灰度值混合。

改法：要硬边，就先二值化；要软边，就保留灰度，并固定用同一个节点。

遮罩和原图尺寸不一致高频

512 的遮罩配 1024 的图

症状：遮罩看起来对齐，重绘区却偏了半张脸。原因：节点把 512 的遮罩拉到 1024，白区跟着变形。

改法：从同一个 LoadAndResizeImage（B1 里同时输出 image 和 mask 的节点）取图，不要分开缩放。

alpha 存丢高频

JPEG / 截图 / 微信传输

症状：涂抹图看着有透明，导入后遮罩全黑。原因：JPEG 不存 alpha，截图会把透明压成底色。

改法：存 PNG（支持 alpha 的图片格式），确认节点的遮罩通道选的是 alpha，再用 MaskToImage 复验。

把 clipspace 当资产高频

05 号 #431 的路径

症状：换电脑打开工作流，LoadAndResizeImage 直接变红。原因：路径指向旧工作台的临时目录。

改法：涂完先另存到项目文件夹，再把节点指向新文件；涂抹图要跟工作流一起归档。

还有一种“没变化”不是遮罩的错：遮罩画对了，但这条支路没有下游（输出没接任何节点），ComfyUI 根本不会执行它。回 B1，用 SaveImage（保存节点，B1 讲过）倒推一遍，先确认线接上了，再怀疑遮罩。
07 / PRACTICE

练习与自检

这一课不动 05 号的参数。练习都在副本上做，目标是让“白、灰、透明、格子”四件事变成手感。

EX 01

做一张二值遮罩

新建 512 × 512，左半纯白、右半纯黑，存 PNG。接 LoadImage（读图）→ MaskToImage（遮罩转黑白图）→ PreviewImage（预览）。

应该看到：黑白边界干净，没有灰边。
EX 02

同一张图存两种格式

把带 alpha 的涂抹图分别存成 PNG 和 JPG（不支持透明的压缩格式），都用 alpha 读法导入。

应该看到：PNG 能读出白区，JPG 的遮罩全黑。
EX 03

对比 feather

先把 #257 接到保存节点（否则它是死端），再在副本上把 feather 改 0 / 5 / 20，各出一张，只放大看接缝。

应该看到：0 有硬边，5 接得上，20 开始糊回原图。
EX 04

对比 grow

在 06 号的副本上：先把 #25 接到 SaveImage（否则 C 段不执行），再把 #33 的 grow_mask_by 改 0 / 6 / 20，各出一张，看墙地和目标边缘谁先被吃掉。

应该看到：0 边缘缺上下文，6 有余量，20 把周围也重画了。
EX 05

量一次 8 倍

把 512 × 512 的遮罩和它对应的 64 × 64 潜空间并排看，找一条斜边。

应该看到：像素层的细边，到草稿层变成 8 像素一级的台阶。
EX 06

迁移 clipspace

把涂抹图另存到项目文件夹，把 #431（B1 里读涂抹图的节点）的路径改过去，重启 ComfyUI 再跑。

应该看到：路径不再变红，换机器也能打开。

交卷前，逐条打勾

  • 我能用一句话说清遮罩、二值、灰度、alpha 的区别。
  • 我知道 ComfyUI 里白 = 改、黑 = 留，并且会先预览再相信颜色。
  • 我能说出 feather 和 grow 各改什么，不会把 grow 当放大。
  • 我知道 512 的像素遮罩到潜空间只剩 64 格，边缘会跳 8 像素。
  • 我知道 alpha 不是独立遮罩，存 JPEG 会丢。
  • 我知道 clipspace 为什么换机就断，并会把涂抹图另存成资产。
  • 我能判断一条遮罩支路有没有下游（回 B1 用 SaveImage 倒推）。
