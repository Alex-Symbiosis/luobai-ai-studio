文字识别局部修改：用一句话指定改哪儿

地板要换成黑色大理石，你沿着墙角涂了十分钟；透视一歪，贴回去还是有一条缝。于是你想：能不能直接说一句“改地板”？这一课讲 GroundingDINO 找框、SAM 抠边的接力链，也讲 06 号落盘支路上那个更隐蔽的坑。

01 / 现实问题与一句话目标

你大概也遇到过：地板要换成黑色大理石，但你不想手动沿着墙角涂一圈——透视一复杂，涂抹边界必然歪，贴回去就有缝。

这一课的目标：看懂“文字 → 检测框 → 像素遮罩”这条接力链，知道提示词该写名词、阈值该往哪边调，并能判断遮罩到底有没有参与最终出图。

02 / PRINCIPLES

两个模型接力：一个负责“哪儿”，一个负责“边界”

你可能以为有一个模型能“听懂一句话就精确抠图”。没有。这条链是分工的：检测器只给矩形框，分割器才给像素级遮罩。

DETECT

GroundingDINO 做什么

开放词表检测器：你给一个名词短语，它在图里找出对应物体的矩形框。“开放词表”指不必预先限定类别——你写什么名词，它就找什么。反例：它不是只认固定 80 类的旧检测器；但它也不懂“大理石”，不懂“换成”，只回答“floor 在哪”。

SEGMENT

SAM 做什么

分割模型：你给框，它在框内沿着真实边缘抠出像素级遮罩。墙角、桌腿、地毯毛边都能贴住，这是手涂最难做好的部分。

THRESHOLD

0.3 是什么

检测置信度阈值。置信度是模型对“这是地板”的把握分数，0 到 1。调低 = 宁可多框（可能误检）；调高 = 只留很有把握的（可能漏检）。06 号用 0.3，偏宽松。反例：阈值不是“准确率”，调高不会让框更准，只会让框更少。

三个术语先分清：检测（detection）输出框；分割（segmentation）输出遮罩；局部重绘（inpaint）拿遮罩去改图。06 号把前两步合成一个节点 GroundingDinoSAMSegment，所以你在图上只看到一个盒子，里面其实是两次推理。
注意第二格和第三格的区别：框是矩形的，会把沙发腿、地毯一起圈进去；遮罩才贴着地板真实边缘。局部重绘要的是第三格，不是第二格——这就是为什么检测之后必须再过一次 SAM。
03 / BLUEPRINT

全景：一条竖着走的识别链，和一条绕开遮罩的保存链

06 号的布局和 05 号不同：识别链是竖着往下走的，保存链却在最底下横着绕过去。先顺着编号看一遍，再回答：最终那张图，经过遮罩了吗？两个词先落地——死端：节点输出没接下游，ComfyUI 求值时不会执行它，不报错，只是安静地不工作；子图：把一堆节点折叠成一个方块，双击才进得去，这份文件里 2 个子图都叫 New Subgraph。

遮罩支路（死端） 实际落盘 检测 / 分割 文字输入 遮罩转换
窄屏速读：地面 → 翻译成 floor → GroundingDINO 找框 → SAM 抠遮罩 → VAEEncodeForInpaint → KSampler → VAEDecode → 无下游。另一条：原图 + 两条文字 → Flux2 子图 → SaveImage。落盘的是后一条，它没有 mask 输入。

比 05 号更隐蔽的一点

05 号的遮罩连重绘节点都没接上；06 号的遮罩确实进了 VAEEncodeForInpaint，链路看起来完全正确——但那条链在最后一步断了。#25 VAEDecode 没有下游，于是整条 SDXL 局部重绘都不会被执行。

最后落盘的 #68 Flux2 只收 text2、text2_1、image 三路，没有 mask。所以“文字识别”找准了区域，但最终图并没有只改那块区域。

本课定位：这一课到这里，你能拿到的是遮罩；重绘支路缺最后一根线，这正是本课的练习。

04 / NODE BY NODE

逐节点：从一句话到一张遮罩，再到一次落空

按“输入与文字 → 检测与分割 → 遮罩重绘 → 落盘”四段看。注意每张卡右侧的真实输入输出，它们决定了节点到底会不会被执行。

检测与分割：一个节点，两次推理

它们做什么：#12 提供“找框”的检测模型，#11 提供“抠边”的分割模型。两者都只加载一次，供 #10 调用。SwinB 是检测骨干的型号（B 比 T 更准也更慢）；vit_b 是 SAM 的骨干型号，b 指 base。Prefer GPU 表示优先用显卡跑，没显卡会自动退回 CPU，只是慢很多。

一句话记住这条链：检测器回答“在哪儿”，SAM 回答“边界在哪”，inpaint 回答“怎么改”。三者缺一，局部修改就退化成整图重画。
边界 1

词表：只认常见名词

floor、sofa、window 这类具体名词最稳。“大理石地面”“右下角那块地”都不是它的语言。

边界 2

阈值：松紧都有代价

0.3 偏松，容易把地毯、台阶一起当地板；调到 0.5 更干净，但可能整块地板都找不到。先用 #27 看遮罩（先把 #27 从静音改成 Always），再决定往哪边调。

边界 3

遮罩：被挡住的看不见

SAM 只能分割“看得见”的部分。沙发压住的地板、桌子下面的角落会缺失；grow 6 只补 6 像素，补不回一大片。

边界 4：分辨率决定边缘精度。Flux2 支路先把图缩到 1 MP，SAM 若在缩过的图上工作，墙角边缘会变糙。要高精度遮罩，就让检测与分割跑在原图上，只在重绘阶段缩放。
06 / PITFALLS

踩坑：找准了区域，不等于改对了地方

这一课的坑集中在“看起来都对”：框对了、遮罩对了、参数也对了，但最后那张图没走过这条链。

#25 解码完没人接，整条 inpaint 白跑致命

#25 VAEDecode · IMAGE 输出为空

症状：遮罩预览里地板抠得很准，出图却整张都变了。因为 SDXL 局部重绘在 #25 结束，没有下游就不会被执行。

改法：给 #25 接一个 SaveImage，和 #26 并排跑一次。你会同时得到“真局部”和“整图重绘”两张，差别一眼可见。

提示词拼成中英混排高频

#62 “将图中的” + #60 “floor” + #63 “转化为” + #65 英文

症状：最终提示词是“将图中的floor转化为black marble floor tile”。中文连接词与英文关键词混在一起，模型能猜，但语义不稳。

改法：把 #62 / #63 也改成英文（例如 replace the / in the image with），或直接把整句写进一个节点，别让翻译结果和中文模板硬拼。

ShowText 框里写着中文，显示的是英文中

#40 ← #39 · #24 ← #16

症状：你以为检测词是“地面”，实际送进模型的是 floor。ShowText 的面板文本只是没接线时的默认值。

改法：看 ShowText 的输入有没有连线；有连线时，以连线来源为准，框里的字不算数。

把一句话塞进检测框中

#10 GroundingDinoSAMSegment · prompt

症状：写“把地板换成黑色大理石”后，检测不到任何东西，遮罩全黑。GroundingDINO 要的是名词短语，不是指令。

改法：检测词只写物体名（floor / rug / sofa）；“换成什么”交给 #16 与重绘提示词。

0.3 把地毯也算进地板中

#10 · 阈值 0.3

症状：遮罩把地毯、门槛、甚至一小块墙面都包进来，重绘后这些地方一起变成大理石。

改法：先把阈值升到 0.4 看是否还漏；漏了再回到 0.35。用 #27 的叠加预览判断（先把 #27 从静音改成 Always），不要只看最终图。

两个子图都叫 New Subgraph低

#68 → #67

症状：进了一层，里面还是一个同名节点；改完不知道改的是外层还是内层。

改法：记住 #68 是外层、#67 里才是 22 个节点的正体；或者进去后立刻重命名。

保存前缀还是 ComfyUI低

#26 SaveImage · filename_prefix

症状：试了 floor / rug / 不同阈值，全在同一串编号里，事后分不清。

改法：用 seg_floor_t030_marble 这种前缀，把检测词、阈值、目标材质写进文件名。

07 / PRACTICE

练习：让遮罩真正参与一次出图

顺序和上一课一样：先证明当前没走遮罩，再亲手接上。这一课到这里，你能拿到的是遮罩；重绘支路缺最后一根线——主练习就是把那根线接上。做完这六题，你对“检测 / 分割 / 重绘”三段的分工就不会再混。

EXERCISE 01

主练习：把 #25 那根线接上

先按现状跑一次（#25 的 IMAGE 没有连到任何保存节点），记下保存目录里没有任何来自 #25 的图；再新增 SaveImage，接到 #25 的 IMAGE，跑第二次。保留 #26 不动，两次对比。

应该看到：接之前只落 #26 一张；接之后多出 #25 那张，且只有地板变，#26 仍然整张重画。
EXERCISE 02

换检测词

把 #39 的“地面”改成“地毯”，跑一次；再改成“沙发”，跑一次。

应该看到：#27 的叠加预览里，白区跟着换了对象（先把 #27 从静音改成 Always），但 #26 的图变化不大——因为它没收遮罩。
EXERCISE 03

阈值三连

把 #10 的阈值设为 0.1 / 0.3 / 0.5，每次用 #27 看遮罩范围（先把 #27 从静音改成 Always）。

应该看到：0.1 把地毯也吞进来，0.5 可能只剩一小块；0.3 是这套图的折中。
EXERCISE 04

找遮罩缺口

用 #27 放大看沙发腿、桌脚附近（先把 #27 从静音改成 Always），记录哪些地板没被白区覆盖。

应该看到：被家具挡住的地板是黑的；这就是 grow 6 补不回来的部分。
EXERCISE 05

只改目标材质

把 #16 改成“浅色木地板”，其他不动，跑 #25 与 #26 各一张（#25 先按 EXERCISE 01 接上保存）。

应该看到：#25 只换地板材质，#26 连墙和家具一起变。
EXERCISE 06

清掉中英混排

把 #62 改成 replace the、#63 改成 with，让整句变成英文。

应该看到：#26 的材质更稳定，地板纹理不再随机漂移。

交作业前自检

  • 我能说清 GroundingDINO 与 SAM 各自输出什么、为什么必须接力。
  • 我知道检测词要写名词短语，改图词才写“换成什么”。
  • 我能从 #26 倒推，指出落盘支路没有 mask 输入。
  • 我知道 #25 为什么不会执行，并亲手给它接过保存。
  • 我会用 #27 检查遮罩（先把它从静音改成 Always），而不是只看最终图。
  • 我能说出阈值调高、调低各自的风险。
  • 我的保存前缀能看出检测词、阈值和目标材质。

这类“缺一根线”不止这一处

真实工作流里这种情况很常见：元件齐全，参数也对，就是少一根线，于是整条支路安静地不执行。这套教材里还有同类——01 号的 #184 VAEDecode、07 号的 #4 ImageScaleBy，输出都没有下游（以实际 JSON 为准）。

学会从 SaveImage 反查：先找到保存节点，再顺着输入往回走，只认这条链上的节点。这样就不容易被“看起来完整”的图骗。
