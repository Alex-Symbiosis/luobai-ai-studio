01 / 先认路一个工作流的“材料清单”：六项打底

打开一张新工作流，先别动参数。看最左边那几个方块：图从哪来，模型从哪来。材料没到位的图，调什么都白调。

加载节点很好认：左边没有输入线，只有右边出去的线。它们站在整张图的最前面，一道工序而已。你只要记住它吐出什么类型，就不会接错。节点和连线的类型概念，L0-01 已经讲过；这一课只看输入这一侧：谁把第一份材料递进来。

两种装法，别混：SDXL 系走 CheckpointLoaderSimple，一次拿到 MODEL / CLIP / VAE 三路。Flux 系拆成 UNETLoader + CLIPLoader + VAELoader 三件。04 的根图用前者，子图用后者，正好一组对照。

三路输出先认下来：MODEL、CLIP、VAE。MODEL 与 VAE 在 L1-01、L1-06 已经讲过，CLIP 的细节在 L2-02 还会展开，这里不重复定义，只关心谁把它们搬进来。反例：VAE 不是画质增强，换 VAE 解决不了构图问题。

LoadImage把一张图读成 IMAGE＋

手上有一张实拍照片，想拿它当底图；或者有一张风格参考图，要喂给 IPAdapter。第一步都是把图读进来。

LoadImage 干的就是这件事：从 input 目录挑一张图，吐出 IMAGE 和 MASK 两路。IMAGE 是像素图，下游拿去编码、缩放、当控制图；MASK 是图片自带的透明通道。反例：它不是“上传按钮”。上传只是帮你把文件放进目录，真正交给下游的是那两个输出口。

IMAGEMASK
image文件名。下拉里能看到 input 目录中的图片。
upload界面上的上传按钮，不产生参数值。
04 建筑：#15 是底图 7db588…jpg，#33 是风格参考图 8d9696…jpg；03 室内：#15 底图、#33 参考图；07 放大：#1 Stable Diffusion.png。

易错：MASK 不是“自动抠图”，而是图片自带的透明通道。JPG 没有 alpha，MASK 往往是空的；要抠图请走分割节点。

CheckpointLoaderSimple一次加载 MODEL + CLIP + VAE＋

第一次打开 SDXL 工作流，你得先回答一个问题：用哪个大模型。选错了，后面调多久都白费。

CheckpointLoaderSimple 就是回答这一步。它读一个 .safetensors 文件，一次吐出 MODEL、CLIP、VAE 三条线：主画师、文本编码器、有损翻译机。三样都在一个文件里，于是三个加载节点可以省掉。反例：它不是“一个模型的另一个叫法”。它是一条三路输出，少接一路，后面就断。

MODELCLIPVAE
ckpt_name大模型文件名，放在 models/checkpoints。
04 #1 = SDXL建筑大模型.safetensors；03 #1、06 #35、文生图 #1 = SDXL室内大模型.safetensors；02 #136 = SDXL建筑大模型.safetensors。

易错：SDXL 的 LoRA 不能配 SD1.5 的 checkpoint；模型族不匹配时，画面会直接崩或完全不听提示词。

UNETLoader只加载扩散模型本体＋

跑 Flux 工作流时，你在下拉里找不到能用的 Checkpoint。不是你装错了，是 Flux 把三件东西拆开给。

UNETLoader 只负责其中一件：主画师。它输出 MODEL，不含 CLIP 也不含 VAE，所以还得配 CLIPLoader 和 VAELoader，三件凑齐才能出图。反例：它不是“整个模型”，只是画图那一部分；少了另外两件，采样器连提示词都读不到。

MODEL
unet_name扩散模型文件，放在 models/unet 或 models/diffusion_models。
weight_dtype权重精度。本套取 default 或 fp8_e4m3fn。
04 子图 #344 = flux-2-klein-base-9b-fp8.safetensors · default；05 根图 #252 = flux_dev_fp8_scaled_diffusion_model.safetensors · fp8_e4m3fn。

易错：weight_dtype 不是“越省越好”。选错可能变慢、报错或画质下降；没有把握就先用 default。

CLIPLoader / DualCLIPLoader把文字变成条件＋

你写了一段很具体的中文，出图却像没看见。先怀疑这一路：文本编码器。

CLIP 是文本编码器，把句子转成一串条件向量。模型只读这串向量，不读你的原文。反例：它不是图像模型，看不懂画面，也不生成像素。Flux2 用一个 CLIPLoader；Flux1 常用 DualCLIPLoader，T5 管长句，CLIP-L 管关键词，两路同时上。

CLIP
clip_name编码器文件。Flux2 用 qwen_3_8b_fp8mixed.safetensors。
type编码器类型。Flux2 填 flux2；Flux1 双编码器填 flux。
device运行设备，本套均为 default。
04 子图 #345 = qwen_3_8b_fp8mixed · flux2 · default；05 根图 #253 DualCLIPLoader = t5xxl_fp8_e4m3fn + clip_l · flux。

易错：CLIPLoader 的 type 选错，节点可能能跑但提示词几乎不起作用；换模型族时先检查这一项。

VAELoader单独加载编解码器＋

用了 UNET + CLIP 的拆分方案，你会发现还差一路：解码。没有它，采样完的图回不到像素。

VAELoader 把 VAE 单独读进来。VAE 是有损翻译机：进采样前把像素压成 1/8 草稿画布，出图后再翻回像素，翻两次损两次。反例：它不是“提画质的工具”，用错 VAE 只会掉画质，不会加画质。

VAE
vae_nameVAE 文件名，放在 models/vae。
04/02/03 子图 #346 等 = full_encoder_small_decoder.safetensors；05 根图 #256 = ae.safetensors。

易错：VAE 与模型族必须匹配。用错 VAE 常见表现是颜色发灰、发绿或整体发糊，而不是报错。

LoraLoader在主模型上叠一层补丁＋

想换画风，又不想重下主模型。加一个 LoRA 就够了。

LoRA 是补丁：不动主模型，只往 MODEL 和 CLIP 上各叠一层偏移。两个强度，一个管画面（strength_model），一个管提示词理解（strength_clip）。反例：它不是“小模型”，不能单独加载出图；拿掉主模型，它什么也生不出来。

MODELCLIP
lora_nameLoRA 文件名，放在 models/loras。
strength_model对画面的影响强度。
strength_clip对提示词理解的影响强度，本套全部为 1。
04 #2 美丽乡村SDXL 0.49；02 #135 建筑外观XL终极版 0.30；03 #2 0.47；06 #36 0.22；综合 #13 0.50；文生图 #2 0.41。

易错：两个强度不是“双倍效果”。多数场景只调 strength_model，把 strength_clip 保持在 1；两个一起拉高更容易过拟合。

03 / 避坑基础六项最容易错的两处

把 Checkpoint 当单模型它是 MODEL + CLIP + VAE 三路输出，不是“一个模型一个口”。只接 MODEL，采样器就缺条件、缺解码，红框会一路亮到底；SDXL 的 checkpoint 配上 SD1.5 的 LoRA，还会直接报维度错。
VAE 接错或缺一路UNET + CLIP 的拆分方案里漏掉 VAELoader，采完的图回不到像素。用错族则颜色发灰、发绿、整体发糊，却没有一条报错——先查 VAE 是不是同一模型族。
