课目表/L2 节点字典/L2-02c 文字工具

L2 字典 · 第二课 C

文字工具：
把图读成话，把话接上提示词

手上只有图，没有词；或者只有一句中文，模型却更认英文。文字工具干的就是两头搬运：先把图读成一段描述，再把描述翻成另一种语言，最后拼回提示词。它不生成条件，只把原料递到编码器门口。

前情提要：前两节把条件的三条来路走完了：文字经 CLIP 编码成条件，结构靠 ControlNet，风格靠 IPAdapter。这一节补外围：一段描述从哪来、怎么换语言、怎么拼回提示词。

反推（caption）：让视觉模型看一眼图，写出一段描述。反例：它不是提示词生成器，写出来的句子还得你自己筛。字符串（STRING）：一串纯文本，节点之间可以互相传。反例：它不是条件，没经过 CLIP 编码，采样器读不懂。

01 / 文字工具识别、翻译、拼接

四个节点围着同一个目标转：把一句能用的提示词凑出来。顺序也很固定——Florence2Run 先出英文描述，DeepTranslatorTextNode 换语言，ShowText 负责核对，CR Text Concatenate 把几段拼成一句。

这条链上没有一个节点能直接改画面。它们的输出全是文本或字符串，最后必须接到 CLIPTextEncode 才变成条件。下面按这个顺序逐条看。

Florence2Run + 加载器看图说话，生成英文描述＋

手里只有一张参考图，懒得自己写描述。让它先看图说话。

先加载 Florence-2 模型，再用 Florence2Run 对图片做描述、检测等任务。本套统一使用 more_detailed_caption。反例：它不生成条件，只吐一段文字；文字还得送进 CLIPTextEncode 才算条件。

CR Text / CR Text Concatenate字符串常量与拼接＋

提示词里有一句固定句式，只有中间那个词每天换。你不想每回手打一遍。

CR Text 提供一个可编辑的字符串；CR Text Concatenate 把多段字符串按顺序拼起来。固定句式、识别结果、目标词各占一段，最后拼成一句。反例：它不翻译、不改写，拼完是什么就是什么。

STRING × nSTRING
06 用 #62“将图中的” + 识别结果 + #63“转化为” + 目标词，经 #60/#64/#65 拼接；04 子图 #348 固定追加“8K,4K,增加细节”；02 #96 是一整段中文构图说明。

易错：拼接顺序就是文字顺序；多一个空格、少一个逗号，都会改变 CLIP 的理解。

四个节点各管一段：识别给原料，翻译换语言，ShowText 只核对，CR Text 负责拼装。真正让它们生效的，是最后那句接进 CLIPTextEncode 的完整文字。

顺序能从节点编号看出来：04 的 #60 识别、#62 显示、#85 翻译、#86 再显示。一路读下来，就是这段文字被加工的全过程。

02 / 动手反推、翻译、拼接，各走一遍

1

打开 04，把 #60 Florence2Run 的参考图换一张。任务保持 more_detailed_caption，模型保持 microsoft/Florence-2-large，看 #62 ShowText 输出的英文描述变成什么样。

目标：确认它给的是描述文字，不是控制指令。

2

打开 01，找到 #182 DeepTranslatorTextNode（把中文提示词翻成英文）。把 from / to 改成中文互译的另一方向，输出仍接回原来的 CLIPTextEncode，跑一次。

目标：看清翻译只换语言，条件仍由编码节点生成。

3

打开 06，找到“将图中的地面转化为黑色大理石地砖”。按 #62“将图中的” + 识别结果 + #63“转化为” + 目标词拆开，把 #63 的“转化为”换成“改造成”，再跑一次。

目标：确认拼接顺序就是最终文字顺序。
